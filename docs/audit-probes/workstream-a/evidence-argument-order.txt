Finding
-------

A reordered named call currently has different fault priority in the Can
evaluator and emitted TypeScript. The evaluator executes argument expressions in
written source order. The emitter rearranges expression text into callee
parameter order, after which JavaScript evaluates it left to right.

This probe uses only source-typed runtime values and two admitted primitive
faults. In the named call below, source writes `right = xs[index]` before
`left = 1 / divisor`. With `xs = Seq<int>[]`, `index = 0`, and `divisor = 0`,
both expressions fault. The actual evaluator reports `seq index out of range`;
fresh emitted TypeScript reports `Division by zero` because it lowers the `left`
parameter first. No null, undefined, wrong host type, call expression, or side
effect is involved.

The normal case is equally important: all four checked Can rows pass, and both
emitted functions return `ok left=1 right=2` for `divisor=1`, `xs=[2]`,
`index=0`. Thus the reproduced discrepancy is fault priority. This probe does
not claim a different result for non-faulting pure values.

```can
  match call order__take(right = xs[index], left = 1 / divisor)
    on Ok result => Ok(result.left, result.right)

fn order__source_order(divisor: int, xs: Seq<int>, index: int) -> Order__Out rev 1
  emits []
  tests

  match call order__take_source(right = xs[index], left = 1 / divisor)
    on Ok result => Ok(result.left, result.right)
```

`order__take` declares `(left,right)`, so `order__reordered` must resolve its
written `(right,left)` arguments into different parameter slots.
`order__take_source` declares `(right,left)`, providing a target-side control in
which source and parameter order already agree.

Interpretation and limits
-------------------------

For the same well-typed faulting values, the real evaluator reports the
source-first sequence fault while fresh emitted TypeScript reports the
parameter-first division fault. The control target, whose parameter order agrees
with source order, reports the sequence fault in Node. This confirms both the
lowering mechanism and an observable evaluator/target discrepancy without a host
contract violation.

The probe establishes neither side effects nor a non-faulting result difference.
Can argument value expressions are call-free here, and valid ordinary rows agree.
It also does not choose the intended semantic order. The language decision must
specify source or parameter order, then make evaluator, TypeScript, diagnostics,
tests, and future host boundaries agree.
