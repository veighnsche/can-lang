# B1-10 — S3-compatible object storage

Status: prepared for ASAP execution; implementation and acceptance still pending. Dependencies: B1-01, B1-05. Surface: Library plus stream integration.

Provide S3-compatible object operations through Bun.S3Client, including bounded reads, streaming transfer, metadata, listing and presigned access where the pinned API supports them. Reuse file/stream contracts. Credentials stay private and test endpoints explicit.

## Proposed API contract

This is interface notation, **not accepted Can syntax or a claim that these operations compile today**. Resolve final names against the current catalogue and express them in existing Can declaration syntax; only primitive gates may add grammar.

```text
s3::client(endpoint, region, bucket, credentials, options) -> opaque_client
s3::read_bytes(client, key, limit); read_stream(client, key)
s3::write_bytes / write_stream(client, key, body, metadata)
s3::stat; delete; list(prefix, continuation, page_limit)
s3::presign(method, key, expires, required_headers) -> signed_request
```

## Implementation sequence

1. Qualify target-native methods and options for read/write/delete/stat/list/presign/multipart against official docs and the exact binary. Constructor presence alone proves none of these operations.
2. Separate object key semantics from local paths: slash is data, not local traversal. Require explicit endpoint/region/bucket and credential sourcing; never expose credentials in error payloads.
3. Implement immutable metadata and typed page continuation. Avoid collecting an entire bucket; enforce per-page/result limits and preserve opaque continuation values.
4. Use B1-05 streams for large transfers; enforce byte and deadline budgets during transfer, cancel on handler failure and observe native rejections.
5. Qualify native multipart behavior, abort cleanup and retry semantics. Do not write an S3 signing algorithm or multipart protocol implementation. If the native API lacks an operation, record that exact target gap before changing scope.
6. Represent presigned result as URL plus required method/headers and expiration metadata. Treat signed URLs as sensitive, redacting them in reports.
7. Run native integration against a provisioned local S3-compatible endpoint: create isolated bucket/prefix, verify bytes and metadata, delete only those test objects.

## Acceptance evidence

- Success: binary round-trip, metadata, paginated listing, delete, signed GET/PUT, streaming transfer and qualified multipart.
- Rejected: invalid config, unsupported signing method, invalid expiration, wrong type and missing key.
- Runtime: denied credentials, missing object, service interruption, cancellation mid-upload, overflow and cleanup; signed request fails if required headers differ.
