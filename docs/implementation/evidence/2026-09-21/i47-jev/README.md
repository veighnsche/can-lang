# I47 catalogue representation consultation

Three fresh requests supplied the same facts and alternatives: I47 precedes the
replacement front-end/runtime but requires the full approved catalogue; generic
signatures, derived callback bounds and conditional native errors are required;
user kernel/protocol/opaque registration is forbidden. All context, question
instructions and option descriptions were rewritten between requests. A
preflight comparison checked corresponding fields differ; manual comparison
confirmed their semantic equivalence. Exact technical identifiers were retained.

Every response selected the single validated JSON inventory with generated
Go/TypeScript/documentation views, reporting confidence 1.0. Returned model was
jev-1.13.0. There was no selection disagreement. Agreement is advice, not proof
of completeness or removal of phrasing bias. The requests and raw responses are
saved here. Current TypeSafe API/Choice documentation read earlier in this same
implementation session remained the API basis.

The implementation distinguishes descriptor availability from executable
adapter implementation. The registry records the complete approved surface and
native recipes, each with its implementation task; it does not mark those
adapter tasks complete. Tests check strict inventory validation, closed lookup,
opacity, concrete specialization, callback and native mode error sets, mirror
drift and the packaged Go/TS error-occurrence boundary.
