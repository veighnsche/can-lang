## W5-L3 BLOCKED analysis (new E09 finding, exact evidence)

The handler boundary behaves exactly per contract: `withTransaction`
with `boundMs: 150` returns `sql::commit_unknown {transaction_id:
"1-1"}` at handler-side 155ms; 1 escalation cause budget with the
`unknown-write / owned / supervisor` marker; the tx settles owned
(late resolved at ~2067ms); the reconciliation reread finds row id 8
exactly once; the hook stays silent. The peer, however, receives the
`unknown:commit` body at 2009ms — at tx callback settlement, not at
the 150ms bound.

Mechanism (read, then measured): dispatch runs each request inside
`withScope`, and owner-core `drain` waits for every callback task
`inside` the request scope. The tx callback is a guarded task in the
tx's inner scope, which nests inside the request scope — so the
request drain (hence the peer response) waits for the tx callback
even though the boundary already returned. Pool-lease work (L1/L2/L6/L7
query legs) is unaffected because leases hang off the pool resource,
not the request scope. The measured split (handler 155ms, peer
2009ms, late record 2067ms) shows the peer releases at callback
settlement, before the late record lands.

Consequence: the overrun-tx shape is drain-blocking (owner-grouped)
plus natively unabortable — the exact shape class the X-R04-2 O2 trip
condition names (there scoped to hedged replicas; this is the
unhedged tx instance). A hung tx callback would hold the peer past
any bound; `stop` itself stays bounded via `shutdownMs` (the
in-flight peer is cut with the session, not answered — reasoning from
`server.stop`/`wait`, unmeasured for tx). Detaching tx ownership from
the request scope is an E04 semantic change with disposal/commit
implications, not a W5 leg fix — so W5-L3-at-budget is BLOCKED and
handed to IC2/preparation. The leg pins the split (handler <1500ms,
peer ≥1800ms and <8000ms) and fails loudly if the shape ever changes.
