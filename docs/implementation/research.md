## Execution observations

`go test ./...` passed all four packages on this machine. This establishes a usable legacy baseline only. No old source was changed to make it pass. [Log](evidence/2026-09-21/legacy-go-test.txt).

Installed Bun is 1.4.2, revision `744846f844374847c902b5e7fd59b4342a51ef99`, macOS arm64. The [small saved probe](evidence/2026-09-21/native-probes.ts.txt) observed JSON reviver source tokens, raw JSON output for a large integer, signed zero, `Array.fromAsync`, immutable sorting availability, strict Bun deep equality, code-unit/scalar distinction and completion-box protection from a callable `then`. This is runtime evidence, not a complete generated-code conformance suite.

A useful counterexample: native intersection of left `[3,2,1]` and right `[1,2]` returns `[1,2]`; C7 requires `[2,1]`. The [ECMAScript algorithm](https://tc39.es/ecma262/multipage/keyed-collections.html#sec-set.prototype.intersection) may traverse the smaller set. Use native membership plus a native left-order array filter and construct a fresh Set. Do not replace C7's order with upstream's order, and do not write a new set algorithm.

## Upstream and packaging findings

Bun 1.4.2 is the research candidate, not a promise that a future release should skip fresh qualification. The arm64 release archive is 25,377,591 bytes with SHA-256 `90987a3a16d7db556d886ac3d551e7b6d3edf0a1cf43acaed622e8676be1d12f`. [Saved release metadata](evidence/2026-09-21/bun-release.json) records the exact tag, commit, URLs and other macOS assets. Bun documents macOS 13+ and provides a separate x64 archive; P15 initially admits arm64 only. [Installation](https://bun.com/docs/installation), [release](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.2).

The installed executable has an embedded Developer ID signature and hardened-runtime flag; its identity is recorded in [signature output](evidence/2026-09-21/installed-bun-signature.txt). This is not verification of a newly assembled Can download or Gatekeeper/notarization behavior. Shipping upstream bytes is possible with either packaging alternative; embedding bytes in Go does not turn Bun into a Go library. [`embed`](https://pkg.go.dev/embed) supplies data, so the embedding alternative still needs an executable file on disk and an extraction protocol.

Apple's direct-distribution workflow includes signing code and notarizing the distribution container. Preserve upstream signatures/entitlements where possible; validate nested executable handling and the Can launcher/container as one release. A hash checks bytes against a trusted expected digest; it does not establish publisher identity by itself. Never suggest removing quarantine or disabling Gatekeeper as installation. [Apple packaging](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution), [signing](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac/), [notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow).

Redistribution is not adequately described as “MIT only”: Bun's own license is MIT, while its published license inventory includes linked JavaScriptCore/WebKit and other components. Package exact notices and satisfy the corresponding upstream source/relink obligations for the actual artifact; preserve provenance. This is a release engineering acceptance item, not a claim of completed legal review. [Upstream inventory](https://github.com/oven-sh/bun/blob/main/docs/project/license.mdx).

Bun accepts explicit `.ts` ESM imports and top-level await. Emit exact relative files; do not rely on extension fallback, ambient node_modules, package downloads or project hooks. Generated TypeScript also needs a separate strict type-check gate; runtime success does not establish TS correctness. [Module resolution](https://bun.com/docs/runtime/module-resolution), [TypeScript settings](https://bun.com/docs/typescript).

SQL execution, pooling, prepared statements and transaction protocol belong to `Bun.SQL`. Its client connects lazily, `begin` commits on callback success and rolls back on throw, `bigint:true` changes int8 decoding, and close waits for queries. These mechanisms still need Can leases, typed row validation and a private rollback signal. A bare successful constructor cannot prove a live pool; test `connect`/reserve availability on the pinned runtime before defining the pool-open adapter. [Bun SQL](https://bun.com/docs/runtime/sql).

For compiler SQL admission, [pg_query_go](https://github.com/pganalyze/pg_query_go) exposes the real PostgreSQL parser through CGo. [go-pgquery](https://github.com/wasilibs/go-pgquery) runs the same upstream C parser compiled to WASM under wazero, also offers optional CGo, and warns of potential WASM-specific issues. Both are reuse; neither justifies a Can SQL parser. Parser major, exact binding revision, scanner byte-offset behavior and cold-start cost need a pinned spike before dependency adoption. Current binding examples use PostgreSQL 17; the language requires a selected pinned major, not automatically the newest major.

For source maps, use an established encoder such as [`@jridgewell/gen-mapping`](https://github.com/jridgewell/sourcemaps/tree/main/packages/gen-mapping). Go emission owns Can-to-TS source positions; a compiler-owned, prebundled JS helper running on packaged Bun can encode maps. This avoids inventing VLQ/source-map serialization. Exact helper version/integrity and Bun stack-map composition remain qualification tasks.

TypeSafe's live index/API/Choice/state/confidence/consistency cookbook were refreshed; [source hashes](evidence/2026-09-21/sources.json) record retrieval. Native language questions remain compiler declarations, with one prepared batch sent to the documented System One endpoint. Provider confidence is data, not a permission or correctness proof. The consistency cookbook explicitly cautions that repeated answers can differ. [API](https://docs.typesafe.ai/api), [Choice](https://docs.typesafe.ai/primitives/choice), [confidence](https://docs.typesafe.ai/confidence), [consistency](https://docs.typesafe.ai/cookbooks/consistency_choice_cookbook).
