# AI/native and failure normalization review (read-only, 2026-09-22)

This memo proposes semantics for the coordinator's design decision. No compiler, runtime, spec, or fixture was changed; no Jev consultation was performed here. The confirmed scope is the seven infrastructure errors at **fetch and judge wrapper boundaries**; no per-`noul`/`choice`/`score` wrapper and no sequencing/nesting redesign. The confirmed ordering is error arms first, `ok` last. Sources below refer to the working tree inspected today.

## Verified baseline

- `docs/implementation/design-revisions.md:7-58` lists the seven errors, language-owned normalization, judge-only AI wrapping, inherited omissions with last override, error-first matches, and the eight-call acceptance fixture. The fixture's eight fetches and seven repeated arms are at `compiler/testdata/current/fetch/main.can:11-50,63-168`; note that `load_envelope` overdeclares `http::status_error` and `codec::invalid_data` at line 21, though A2.3 excludes status error from envelope intrinsic bounds (`docs/syntax-taste/ai-io-spec.md:76-85`).
- The current spec makes every native `emits` a complete public upper bound and requires explicit intrinsic errors (`docs/syntax-taste/ai-io-spec.md:72-89`). The checker enforces that list in `compiler/internal/check/native_program.go:112-175`, and the judge checks each registered question's declared bound and nominal connection identity in `compiler/internal/check/native_bodies.go:135-160`. These checks must be revised at the raw/public boundary; a text macro for `emits` alone cannot remove seven caller arms.
- Existing HTTP errors are typed nominal domain errors, with exact fields: `invalid_request(reason)`, `credentials_missing(variable)`, `transport_failed(phase)`, `timeout(timeout_ms)`, `body_limit(limit)`, `status_error(status, headers)`, `codec::invalid_data(path, reason)` (`docs/syntax-taste/ai-io-spec.md:53-70`). The transport builds immutable typed payloads in `runtime/transport/http.ts:9-25`; status headers are a normalized snapshot (`docs/syntax-taste/ai-io-spec.md:154-160`). A domain occurrence separately has its ID, payload, cause, and origin (`runtime/domain.ts:18-25,125-135`).
- The current native AI example repeats the raw seven at `examples/native-ai/src/oracles/oracles.can:68-75,103-123`, and its `fn` wrappers at lines 77-123 exist to adapt grouped state/callables, not to normalize infrastructure failures. The spec explicitly distinguishes those wrappers and rejects judge/LLM callable references (`docs/syntax-taste/ai-io-spec.md:93-103`).

## Recommendations

1. **Make a language-owned default wrapper part of each fetch/judge's public contract.** Keep raw adapter completions with their current seven typed errors internally. Before the completion is visible to ordinary Can calls, a compiler-owned wrapper converts each applicable one to a single catalogue error, tentatively `http::request_failed(http::failure_detail detail)`. `http::failure_detail` is a closed nominal variant with seven error-payload leaves, one for each original kind. The wrapper's public `emits` includes the one error plus all unaffected authored/AI errors. A mode without a possible leaf (e.g. envelope fetch has no status error, byte-only/bodyless may have no codec error, unauthenticated has no credentials error) simply has no reachable mapping for that leaf; the type is stable. The declaration may spell the one public error explicitly, while the compiler verifies raw intrinsic obligations internally. This preserves a finite visible bound without seven repeated entries. No blanket conversion of ordinary `codec::decode_json`, LLM, SQL, authored errors, or standard `[_]` failures is implied. The raw/public split is necessary because the existing checker currently requires raw intrinsic errors (`compiler/internal/check/native_program.go:123-173`) and the spec says standard failures are distinct (`docs/syntax-taste/ai-io-spec.md:87-89`).

2. **Preserve the complete typed detail and occurrence provenance.** The seven detail leaves retain exactly `reason`, `variable`, `phase`, `timeout_ms`, `limit`, `status` plus normalized `headers`, and `path` plus `reason`, respectively; do not collapse to a message/code or copy native exception text. A selective handler can inspect the detail leaf and fields, for example recover only status 404 or only `codec::invalid_data` at `/id`. The newly constructed outer domain occurrence should retain the original occurrence as its runtime diagnostic cause, while the public payload contains the immutable original typed payload. Do not expose credentials or response body. Keep timeout-over-cancellation precedence and no retry, as already specified at `docs/syntax-taste/ai-io-spec.md:142,148-152`; normalization happens after the adapter classifies the outcome, without a second fetch. Domain occurrence/cause storage already exists in `runtime/domain.ts:18-25,125-135`, but attaching the original occurrence requires explicit implementation and tests.

3. **Define wrappers as typed transformations over completions, with one linear derivation chain.** A wrapper associates an operation and an ordered mapping from raw error identity to a handler. The built-in base covers the applicable seven; an authored derived wrapper inherits every omitted mapping and may replace a mapping or add a handler for an additional declared error. Apply ancestors in order, then the current declaration's handlers in source order; the last definition of an error identity wins. Reject an unknown target kind, a cycle, incompatible input/result/connection, or an override whose completion escapes its computed public bound. A handler may return the operation's result (`ok`, selective recovery) or a declared error. Recompute the derived wrapper's public bound from the **effective final handlers** plus unchanged passthrough errors; do not union obsolete base-handler errors after an override. Multiple inheritance is unnecessary now; if later added, it needs an explicit linearization and ambiguity rule. This directly implements `docs/implementation/design-revisions.md:40-46` without conflating semantic wrappers with the plain `fn` callable adapters seen at `examples/native-ai/src/oracles/oracles.can:77-123`.

4. **Normalize once at the outer fetch/judge boundary, after whole-batch validation and before caller dispatch.** Individual questions retain their own `ai::invalid_question`, `ai::invalid_answer`, and handler error bounds; the judge checks their union and connection identity as now (`docs/syntax-taste/ai-io-spec.md:241-255`; `compiler/internal/check/native_bodies.go:152-160`). The judge wrapper maps only the seven infrastructure errors. AI validation and application handler errors pass through with their typed identity. Do not convert a question-handler arithmetic/standard failure into `http::request_failed` or a bad model answer; A2.3/A3 specifically separate these (`docs/syntax-taste/ai-io-spec.md:87-93`). The single POST/validate-all/ordered handler phases remain intact.

5. **Propagate the public effect, not the raw adapter effect.** A call to a wrapped fetch/judge contributes `http::request_failed` and its unaffected errors to the caller's bound; `match` requires arms for those visible errors only. A pure forwarder may list/forward that public bound, and a caller that handles the normalized error can omit it from its own `emits`. A derived wrapper that recovers all applicable infrastructure outcomes may remove `http::request_failed` only if its effective handlers cannot emit it, while other escaped domain errors remain explicit. `[_]` remains outside domain `emits`. Do not solve this with R8's named `errorset`: it abbreviates the seven names but still requires seven arms (`docs/syntax-taste/redundancy-review-2026-09-22.md:455-504`). The current completion checker unions callee effects (`compiler/internal/check/completions.go:553-575`), so it must consume the wrapper signature, not the hidden native signature.

6. **Make error-first/`ok`-last a checked grammar invariant for success/error matches.** It is a confirmed requirement across matches (`docs/implementation/design-revisions.md:48-54`). Parse an arbitrary sequence of error arms followed by exactly one success arm; reject an error after `ok`, including after a `when` fixture section. Preserve the relative order of errors unless a later decision chooses a canonical order. Update formatter and all admitted fixtures/goldens consistently; no compatibility obligation exists (`AGENTS.md:1`). The eight-call fixture's present `ok`-first form (`compiler/testdata/current/fetch/main.can:70-168`) is the clearest migration probe. Do not change its nesting as part of this work (`docs/implementation/design-revisions.md:27-29`).

7. **Use two fixture layers to prove the boundary.** A call-site assertion's `when` completion should name `http::request_failed(detail)` or a recovered `ok`; it should never inject an unobservable raw seven-error completion. Raw HTTP fixtures must drive each adapter failure through the real wrapper, asserting the exact detail leaf/fields and outer occurrence provenance. Include status 404 selective recovery and status 429 passthrough; `status_error(429, normalized_headers)` is already an exact spec trace (`docs/syntax-taste/ai-io-spec.md:438-440`). Cover all seven kinds, omitted inherited handlers, last override, inherited selective recovery, extra `ai::invalid_answer` passthrough, no question wrapper, `[_]` passthrough, and raw/public effect checks. For the eight-call fixture, the acceptance metric is seven infrastructure names in each native/caller signature and each match becoming one public error name/arm, while all eight success calls and their existing shape remain (`compiler/testdata/current/fetch/main.can:11-168`). `docs/syntax-taste/ai-io-spec.md:338-350` already separates raw-provider fixtures from supplied completions.

## Critical assessment of adjacent simplifications

- **Question declarations (R1):** Preserve `noul`/`choice`/`score` as visible kinds; their different answer contracts are material. A single `question` header plus `kind` line adds a line without removing kind-specific validation. A common section order and a single Choice production are worthwhile independently of normalization (`docs/syntax-taste/redundancy-review-2026-09-22.md:18-98`; current A3.1 at `docs/syntax-taste/ai-io-spec.md:105-117`). Do not introduce wrappers around questions.
- **State calling (R6):** The final grouped state syntax blocks judge/LLM callable references and causes forwarding functions (`docs/syntax-taste/ai-io-spec.md:95-99`; `examples/native-ai/src/oracles/oracles.can:77-123`). A per-parameter `state` marker could unify call signatures while preserving serialization names and shared-state grouping, but it is a separate source/API redesign, not a prerequisite for failure wrappers. The alternative “last record parameter is state” is implicit and risks accidentally disclosing an ordinary data record (`docs/syntax-taste/redundancy-review-2026-09-22.md:320-389`).
- **Connection identity (R3):** Keep nominal declaration identity for judge/question batching. The compiler currently proves identical connection IDs statically (`compiler/internal/check/native_bodies.go:152-153`), and the spec expressly rejects independently declared identical settings (`docs/syntax-taste/ai-io-spec.md:241-247`). Runtime record value equality would move this proof into the request path, conflate credentials/policy with data, and change the compile-time config rule (`docs/syntax-taste/ai-io-spec.md:121-140`). Lexical nearest-connection selection becomes ambiguous as soon as a file imports two services. Revisit only as a separate capability-design decision.
- **`choice_arm` (R2):** A generic callable spelling alone misrepresents its semantics: an arm is currently capture-free, has a constant `describes`, is invoked by static spread, and receives contextual `%`, with no ordinary `call arm()` (`docs/syntax-taste/ai-io-spec.md:289-297`). Ordinary callables would need an explicit probability argument, static description witness, and capture rule that preserves descriptor determinism. Keep the dedicated type until that full conversion is designed; merely making its type look like `callable` saves syntax while hiding a semantic distinction (`docs/syntax-taste/redundancy-review-2026-09-22.md:100-146`).
