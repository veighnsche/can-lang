# LD29 pre-dispatch audit

Three independently worded requests contain four Choice questions each. All explanatory state, instructions and option descriptions differ across every packet. Technical identifiers, example code and option keys are deliberately stable. Programmatic uniqueness checks ran before dispatch; the complete packets were reviewed for these shared meanings:

- Can identity, no compatibility requirement, native lowering and attached ownership remain constraints.
- Existing helper deliberately divides by zero; a real named check needs a reason and source span in applications and fixtures.
- API alternatives are one conditional catalogue operation, a failure-only operation with authored branching, a keyword, or no selection.
- Channel alternatives are recoverable declared domain failure, recoverable distinct standard check failure, test-sticky authored checks with standard production behavior, or no selection.
- Domain errors require explicit bounds/handling and already admit expected constructor payloads; standard snapshots remain opaque and currently lack direct expected rows.
- Both standard-expectation and domain-expectation questions explicitly assume their channel. Questions run independently; only the applicable branch informs the final choice.
- Standard-expectation alternatives retain named catch adapters, introduce a check-only row matcher, broaden standard matching, or leave the decision open. Domain-expectation alternatives retain existing grammar, extend it anyway, or remain undecided.
- Every candidate excludes bypassing sticky actual harness violations or expecting supervisor timeouts. Reasons evaluate once in ordinary order, including on true; lower to a native branch and existing adapter, without production disabling.

No packet contains an earlier answer or an asserted preferred choice. The sticky-authored-check alternative is distinct from the non-negotiable stickiness of infrastructure violations. Code-like names are hypothetical candidates, not reported as existing catalogue declarations. No new error ID has been allocated. Advisory agreement will not count as proof; disagreement requires engineering analysis of the alternatives against these facts.
