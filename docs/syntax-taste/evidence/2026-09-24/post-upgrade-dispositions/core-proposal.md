# Core proposal for the next upgrade

24 September 2026. This is a proposed fix/retain/defer disposition for P03–P05, P13–P21 and B02. It is decision input, not an implementation record or a claim that a new contract has already been selected. The [post-upgrade reconciliation](../../../post-upgrade-reconciliation-2026-09-24.md) distinguishes the defects from proposals, and the [core source audit](../post-upgrade-reconciliation/core-source-audit.md) checks them against current source and earlier decisions. No source change or fresh execution is claimed here.

**Recommended next-upgrade core scope: P03 and B02.** “Fix” for P03 means accepting a bounded new composition capability, not relabeling the existing checker as defective. “Fix” for B02 is a conformance repair under the existing text contract. Retain the shipped rules where the review gives no reason to reverse them; defer the broader mechanisms until their stated comparison or workload gate is met. This scope keeps DI-04's declaration-time parametric guarantee and C6's native JavaScript semantics.

| ID | Proposed disposition | Reason and prerequisite | Smallest observable acceptance / boundary |
| --- | --- | --- | --- |
| **P03 — public generic helper composition** | **Fix in the next upgrade, as a bounded extension.** | Extracting a parametric helper currently changes an exported generic from valid to rejected solely because its type argument is opaque. DI-04 selected declaration checking and explicit operation inputs, but did not select generic-to-generic symbolic calls. The [specializer](../../../../../compiler/internal/check/specialize.go#L88) rejects all non-self opaque applications because a private generic may be only a concrete template. Before admission, establish that the called body has discharged a parametric obligation; do not trust an arbitrary generic signature. | An exported identity wrapper and a nested helper chain compile with unchanged public inputs and results, including a cross-package call and declaration reordering. A reached private template cannot be treated as validated by accident. Editing the helper to perform unsupported `+` fails at its declaration even if today's concrete calls use `int`. Explicit callable/dictionary inputs remain required for actual representation-dependent operations. A mutually recursive or growing type-argument cycle terminates checking with a clear result, and opaque symbolic identities never enter concrete specialization/emission. Start with a small validated subset if cycles cannot be admitted soundly. Exact eligibility spelling and validation graph are left to implementation design. |
| **P04 — failure-preserving authored wrappers** | **Defer finite error-set parameters; retain explicit written bounds and result-data composition.** | DI-03/LD14 already deferred a new generic kind. The [callback checker](../../../../../compiler/internal/check/array.go#L276) shows catalogue operations derive invocation errors, while authored APIs cannot express the same dependency. That asymmetry is real, but an effects parameter brings row union, overlap, inference, specialization and diagnostic rules. P03 alone does not solve it. | Reopen after one reusable wrapper around another wrapper is authored for two unrelated error domains in both current idioms: exact concrete bounds and nominal result data. Record whether either changes error identity, short-circuiting or the public signature, and count required adapters. If a narrow parameter is then proposed, require exact error identity, explicit public contracts, declaration-time validation and no implicit widening. No full effects system is selected now. |
| **P05 — dynamically growing iteration** | **Defer a new stack-safe mechanism; retain and state the present recursion boundary.** | The saved [countdown result](../post-upgrade-review-961f921/core-probes/relay-output.txt) overflows around 10,000 on the review's local Bun, but `relay` promises completion forwarding, not tail-call optimization. Native-backed folds already traverse existing arrays. Direct loop lowering could change per-call assertion frames, fixture paths, failure origins and evaluation order; LD21 deferred a narrower early-stopping accumulator. | State in the current language reference that `relay` carries no stack-safety guarantee and avoid a portable numeric threshold. Reopen mechanism choice with a 100,000-step state loop and a paginated callback case, then compare direct-self lowering with an explicit immutable-state iteration API under named failures, faulting arguments, repeated fixtures, captures and concurrent roots. A pure countdown alone cannot qualify the feature. No general recursion elimination is implied. |
| **P13 — explicit `near` capture binding** | **Retain name-based capture; defer new binding syntax.** | DI-08/LD38–39 selected the current rule and explicit context records. A same-typed rename or shadow can redirect a capture, but no controlled refactor shows a material failure that context records or diagnostics cannot prevent. | Keep the current creation-time immutable capture behavior. Reopen with a held-out rename/shadow repair task comparing explicit context records against site-level bindings, including a same-type shadow that must not silently change the intended value. Do not alter ordinary input binding or `near` lifetime as part of that experiment. |
| **P14 — local-elision error** | **Retain provisionally; defer demotion to advice.** | C8/DI-23b selected the narrow validity rule. The [checker predicates](../../../../../compiler/internal/check/locals.go#L41) require a single-use, nonfaulting local immediately returned unchanged; the review's explanatory `invoice_total` local is a genuine authoring cost, but not proof all useful locals are rejected. | Compare agent creation, rename and repair on a meaningful domain local versus an accidental alias. If a measured correctness or task-cost benefit warrants demotion, specify diagnostic severity and preserve substitution-equivalent typing; do not silently remove unrelated local checks. |
| **P15 — Boolean match arm order** | **Retain `false` before `true`.** | This was an [explicit September 23 choice](../../../decisions.md#matching), scoped to a single Boolean scrutinee. The observed rejection follows that rule and does not affect exhaustiveness. Taste disagreement alone does not justify a reversal. | Existing valid/invalid arm-order tests remain the acceptance boundary. A future reversal requires a new user decision, separately from multi-scrutinee, completion, coordination and AI ordering. |
| **P16 — multiline delimited expressions** | **Defer continuation grammar; retain the current physical-line rule and formatter.** | LD46/DI-23 deferred grammar until formatter and agent-edit evidence; the [lexer](../../../../../compiler/internal/syntax/lexer.go#L90) intentionally rejects open-delimiter newlines. Long lines are real, but the continuation and comment/indent rules are still unchosen. | Reopen only after held-out agent edits show material failures or repair cost under the existing comment-preserving formatter. Test calls, constructors, nested delimiters, comments and diagnostic spans without changing block indentation semantics. |
| **P17 — authored cleanup abstraction** | **Retain explicit cleanup and owner fallback; defer new helper or `try/finally` form.** | DI-12 selected explicit owner-scoped cleanup. The [current stream pump](../../../../../examples/stream/src/main.can#L23) now closes on read failure; the former omission is repaired. Repeated branches remain, but the exact abstraction and failure precedence need evidence. | A comparison should run the same stream pump with a named helper and a narrowly scoped native-lowered cleanup form. Preserve exactly-once close and the primary read failure when close also fails. This is not a new repair of the already-fixed sample. |
| **P18 — bulk immutable Map/Set construction** | **Defer bulk API selection; retain immutable point operations.** | C7 requires fresh native copies for point updates. Distinct-key repeated insertion is quadratic by [source](../../../../../runtime/collections/set.ts#L40), and the review's timings illustrate cost, but DI-20 asked for representative scale and semantic rules first. | Reopen with registered unique and duplicate-heavy workloads and a native one-build/one-publication trial. Specify duplicate-key winner, insertion order, callback failure, ownership and alias immutability. Preserve point-update semantics; do not infer mutable public aliases or a custom persistent engine. |
| **P19 — schema-aware SQL tooling** | **Retain statement/parameter/cardinality checking plus runtime row validation; defer schema snapshots.** | DI-14b explicitly excludes a compile-time database-schema proof. The wider declared row accepted for `SELECT id` is within that contract. Build-time schema checks would need migration and deployment provenance. | Reopen only with a versioned schema source tied to an executed drift case and deployment version. Current acceptance is accurate descriptor diagnostics followed by runtime rejection of rows that do not match their declared type; do not describe it as schema agreement. |
| **P20 — mutation `RETURNING`** | **Defer descriptor extension; retain transaction plus SELECT.** | DI-14a deferred it, and the [cardinality checker](../../../../../compiler/internal/sql/cardinality.go#L29) deliberately rejects mutation results. Native dialect support alone is insufficient to establish a Can-level shape and error contract. | Reopen with an executed invoice/webhook post-write case showing extra read, race or round-trip cost. A proposal must specify dialect support, returned-row cardinality, affected-row bounds and transaction behavior. It must not infer mutation limits from SELECT `LIMIT`. |
| **P21 — owner-selected abstract equality** | **Retain eligible structural equality; defer an abstract-equality redesign.** | DI-02 deliberately kept equality on stored fields. [Eligibility](../../../../../compiler/internal/types/inhabitation.go#L118) can change when a hidden field changes, which affects package evolution but does not bypass owner construction or codec confinement. | Reopen with a two-version owner-package example where public factories/projections preserve intended equivalence while representation changes. Compare an exported owner comparison against foreign automatic equality and decide explicitly which semantics imports observe. Preserve the already-qualified owner boundary and ordinary record equality. |
| **B02 — Unicode empty regex advancement** | **Fix in the next upgrade.** | `text::matches` increments `RegExp.lastIndex` by one UTF-16 unit after an empty match. Under `u` or `v`, that enters a surrogate pair and repeats an offset. The [saved probe](../post-upgrade-review-961f921/core-probes/regex-output.txt) records `[0,0,0,0,0]` for `(?:)` on `😀x` where native `matchAll` yields `[0,2,3]`. This contradicts C6's native-operation contract. | With limit 5, emitted `text::matches` yields starts `[0,2,3]` for the Unicode empty pattern; non-Unicode empty matches, nonempty astral matches, captures, UTF-16 end offsets and the existing limit/error contract remain correct. Prefer native capped iteration or a minimal adapter implementing native Unicode advancement. The cap only bounds work; it is not a correctness substitute. |

The next-upgrade delivery boundary is therefore two observable core changes: a validated public-generic composition path and native-equivalent empty-regex advancement. The other rows are retained contracts or explicitly gated investigations. P03 should not be implemented by allowing symbolic arguments through an unvalidated private template or by routing opaque instances into the concrete-emission cache; B02 should be verified against native JavaScript/Bun behavior. The [review's core reconciliation](../post-upgrade-review-961f921/core-reconciliation.md) details the unsound cases and the limits of pure-countdown and callback-only evidence.
