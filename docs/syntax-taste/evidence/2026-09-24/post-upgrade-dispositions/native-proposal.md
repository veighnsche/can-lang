# Native, AI and qualification disposition proposal

24 September 2026. This proposal covers P06–P07, O01–O05, B03–B04, U06 and the native/test/dependency observations in the [post-upgrade reconciliation](../../../post-upgrade-reconciliation-2026-09-24.md). It selects next-upgrade treatment, not a new implementation or test result. The [native source audit](../post-upgrade-reconciliation/native-source-audit.md) supplies detailed source anchors. Here **fix** means close an accepted gap or defect, **retain** means preserve a selected policy, and **defer** means keep a new mechanism outside the next upgrade until its stated evidence is available.

| P06 — response publication after race | **Retain** owner leases and draining; **defer** a changed response/loser policy pending a live HTTP hedge measurement. | The native aggregate selects promptly, while the request's `withScope` waits for owned losers before returning a response. The saved 2 ms selection / 83 ms root result measures a root, not HTTP. Compare a real request under current drainage with operation-local deadlines, cooperative abort where the native operation supports it, and server-supervised ownership only if a loser can lawfully outlive the response. Record response time, lease and resource state, late failures, cleanup, shutdown, client disconnect, and irreversible effects. A faster hedge alone cannot authorize dropping leases or assuming cancellation rolls back effects. Any later policy must explicitly assign loser effects and shutdown responsibility, then pass the corresponding fault matrix. The review's native execution, testing and dependency foundation is **retained as a bounded positive finding**. The 144-operation catalogue inventory, T19 native Linux qualification (78 APIs and 10 probes), final T20 Gate 4 result, T25 browser gate, and T27 source checks have recorded evidence for their exact configurations. Additional host, adapter or browser-runtime conformance is a new qualification proposal or part of the separately identified U04 acceptance, rather than a reason to erase those passes. The review itself freshly ran narrower compiler/runtime suites and probes; it did **not** rerun a release build, installed Linux Gate 4, live provider/database workflow, full Playwright matrix, deployment or security audit. Keep those two evidence vintages distinct. [Coverage](../../../../implementation/coverage.md), [T task record and final acceptance](../../../can-implementation-task-list-2026-09-24.md), [review verification](../../../post-upgrade-language-review-961f921-2026-09-24.md#verification-and-limits).

The opaque `=> ok` observation limit is also retained: it establishes completion, not response bytes or external effects. Attached assertions, scenario links, verified publication and external deadlines exist, while DI-13's companion protocol/browser/database observations remain the acceptance method where product effects matter. A missing specified companion observation is an unfinished acceptance check for its own feature; a new assertion-language form requires a separate proposal. [Assertions](../../../../implementation/assertions.md), [DI-13](../../../preparation/design-disposition-ledger.md).

No live HTTP hedge, new host qualification, or agent comparison was performed for this proposal. The P06 measurement and the O03 workflow comparison are candidate evidence; cooperative cancellation, supervised losers, a nonempty-race API and new AI syntax are candidate mechanisms, not decisions inferred from those measurements.
