# Platform disposition proposal for the next upgrade

24 September 2026. This is an independent proposal, not a selection of exact syntax, runtime architecture, or implementation tasks. It uses the [post-upgrade reconciliation](../../../post-upgrade-reconciliation-2026-09-24.md), its [platform source audit](../post-upgrade-reconciliation/platform-source-audit.md), the [post-upgrade review](../../../post-upgrade-language-review-961f921-2026-09-24.md), the earlier [integrated action contract](../../../preparation/integrated-action-contract.md) and [browser target design](../../../preparation/browser-target-design.md), and the [T01–T27 execution record](../../../can-implementation-task-list-2026-09-24.md). No code or tests were run for this proposal. “Fix” means include the outcome in the next upgrade; “retain” keeps an already selected boundary; “defer” requires new evidence and a separate decision. These labels do not treat a review suggestion as an accepted implementation mechanism.

## Recommended platform scope

Finish the already selected shared action and browser delivery contracts, repair the browser audit defect, and close the three accepted UI behavior gaps. This joins the next upgrade's independent Unicode regex defect and public generic composition decision without making either a platform implementation dependency. The useful release claim is narrower and observable: an unrelated application can build one contract package for server and browser, bind authenticated request-aware handlers, serve its generated browser asset through a maintained command, and exercise it without the invoice-specific rewrite or test-only runtime shims. Keep the browser's bounded native catalogue and explicit state/rendering model while doing that work.

| --- | --- | --- |
| **U01** shared transport declarations | **Fix.** The accepted integrated packet already places HTML save, JSON save and JSON load declarations in one locked package; current mandatory `handles` and client stubs defeat that boundary. Prerequisite: decide the declaration/binding interface consistently with U02 while retaining canonical package-instance identity and finite wire/case checking. Acceptance: both targets import the same three action symbols; the browser build contains no server handler or placeholder handler; a method/path/body/case edit is checked through that one symbol. Do not require compatibility with today's action spelling. |
| **U02** request context and startup services | **Fix.** A checked mount must bind server-derived actor/request data and startup-owned services to the live operation; present action handlers accept only captures/body and the invoice JSON routes work around that. Prerequisite: U01 contract/binding boundary, existing request scope and guarded route lifecycle. Acceptance: one startup pool is used by the checked GET/POST handlers, actor is derived from the incoming request and revalidated for each protected operation, and no client-supplied token grants access. This does not select automatic authentication, ambient injection, or a new global dependency system. |
| **U03** route and cross-target agreement | **Fix.** The declared captured GET and mounted query GET diverge; Gate 5 rewrites the URL and direct captured access returns 404. Prerequisites: U01/U02 plus the existing capture/router and action-fetch support. Acceptance: the declared captured GET reaches the checked live handler without origin rewrite; HTML and JSON save/load run through the selected mounts; route, capture, field, leaf and body-mode edits either update linked uses or diagnose them on both targets. Preserve authorization and replay checks from the integrated contract; static linkage alone does not prove them. |
| **P01** bound-callable client projection | **Retain the selected declaration/mount split; defer this alternative.** The earlier packet chose handler-free transport declarations and separate request-aware server binding. A bound callable whose browser projection is truly server-free may be viable, but it changes that choice without being necessary to finish U01/U02. Reopen only with a concrete two-target prototype that proves no server capability enters the client closure and improves the checked binding/authoring result over the selected split. |
| **U04** maintained browser delivery | **Fix.** The compiler emits gated TypeScript and a manifest, while the tested grid bundle needs four Node-module semantic shims with limited async-context claims. Prerequisites: identify the reachable emitted/runtime dependency and sourcemap closure, define a supported build/publish command and browser runtime semantic boundary, then qualify it in named browsers. Acceptance: an empty Can app and the invoice grid boot from the supported command without importing the test bundler; standard faults/diagnostics, equality, async callbacks, disposal, admitted coordination and codec parity behave under that command; emitted assets and reachable runtime dependencies contain no server-only capabilities or secrets. A bundler is allowed. |
| **P02** browser runtime profile versus maintained shims | **Defer the mechanism choice within U04.** A dedicated browser runtime and a fully maintained semantic adapter layer are alternatives, not separate product requirements. Choose after a dependency inventory and focused probes show which native JavaScript/Bun operations and adapters preserve Can's contracts with the least semantic surface. The observable decision gate is the U04 empty-app/grid/failure/async matrix plus closure audit; merely copying the grid's synchronous `AsyncLocalStorage` shim fails it. |
| **U05** cancelable events | **Fix.** Explicit `preventDefault` on admitted cancelable events was selected; the four-field snapshot/listener contract cannot perform it. Prerequisite: specify which admitted event kinds are cancelable and how a view-owned handler may request cancellation without retaining a raw native `Event`. Acceptance: a keyboard or submit fixture prevents its native default when requested, leaves uncanceled behavior intact, and rejects cancellation after disposal or for an unsupported event. Native `Event.preventDefault` should do the work. |
| **P08** richer event payloads | **Defer.** Checked state, modifiers, file lists and IME composition are separate capabilities absent from the first selected catalogue. Do not combine them into an undifferentiated event expansion or promise arbitrary host objects. Reopen each with an all-Can interaction that cannot be expressed under the accepted event API, a bounded immutable projection/ownership contract and a browser test (for example checkbox state, composition-safe edit, or selected files). U05 does not depend on these additions. |
| **P09** reload-persistent drafts | **Retain the current in-view boundary; defer persistence.** Both accepted packets expressly exclude reload durability and automatic offline replay. A persistent draft would need a storage/privacy/version/migration contract and a rule for uncertain saves and identified replay across reload. Reopen with a product requirement and crash/reload test that retains raw invalid input, reconciles an uncertain commit, and never blindly repeats a write. Its absence must not fail the next upgrade's existing grid claim. |
| **P10** browser history and WebSocket | **Defer.** Neither is in the first browser catalogue; server WebSocket is a separate capability. Reopen history and browser sockets independently with concrete navigation or real-time workflows, lifecycle and origin/authentication contracts, and a test that distinguishes view disposal, reconnection and server state. Neither is a prerequisite for supported browser delivery. |
| **P11** catalogue expansion versus typed host adapters | **Retain the controlled catalogue; defer an extension architecture.** DI-19 did not admit arbitrary SDK/JavaScript imports, and a generic adapter would create a new capability and auditing boundary during U04 closure work. Reopen after at least two concrete missing native browser operations expose repeated compiler changes; compare bounded catalogue entries against a reviewed typed adapter using the same capability-closure, native-operation, error and ownership tests. A single checkbox or persistence proposal does not select a general escape hatch. |
| **P12** reusable field/keyed-row editors and component syntax | **Defer language syntax; allow a bounded library experiment after S03.** Named functions and typed nodes already compose, while manual rendering/focus coordination is costly. Preserve explicit state and view ownership. Acceptance for reconsideration: extract one typed field and keyed-row editor, then add one field without duplicating several event/state/DOM paths; keyboard focus, selection/IME where supported, reorder, late replies and disposal remain correct. If a library meets this, no component syntax follows. S03 repairs must not wait for the experiment. |
| **B01** browser artifact false positives | **Fix.** Raw substring scanning rejects harmless literal `"Bun."` and `"node: introduction"` while accepting equivalent concatenation. Prerequisite: replace text scanning with structured import/capability evidence and coordinate with U04's full reachable-runtime audit. Acceptance: those literals and equivalent generated text compile; actual forbidden imports/operations, including reachable runtime dependencies, still fail with useful source attribution. The positive text tests and negative capability tests must use the supported browser pipeline. |
| **S01** visible HTML 503 feedback | **Fix.** The accepted integrated contract requires a 503 to replace stale feedback; current HTMX policy suppresses its swap. Prerequisite: the HTML action response/status and safe fragment policy. Acceptance: a real 503 retains status 503 and visibly replaces the intended target's stale feedback; 200/422/409/403 behavior follows the selected per-status display contract without relabeling failure as success. |
| **S02** browser callback failures | **Fix.** The browser packet requires observable event-handler failure; current `settle` consumes rejection. Prerequisite: choose a bounded reporting path consistent with sanitized startup faults and view lifetime, without treating an ignored rejection as success. Acceptance: a deliberately failing admitted handler produces an observable, sanitized diagnostic exactly once and does not silently mutate state; disposal still releases listener resources. This does not require new Can failure syntax. |
| **S03** grid focus, announcement and visible save state | **Fix.** Gate 5 records `L-focus-row`, `L-notice` and `L-flight`; focus restoration and visible save/error state were selected outcomes. Prerequisite: U04's supported browser test path for final qualification, though local app corrections can begin earlier. Acceptance: after add/move/reorder, focus lands on an attached intended cell; a blocked save notice survives rerender and is announced; an in-flight save has a visible state until settlement; late response/disposal does not overwrite newer edits. No exact notice wording or literal `saving...` label is required. |

## Sequencing and limits

B01 can be repaired independently but must feed U04's final closure audit. U01 and U02 need a single declaration/mount contract before U03 can remove route rewriting and prove linked edits. U04 and U01–U03 are independent implementation lanes until the real browser/server qualification, where both are required. U05 and S02 share the event boundary; S03 depends on their relevant interaction semantics and U04 for final browser evidence. S01 is the HTML lane. The generic helper proposal should be qualified separately and must not turn an action or UI task into an error-parameter, component, or host-adapter redesign.

The review's final milestone mentions a persistent editable UI, but the earlier accepted browser packet explicitly promises only an in-view draft. Treat reload persistence as P09, not an implicit U04/S03 acceptance criterion. Likewise the review's preferred browser runtime profile and bound-callable action projection are alternatives to be assessed, not authority to replace selected boundaries. T21–T25 passing their recorded checks establishes real browser Can and a tested grid; it does not erase their documented delivery, route and UI limits. No backwards-compatibility aliases or old generated layouts are needed because the repository has no external users.
