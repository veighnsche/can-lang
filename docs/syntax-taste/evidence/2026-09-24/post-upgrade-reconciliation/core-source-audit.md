# Core source audit for the post-upgrade review

Scope: review §§3–5, 8–9, owner-record equality in §10, and the Unicode regex defect. Audited against current `fbd2a56`; the review measured `961f921`. This is a source/document audit, not a new implementation or design selection. “New proposal” below means a proposed change to a retained rule or an extension with no accepted implementation contract. “Unfinished accepted requirement” means a selected contract whose specified behavior is still absent. The earlier probes support their stated local observations; no broad suite was rerun here.

| Review finding | Classification and current evidence | Earlier decision / qualification |
| --- | --- | --- |
| §3 public generic calling another generic with an opaque type argument | **New proposal** to relax a deliberate restriction, not a bug in the accepted declaration check. Exported generic bodies are symbolically checked at declaration, while private generics keep concrete template checking ([checker](../../../../../compiler/internal/check/exported_generics.go#L13)). Instantiation rejects another generic with opaque arguments except identical-variable self recursion ([specializer](../../../../../compiler/internal/check/specialize.go#L88)); the review's full-program private/public probe records the difference ([independent core](../post-upgrade-review-961f921/independent-core.md#L23)). A safe broader rule would need evidence that the callee has discharged a parametric obligation, including private helper reachability and cycles; substituting into an arbitrary template signature is unsound ([reconciliation](../post-upgrade-review-961f921/core-reconciliation.md#L5)). | **Accepted and shipped:** DI-04 requires declaration checking, rejection of representation-dependent body operations, and explicit callable/dictionary inputs, while preserving private template behavior ([accepted decision](../../../preparation/accepted-technical-decisions.md#L222)). It does **not** promise generic-to-generic symbolic calls. The review's proposed safe composition is additional design work; do not relabel declaration checking “unfinished” or remove it. |
| §4 callback-specific finite errors in authored generic wrappers | **New proposal** for an authored library contract. Catalogue array operations take the actual callback's error set as the invocation bound ([array checker](../../../../../compiler/internal/check/array.go#L267), [selected C7](../../../technical-spec.md#L228)); authored generic declarations have no error-set parameter ([exported checker](../../../../../compiler/internal/check/exported_generics.go#L13)). A two-domain, 28-assertion current-Can probe establishes real fixed-bound extra arms and result-data adapters, but no agent-maintenance win for new syntax ([generic helper probe](../../../preparation/generic-helper-probe.md#L1)). | LD14 explicitly defers finite error-set parameters pending demonstrated scope and a prototype; LD12 retains written public `emits` bounds ([ledger](../../../../implementation/language-design-dispositions-2026-09-22.md#L44)). DI-03 compares concrete bounds, result data, and a finite parameter; its trial does not authorize a general effects system ([alternatives](../../../preparation/core-alternatives.md#L144)). The review correctly keeps exact remedy open. |
| §5 deep terminal `relay` recursion overflows | **New proposal** for stack-safe state iteration, with a verified current limitation. The emitted countdown yielded `native_exception` at 10,000 on the review's Bun 1.4.2, while 100 and 1,000 completed ([probe](../post-upgrade-review-961f921/independent-core.md#L61), [emitted output](../post-upgrade-review-961f921/core-probes/relay-output.txt)). Emission invokes each call through a completion/context boundary ([emitter](../../../../../compiler/internal/emit/regions.go#L384)); assertion contexts create nested invocation frames and copy identity paths ([context](../../../../../runtime/assert/context.ts#L285), [identity](../../../../../runtime/assert/identity.ts#L54)). A direct loop rewrite could change fixtures and diagnostics. | The selected iteration story is sequential native-backed collection operations and terminal completion; there is **no stack-safety or tail-call-elimination promise** for recursion ([decisions](../../../decisions.md#L2283), [relay definition](../../../decisions.md#L1540)). LD21 deferred the narrower early-stopping accumulator pending workload evidence, not a general dynamic-loop contract ([ledger](../../../../implementation/language-design-dispositions-2026-09-22.md#L54)). Documenting bounds is immediately accurate; a state-iteration primitive or tail lowering remains a separate choice, not a compiler contract already violated. |
| §8 `near` capture follows callee parameter spelling | **New proposal** for explicit binding; current behavior is by design. At `callable` creation, the checker looks up `declaration.Names[i]` in the reference site's scope and checks exact type ([capture checker](../../../../../compiler/internal/check/callables.go#L124)); a same-typed rename/shadow can therefore change which immutable value is captured. Existing record/context arguments remain a valid explicit idiom ([core evidence](../../../preparation/core-evidence.md#L40)). | `near` and ordinary inputs have different selected roles ([decisions](../../../decisions.md#L1072)); LD38 retains them and LD39 explicitly defers changed capture syntax until a concrete edit failure and comparative prototype ([ledger](../../../../implementation/language-design-dispositions-2026-09-22.md#L80)). A plausible refactor hazard alone does not mark the deferred syntax as unfinished accepted work. |
| §8 forwarded local rejected as unnecessary | **New proposal** to demote an accepted validity rule to advice. The checker requires a final binding followed by the same terminal name, one use, no capture, simple nonfaulting expression and equivalent substitution typing before diagnosing ([local checker](../../../../../compiler/internal/check/locals.go#L41)); the review's `invoice_total` example triggered it ([independent core](../post-upgrade-review-961f921/independent-core.md#L112)). It is narrow; naming arbitrary complex or faulting expressions is not categorically forbidden. | C8 explicitly selects the local-binding rule ([technical spec](../../../technical-spec.md#L254)). Its authoring cost can be evaluated, but it is not an accidental checker rejection. LD48 retains the general core design; DI-23 calls for a controlled agent/edit comparison before replacing this rule ([agent evidence](../../../preparation/ai-support-evidence.md#L31)). |
| §8 `false` must precede `true` in ordinary Boolean match | **New proposal** to change an explicit user choice. The checker enforces this only for a single Boolean scrutinee with literal arms ([match checker](../../../../../compiler/internal/check/completion_matches.go#L428)); usefulness/exhaustiveness checking is separate. The review observed a direct rejection ([independent core](../post-upgrade-review-961f921/independent-core.md#L123)). | The user selected this exact order on 2026-09-23, explicitly excluding completion, coordination, multi-scrutinee and AI criteria ([decisions](../../../decisions.md#L1641)). Treat advice-only ordering as a proposed reversal, not an unimplemented prior requirement. |
| §8 physical-line limit on delimited expressions | **New proposal** for multiline continuation. Lexer rejects newline with open delimiters ([lexer](../../../../../compiler/internal/syntax/lexer.go#L90)); long calls/constructors/assertions therefore remain a real presentation cost. | LD46 defers multiline forms until safe formatting and measured line pressure; LD45 accepts a comment-preserving formatter as separate work ([ledger](../../../../implementation/language-design-dispositions-2026-09-22.md#L87)). DI-23 also explicitly leaves continuation syntax unselected ([agent evidence](../../../preparation/ai-support-evidence.md#L31)). The review should not imply the delimiter rule was accepted but left unimplemented. |
| §8 cleanup repetition | **New proposal** for an authored cleanup abstraction; the repeated failure arms in the *current* stream pump are real ([stream](../../../../../examples/stream/src/main.can#L23)). It now explicitly calls `close_reader` in read-failure, cancellation, limit, and EOF arms, and preserves the primary failure if close also fails ([stream](../../../../../examples/stream/src/main.can#L34)). Runtime fallback remains a distinct ownership guarantee, not an authored `finally` equivalent ([owner evidence](../../../preparation/lifetime-deployment-evidence.md#L15)). | LD19 retains existing chain/completion ownership, LD20 defers new sequencing syntax ([ledger](../../../../implementation/language-design-dispositions-2026-09-22.md#L52)). Any `try/finally` or helper design needs explicit primary/cleanup precedence; the current stream example has selected precedence in source. **Stale active evidence:** [lifetime preparation](../../../preparation/lifetime-deployment-evidence.md#L21) and [recommendation program](../../../can-recommendation-program-2026-09-24.md#L67) still assert that the stream's read-error arms omit `close_reader`. That omission is no longer present. |
| §9 repeated immutable Map/Set point updates copy the collection | **New proposal** for bulk construction or aggregation, not a defect relative to C7. Runtime `insert`/`replace`/`remove` copy the native Map and Set `add` copies the native Set ([map](../../../../../runtime/collections/map.ts#L47), [set](../../../../../runtime/collections/set.ts#L40)); distinct-key repeated insertion has quadratic total copying by source analysis. The gallery uses a fold for word frequencies ([example](../../../../../examples/gallery/src/24-map-word-frequencies.can#L1)); the review's Set timings are illustrative local data ([probe](../post-upgrade-review-961f921/native-probes/immutable-set-scaling.stdout)). | C7 explicitly selects fresh native copies and immutable aliases ([spec](../../../technical-spec.md#L252)). DI-20 calls for realistic duplicate-heavy/unique workloads and native bulk adapter comparison before selection ([prep](../../../preparation/ai-support-evidence.md#L21)). No mutable alias or persistent-collection redesign follows from the measured copy cost. |
| §9 SQL declared row may exceed `SELECT` projection | **New proposal** if requesting schema-aware build checks; current static/runtime boundary is accurately selected. Descriptor checking validates ordinary row/parameter types and their SQL-admissible fields, then statement shape, without database-schema comparison ([descriptor checker](../../../../../compiler/internal/check/sql_descriptors.go#L47)); a positive test accepts `SELECT id` with a wider row ([test](../../../../../compiler/internal/check/sql_test.go#L84)). Runtime row validation remains part of the contract. | LD35 retains compiler-validated static descriptors, and the recommendation program expressly says statement/parameter/cardinality checks plus runtime row validation do not prove schema agreement ([program](../../../can-recommendation-program-2026-09-24.md#L57)). Calling this a checker bug would impose a guarantee never selected. A versioned schema snapshot is separate tooling. |
| §9 mutation `RETURNING` rejected | **New proposal** for a native mutation result descriptor. Current cardinality logic requires `SELECT` for row-returning shapes and rejects `RETURNING` on `execute` mutations ([cardinality](../../../../../compiler/internal/sql/cardinality.go#L24)); this matches the original task's negative acceptance ([I37 task](../../../../implementation/tasks.md#L106)). | The recommendation program permits a targeted Gate 3 `RETURNING` trial if it removes a demonstrated read-after-write ([program](../../../can-recommendation-program-2026-09-24.md#L57)). It is not unfinished accepted language behavior. The present `LIMIT` rule bounds SELECT rows, not the number of rows any mutation affects. |
| §10 owner-record automatic equality depends on hidden fields | **New proposal** for owner-selected abstract equality. Foreign construction, representation access/update and codec paths are rejected ([owner tests](../../../../../compiler/internal/check/owner_record_test.go#L111)); equality eligibility recursively traverses stored fields with no owner exception ([eligibility](../../../../../compiler/internal/types/inhabitation.go#L118)). Admitted aggregate equality lowers to strict `Bun.deepEquals` ([emitter](../../../../../compiler/internal/emit/expressions.go#L178)), observing the native record's stored fields ([representation](../../../../../runtime/data.ts#L21)). Adding an internal field can change equality or make it ineligible; that does **not** bypass owner invariants. | DI-02 deliberately retained existing eligible structural equality for owner records ([accepted decision](../../../preparation/accepted-technical-decisions.md#L60)). The later core reconciliation calls owner-selected equality an abstraction-evolution experiment, not invariant repair ([reconciliation](../post-upgrade-review-961f921/core-reconciliation.md#L54)). |
| Unicode empty `text::matches` with `u`/`v` | **Bug.** The runtime builds a global native regex and increments `lastIndex` by one UTF-16 unit after an empty match ([runtime](../../../../../runtime/text.ts#L169)). With `(?:)` on `😀x`, repeated scans under `u`/`v` return start `0` up to the cap while native `matchAll` advances through `[0,2,3]` ([probe output](../post-upgrade-review-961f921/core-probes/regex-output.txt)); current tests cover empty matches without `u`/`v` and a nonempty astral match, leaving this gap ([tests](../../../../../runtime/test/text.test.ts#L137)). | C6 uses UTF-16 positions but favors native operations and contract adapters; this is an incorrect adapter for native Unicode regex advancement, not a proposal for new syntax ([primitive contract](../../../technical-spec.md#L198)). The match limit bounds runtime work but does not correct duplicate offsets. |
