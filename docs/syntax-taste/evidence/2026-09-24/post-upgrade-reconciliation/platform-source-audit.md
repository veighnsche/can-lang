# Platform source audit for the post-upgrade review

24 September 2026. Scope: sections 1, 2 and 7, plus the browser-artifact defect, of [`post-upgrade-language-review-961f921-2026-09-24.md`](../../../post-upgrade-language-review-961f921-2026-09-24.md). This is a source and prior-decision reconciliation, not a new implementation decision. “Unfinished accepted requirement” means the September 24 integrated/browser product contract already selected the outcome; it does not imply that every illustrative spelling in those packets became current syntax. The review's proposed remedies are classified separately from the underlying gap. No test suite was rerun for this audit.

## Section 1 — shared authenticated actions

| Finding | Classification, evidence and prior contract |
| --- | --- |
| Shared server/browser declaration package and authenticated, request-aware server mounting | **Unfinished accepted requirement.** Current `action` checking requires `handles` to resolve to a non-generic function with exactly captures plus body, `emits []`, and no request argument ([checker](../../../../../compiler/internal/check/actions.go#L286)); emitted rows freeze that handler identity ([emitter](../../../../../compiler/internal/emit/actions.go#L30)). Imported action names already resolve by package instance, so cross-package *reference* is present ([fetch resolution](../../../../../compiler/internal/check/action_fetch.go#L191)). The selected [integrated contract](../../../preparation/integrated-action-contract.md#source-declarations-and-boundaries) explicitly calls for a shared contract package and distinct HTML/JSON mounts whose valid handler receives `request` plus captures/wire, allowing server-derived actor and startup-owned services. It is inaccurate to call the whole shared-contract/request-aware-mount idea a newly proposed direction. Exact current syntax differs from the planned packet, which is marked planned rather than shipped. |
| Invoice route divergence and client stubs | **Unfinished accepted requirement, observed in the example.** The server declares GET `/invoices/{invoice_id}` but mounts GET `/invoices/load` with query/cookie handling; JSON save is also an exact manual route while only the form uses `serve_form_action` ([server declarations/routes](../../../../../examples/invoice/src/web/web.can#L5), [router](../../../../../examples/invoice/src/web/web.can#L804)). The grid repeats JSON action declarations with never-served handlers ([grid declarations](../../../../../examples/invoice-grid/src/web/web.can#L5)). The integration origin rewrites the captured GET to the query endpoint, and a direct API test expects 404 ([rewrite](../../../../../tests/integration/gate5_frontend_test.go#L437), [negative](../../../../../tests/integration/gate5_frontend_test.go#L976)). The [integrated qualification boundary](../../../preparation/integrated-action-contract.md#qualification-boundary) already requires one locked contract package, linked edits and no route drift. This is an application/platform integration gap, not proof that path captures, typed fetch, or Can-authored browser execution are absent. |
| Handler-free declaration versus a bound callable with a server-free client projection | **Accepted split remains unfinished; bound-callable projection is a new alternative.** The prior integrated packet explicitly shows handler-free shared declarations and binds request-aware handlers separately at mount. Those architectural requirements belong to unfinished accepted work despite differences between planned and current grammar. The review's bound-callable projection is an alternative to that selected split and needs a new decision; migration mechanics alone do not make the original split a new proposal. |

Current positive foundation: action metadata includes method, path, captures, body schema, result cases and response schema ([emitter](../../../../../compiler/internal/emit/actions.go#L30)); route matching/building implements typed captures and 400/404/405 classification ([route adapter](../../../../../runtime/platform/action-routes.ts#L1)); browser fetch sites resolve imported `package::action` and check GET/POST wire/result shape ([fetch checker](../../../../../compiler/internal/check/action_fetch.go#L191)). The form adapter has a checked mount ([server usage](../../../../../examples/invoice/src/web/web.can#L815)). None of these claims proves an authenticated JSON/captured-route mount has been integrated in the invoice server.

## Section 2 — browser delivery

| Finding | Classification, evidence and prior contract |
| --- | --- |
| A supported, reproducible browser build/bundle path with audited runtime dependencies | **Unfinished accepted requirement.** `build --target browser` genuinely checks the capability closure, verifies assertions under Bun, emits a distinct browser root, and publishes a content-addressed `browser/asset.json` ([driver](../../../../../compiler/internal/driver/browser.go#L46), [entry](../../../../../compiler/internal/emit/browser.go#L73)). The shipped TypeScript is not yet a standalone browser-executable bundle. Gate 5 invokes a test bundler that supplies `node:async_hooks`, `node:util`, `node:fs` and `node:crypto` shims; its own comments limit ALS/proxy/source-map behavior to the grid's path ([bundler](../../../../../tests/integration/browser/build-grid.mjs#L1)). The [browser target packet](../../../preparation/browser-target-design.md#build-and-capability-boundary) selected a compiler-produced same-origin asset and actual browser qualification, and the [product matrix](../../../preparation/product-acceptance-matrix.md#broad-can-authored-frontend-editable-invoice-grid) demands real interaction. A maintained delivery and dependency contract remains unfinished; this does **not** mean there is no Can browser target or no functioning Can-authored grid. |
| Runtime-profile implementation versus maintained shim layer | **New proposal for mechanism.** The review's preference for a browser-specific runtime profile and its alternative fully specified shim layer are implementation choices. The accepted contract is browser-safe semantics, native DOM/Fetch basis, shared wire behavior and supported delivery, not one particular module layout. A grid-only synchronous `AsyncLocalStorage` shim cannot be treated as proven for admitted async ownership or coordination. |
| Empty-app, failure, equality, async, disposal and dependency-closure acceptance probes | **New proposed test expansion serving an accepted requirement.** Existing Gate 5 covers the grid in named browsers; the suggested empty-app and broader runtime behavior matrix is additional qualification evidence. The current artifact audit skips runtime bodies ([audit](../../../../../compiler/internal/browser/browser.go#L608)), so authored-module scanning alone does not establish the whole bundled dependency closure. |

Positive foundation and support boundary: browser capability checking rejects transitive server-only operations including SQL, environment, files, process, crypto, WebSocket server handles, native declarations and server lifecycle operations ([gate](../../../../../compiler/internal/browser/browser.go#L58)); browser emission removes server factories ([emitter](../../../../../compiler/internal/emit/browser.go#L86)). The browser runtime implements DOM nodes, event registration, view disposal/timer cleanup and versioned state ([runtime](../../../../../runtime/platform/browser.ts#L220)). The grid and Gate 5 show an actual Can-authored subset executing with explicit test bundling. Their browser results do not validate every reachable shared runtime operation or a general public bundling path.

## Section 7 — frontend capability and reuse

| Finding | Classification, evidence and prior contract |
| --- | --- |
| Event snapshot is narrow; cancellation and handler failure observation | **Partly unfinished accepted requirement, partly new capability proposal.** The runtime projects only `kind`, target ID, value and key ([snapshot](../../../../../runtime/platform/browser.ts#L244)); listener callback settlement currently consumes both completion and rejection without a reporting channel ([settle](../../../../../runtime/platform/browser.ts#L235)). The [browser design](../../../preparation/browser-target-design.md#explicit-native-browser-catalogue) explicitly called for admitted cancelable-event `preventDefault` and observable handler failures. Those are unfulfilled accepted behavior. Native `checked`, modifier keys, files and composition fields were not selected in the first event snapshot; adding each is a **new proposal** supported by product examples, not a shipped-contract bug. |
| Reload-persistent drafts, history and browser WebSocket | **New proposal or expressly excluded first-scope feature.** The [browser design](../../../preparation/browser-target-design.md#grid-state-and-save-ownership) and [integrated contract](../../../preparation/integrated-action-contract.md#request-operation-and-response-policy) explicitly limit drafts to a living app/view and disclaim reload durability and automatic queueing. The [product matrix](../../../preparation/product-acceptance-matrix.md#broad-can-authored-frontend-editable-invoice-grid) repeats that boundary. Server WebSocket is rejected from the browser catalogue ([gate](../../../../../compiler/internal/browser/browser.go#L58)); there is no browser WebSocket API. Persistence, history and WebSocket client support may be worthwhile but should not be labelled regressions against the accepted first target. |
| Extending the closed catalogue versus a reviewed typed host adapter | **New proposal for mechanism.** The existing browser capability gate has a fixed admitted operation set and rejects server domains ([gate](../../../../../compiler/internal/browser/browser.go#L58)); ordinary Can packages cannot add host operations merely by defining functions. The review's two extension architectures require separate design selection. |
| Reusable typed fields/keyed-row editor and possible component syntax | **New proposal for reuse research.** Named functions and typed nodes already compose UI, while the grid contains substantial manual rendering ([grid](../../../../../examples/invoice-grid/src/web/web.can#L556)). The prior [browser design](../../../preparation/browser-target-design.md#grid-state-and-save-ownership) explicitly selected application-owned state/rendering rather than a virtual DOM or inferred reactive layer. Authoring-cost prototypes may justify a later abstraction; current manual code is not evidence that UI composition is impossible. |

## Independent browser-artifact defect

**Bug.** `AuditArtifacts` uses raw substring checks for `process.`, `Bun.`, `require(` and `node:` in non-runtime TypeScript bytes ([audit](../../../../../compiler/internal/browser/browser.go#L580)). The preserved [probe results](../post-upgrade-review-961f921/browser-audit-results.json) show harmless literal `"Bun."` and `"node: introduction"` rejected after checking/emission, while equivalent `"Bu" + "n."` is accepted. The check therefore treats user text as host access and is trivially spelling-dependent. It should use structured import/operation evidence and audit the actual reachable runtime closure; the latter is also the browser-delivery requirement above. This is a concrete compiler audit defect, distinct from missing frontend APIs.

## Supplement: accepted UI observations versus Gate 5 limits

These are adjacent to the review findings, not additional claims made by that review.

| Observed limit and classification against prior acceptance |
| --- |
| **HTML 503 is served but not displayed in the HTMX target.** The selected [integrated action contract](../../../preparation/integrated-action-contract.md#request-operation-and-response-policy) unambiguously requires visible inner swaps for 200/422/409/403/503 and specifically says a 503 must replace stale feedback. The [product matrix](../../../preparation/product-acceptance-matrix.md#server-driven-saas-flow-tenant-invoice-edit) requires visible unavailable feedback without rewriting the status to 200. Current `runtimeHead` puts every 4xx/5xx except 422 into `noSwap` ([HTML runtime](../../../../../runtime/platform/html.ts#L402)); the [T26 guide](../../../t26-product-guide-2026-09-24.md#22-keyed-row-form-post) accurately describes that shipped policy. **Unfinished accepted requirement / confirmed behavior mismatch**, rather than a new proposal or a defect in the guide's description of current behavior. It limits the server-rendered acceptance claim even if the HTTP response itself is correct. |
| **Event callback failures are consumed.** The selected [browser event contract](../../../preparation/browser-target-design.md#explicit-native-browser-catalogue) explicitly requires observable handler failures. Current `settle` discards both completion and rejection with no reporting channel ([browser runtime](../../../../../runtime/platform/browser.ts#L235)). **Unfinished accepted requirement / confirmed runtime behavior gap.** The review identifies the narrow event snapshot, but does not separately establish this callback-failure mismatch; record it as supplementary source evidence. The exact reporting mechanism remains undecided. |
| **`L-focus-row`, `L-notice`, `L-flight`.** Gate 5 records pre-attachment add/move focus that never lands, a blocked-save notice erased by rerender, and no visible mid-flight saving indicator while the single-flight guard still works ([known divergences](../../../../../tests/integration/gate5_frontend_test.go#L12), [report](../../../../../tests/integration/gate5_frontend_test.go#L863)). The [browser packet](../../../preparation/browser-target-design.md#grid-state-and-save-ownership) already requires focus restoration, live error announcement, and visible save/error state; its acceptance section requires observing focus and announcements. **Observed example/qualification gaps under accepted product behavior.** The packets do not mandate one exact blocked-press message or a literal `saving...` label, so those specific UI spellings are not separately accepted requirements. The review's section 7 mentions focus effort but does not enumerate these three Gate 5 observations. |
| **`L-wire` and `L-unlink`.** Gate 5 preserves a grid-only positional wire rename that still asserts, and a server action rename that still builds while the manually served endpoint responds ([static probes](../../../../../tests/integration/gate5_frontend_test.go#L1019)). The [integrated contract](../../../preparation/integrated-action-contract.md#qualification-boundary) requires shared declarations and linked route/field/leaf changes. **Unfinished accepted linkage requirement**, already covered by section 1 of this audit. `L-wire` alone is not proof of unsafe wire decoding: the test explicitly says a cross-target driver owns protocol agreement; the problem is missing static cross-target propagation in that edit. |
