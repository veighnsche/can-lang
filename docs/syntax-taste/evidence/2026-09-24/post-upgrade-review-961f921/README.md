### Core behavior

`core-probes/` contains exact Can source, generated countdown TypeScript, regex probe TypeScript, and raw outputs. The core report also contains complete generic-composition source, a common main, and the observed public/private acceptance difference, plus the exact local-style and Boolean-order diagnostics.

- Emitted countdown: 100 and 1,000 steps return success; 10,000 returns a standard native stack-overflow failure on Bun 1.4.2. Generated through the current full checker and region emitter, executed directly with the real completion runtime, outside the CLI supervisor. This does not establish a portable numeric stack limit.
- Unicode regex: empty `(?:)` under `u` and `v` over `😀x` gives five matches at offset 0 with a limit of five; native `matchAll` gives offsets 0, 2, 3. Non-Unicode mode yields 0, 1, 2, 3. The direct runtime probe supplies a dummy error-domain object because only successful paths are reached; it isolates scanning semantics, not catalogue wiring.
- Exported generic helper: symbolic argument forwarding to another generic identity rejects; the equivalent private templates check. The temporary Go fixture helpers were removed after their results were recorded in the report.

The saved TS probes can be run with local Bun against the referenced repository runtime. Absolute imports make the artifacts specific to this workspace; copy/adjust those paths when reproducing elsewhere.

### Native lifetime and collection probes

`native-probes/` preserves three scripts and each process's `.stdout`, `.stderr` and `.status`:

- `empty-race.ts`: races native `settle("race", [])` against a 50 ms observation timer; reports `timed out`. It observes pending behavior for a bounded interval; the permanent-pending contract follows the native operation/source, not observation of infinite time.
- `owner-latency.ts`: first-success selection at roughly 2 ms, owner return around 83 ms with an 80 ms loser. The initial independent observation was approximately 5/85 ms. Both demonstrate the same distinction; neither measures an HTTP server directly.
- `immutable-set-scaling.ts`: one local run of 10k/20k/40k additions measured 184/649/2,527 ms. The earlier independent run was approximately 150/617/2,859 ms. These are indicative microprobes without statistical benchmarking. The quadratic deduction comes from full native Set/Map copying on each point update.

No probe calls a production service or live model. Existing route-rewrite and direct-404 integration test expectations were inspected as source; the live browser/database matrix was not rerun. The main report labels this distinction explicitly.

Disagreements prompted source-based followups, not another vote. See `core-reconciliation.md` and `platform-reconciliation.md`:

- Symbolic calls must consume validated parametric callee contracts, not trust signatures while permitting representation-dependent private helpers.
- Stack safety is the desired capability; tail lowering versus explicit iteration remains open. Fixtures and invocation tracing can retain costs even after native stack growth is removed.
- Result data and concrete bounds need a realistic comparison before adopting error-row syntax.
- Browser catalogue expansion versus reviewed adapters requires the same persistent-draft/rich-input example on both sides. No universal FFI is prescribed.
- A supported semantic shim layer can be legitimate; unsupported grid-specific assumptions are the current recommendation boundary.
- Imported actions exist. The missing separation is handler-free contract/client projection plus contextual server binding, not all action imports or mounts.
