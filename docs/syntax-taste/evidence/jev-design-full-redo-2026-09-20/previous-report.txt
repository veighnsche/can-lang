# Jev design consultations and engineering judgments

20 September 2026. Advisory evidence accompanying the [technical specification](technical-spec.md). This record does not override approved source syntax or establish runtime conformance.

## Method and evidence

The updated [AGENTS.md](../../AGENTS.md) asks for differently worded versions of the same Jev question. The user's steering made this required for difficult design decisions. The [TypeSafe skill](../../.agents/skills/typesafe-ai/SKILL.md) was followed: live index, API, Choice, state, confidence, and the closest self-consistency cookbook were read; relevant facts and alternatives were supplied explicitly. Jev performed no research and supplied typed choices, distributions, and confidence, not explanations.

Eight technical tradeoffs were each submitted in three differently worded questions, in three independent API requests. Every request contained the identical structured state and identical candidate descriptions, including a `review_needed` outcome. Only question instructions changed; candidate order also remained fixed. Each question referred explicitly to its relevant topic and the common constraints. No earlier answer was supplied to a later question. The requests asked `jev-latest`; every response identified `jev-1.13.0`. Total reported usage was 13,285 input and 1,302 output tokens. Credentials were supplied only in the request header and are absent from the evidence files.

There were no categorical disagreements in this bounded sample. The distributions still moved: native async mapping ranged from 0.66 to 0.85, and shared fixture FIFO from 0.69 to 0.90. That variation leaves meaningful uncertainty about wording sensitivity or ordinary model variability; this experiment cannot separate the two. The same model, shared facts, fixed option order, and related paraphrases are correlated evidence. Agreement is neither independent replication nor majority-vote proof. No acceptance threshold or automatic voting rule changed the specification. A disagreement would require checking factual parity and the underlying tradeoff, not running questions until a preferred answer wins.

## Engineering judgments and resulting contracts

These reasons are the reviewing agents' judgments, not explanations generated by Jev.

1. **Exact integer JSON: revise A6/A10.** JSON Schema treats mathematically integral numeric values as integers regardless of decimal-point spelling. Rejecting `1.0` while accepting `1` would turn a permitted structured-output representation into a Can failure without protecting additional numeric precision. Native source-token recovery plus a bounded coefficient/decimal-shift adapter preserves the exact value. A6 now defines trailing-zero integrality checks, zero handling, lexical bounds for enormous exponents, and a cumulative canonical-integer byte budget before expansion or BigInt construction. Fractional values and quoted numbers remain rejected. This is an I/O representation contract, not source int/float coercion. Native JSON parsing and BigInt remain authoritative operations. Independent review also closed the encoder side: it counts serialized structure and native primitive lengths, guards oversized bigints before decimal formatting, and allows only bounded temporary escaping allocations before the final native JSON.stringify pass.

2. **Generation shapes: retain A10's initial subset.** The traced generation-to-judgment programs need ordinary nonrecursive records and arrays. The shared codec remains reusable; one explicit provider-admissibility predicate rejects a broader type graph before sending. Adding variants/references now would create schema-emission and diagnostic work without closing a required trace. This is a deliberate scope boundary, not a claim that the provider cannot handle recursion. Broader types remain a future technical capability decision.

3. **Aggregate typing: retain Q6's lazy expected named type.** A fallback that never observes or exports its failures needs only the finite compiler-private participant set. Observation or forwarding requires one unique named expected variant covering that set. This keeps source-visible nominal identity explicit without requiring unused data types or making inference depend on unrelated declarations. The private aggregate cannot escape as a source-visible untyped error value.

4. **Resource deadlines: clarify Q10/P6/P10/P12.** A close timeout can report failure while a live lease prevents cleanup forever. Neither a declared failure nor a recorded unsuccessful status guarantees that the process will actually exit. The language retains owners and does not invalidate leases. Deployments requiring bounded host termination must use an external process supervisor; killing the process supplies no Can cancellation, clean-drain, or remote-rollback guarantee. No hidden runtime hard-stop policy was added.

5. **Sequential map: revise C7/Q11 to native `Array.fromAsync`.** The native operation directly supplies ordered awaited callback execution and first-failure stopping, avoiding an eagerly allocated predecessor-promise graph. The published algorithm and Bun 1.4.2 probes support that specific equivalence. A generated adapter iterates native array indices and returns protected completion boxes; a final synchronous native map extracts payloads. This preserves records with callable `then` fields on both input and output. The choice follows native capability and the contract, not the three selections. Target conformance must check the same behavior before this lowering is accepted.

6. **Fixture queues: retain P3's canonical shared FIFO and state its limit.** The existing row grammar can script successive invocations at one shared helper site without introducing participant syntax. Searching rows by argument would hide some ordering mistakes; replaying an independent queue per participant would change the meaning of one global sequence. The canonical scheduler needs explicit conformance and exercises only its defined schedule. Separate controlled-promise tests must cover relevant native interleavings, including early settlement and losers. The broader probability variation is a reason to retain those limits visibly, not a reason to claim the fixture policy is proven.

7. **Generic checking: retain C4's concrete specialization.** No approved constraint syntax exists. Parametric-only bodies would exclude useful generic operations or force concrete wrappers. Checking every branch of each reachable concrete instance supplies a finite, explicit obligation without treating assertion examples as proof for all types. Declaration-time grammar/name checks, instantiation diagnostics, and rejection of expanding specialization remain required. This consciously accepts some use-site errors in exchange for expressiveness.

8. **Promise payloads: add a universal C4 contract and apply it in Q3/C7.** A callable record field named `then` is legal Can data. JavaScript promise resolution can invoke it, so directly returning that record from generated async code can execute unintended effects or never settle. A Bun probe demonstrated assimilation and then demonstrated preserved identity without additional invocation when a private box was used. Every native promise crossing now protects the payload in a null-prototype box without application-controlled keys or `then`; only synchronous generated code unwraps it. This covers ordinary calls, callback adapters, accumulators, and race winners. It needs no source-name ban or fixed generated record layout.

## Sources and limits

The [TypeSafe API](https://docs.typesafe.ai/api), [Choice guide](https://docs.typesafe.ai/primitives/choice), [state guide](https://docs.typesafe.ai/concepts/state), and [confidence guide](https://docs.typesafe.ai/confidence) define the advisory request/answer model. The [self-consistency cookbook](https://docs.typesafe.ai/cookbooks/consistency_choice_cookbook) supplied a relevant comparison method; its demonstration thresholds were not imported as policy.

The numerical interoperability fact comes from the [JSON Schema numeric-type reference](https://json-schema.org/understanding-json-schema/reference/numeric). Native lowering facts come from the [TC39 Array.fromAsync algorithm](https://tc39.es/proposal-array-from-async/) and [ECMAScript Promise resolution](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise-resolve-functions), supplemented by the recorded probes. Generation-profile breadth is documented by [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

The three live TypeSafe requests were design consultations made directly through its API. They did not run generated Can code, validate a Can adapter, test an application judgment, establish model calibration, or exercise a live database or deployment. The native probes are likewise bounded observations, not the compiler conformance suite. The historical audit and all implementation files remain unchanged. These consultations support a documented engineering decision; they do not certify the specification or eliminate implementation review.
