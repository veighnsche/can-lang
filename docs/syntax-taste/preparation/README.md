# Reading the September 24 preparation records

This directory contains the evidence, alternatives and selected contracts used
before the T01–T27 upgrade. That implementation round now has a completed
[execution record](../can-implementation-task-list-2026-09-24.md).

Start with the [post-upgrade reconciliation](../post-upgrade-reconciliation-2026-09-24.md)
for current implementation status. It distinguishes bugs, unfinished accepted
requirements and new proposals. A preparation document saying “current”,
“planned” or “not implemented” describes its preparation-stage snapshot unless
its post-upgrade status note says otherwise.

- [Selection ledger](design-disposition-ledger.md): earlier accept/retain/defer
  decisions and reopening criteria, not a shipping checklist.
- [Accepted technical decisions](accepted-technical-decisions.md): selected
  contracts, including forms that differ from current compiler syntax.
- [Integrated action contract](integrated-action-contract.md) and
  [browser target design](browser-target-design.md): accepted outcomes with
  remaining integration and runtime-delivery gaps.
- [Product acceptance matrix](product-acceptance-matrix.md): required observable
  behavior, not evidence that every row passed.
- [Readiness audit](readiness-audit.md): pre-implementation consistency check,
  not a current product qualification.
- [Evaluation protocol](evaluation-protocol.md): agent-trial method. Registration
  and mechanical replay do not establish measured live-agent benefit.

Earlier probes, consultation requests/responses and alternatives are preserved.
Their results do not automatically approve new syntax or reopen user choices.
