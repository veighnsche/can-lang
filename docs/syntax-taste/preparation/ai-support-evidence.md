# AI and supporting-capability evidence packet

Snapshot: `02a549d2`, 24 September 2026. This packet supports the [decision inventory](decision-inventory.md) and [recommendation program](../can-recommendation-program-2026-09-24.md). Can's audience is AI coding agents; human readability and familiarity are not goals. The secondary measured outcome is **total tokens per successful AI coding task**, including instructions, generated code, diagnostics and repair attempts. This is evidence for later disposition and implementation planning, not a syntax selection or production change. Existing examples and specifications establish current contracts; the source links below locate the compiler/runtime behavior. The reviews' estimates are hypotheses until benchmarked on agent tasks.

## Native AI: current idiom and remaining trials (DI-17a–c)

Can has separate `llm`, `noul`, `choice`, `score`, and `judge` declarations. The [native AI example](../../../examples/native-ai/src/oracles/oracles.can) shows an LLM producing a typed `triage_plan`, runtime Choice options, Noul and Score questions registered in one judge, and ordinary named functions adapting grouped-state calls. Its [app](../../../examples/native-ai/src/app/main.can) performs LLM generation, option transformation and judgment explicitly. This is an existing two-request composition, not an absent feature. The normative [A7 phase contract](../ai-io-spec.md#a7-judge-execution-phases-and-the-batch-boundary) and [judge emitter](../../../compiler/internal/emit/judge.go#L244) prepare each registration, make one batched request, validate the full answer set, run handlers in registration order and then run the continuation. The [question validator](../../../runtime/ai/questions.ts#L226) checks returned answers. A failed later handler leaves any earlier authored external effect in place; returned record construction alone does not promise transaction rollback. The clean-room review flags this precise limit ([§11](../clean-room-language-review-2026-09-24.md#11-finish-native-ai-composition-through-concrete-workflows)).

Fetch/judge `wrap` has origin-sensitive `handles native` and `handles emitted` policy with a calculated public error bound ([A2.4](../ai-io-spec.md#a24-fetchjudge-normalization), [A3.2](../ai-io-spec.md#a32-operation-wrappers)). The [resolver](../../../compiler/internal/resolve/native.go#L75) admits fetch, judge and wrapper bases, excluding LLMs. The example's `draft_account` manually matches and forwards all LLM errors, while `review_bundle` manually adapts grouped judge state ([source](../../../examples/native-ai/src/oracles/oracles.can#L74)). Their repetition is real, but one example does not establish a material token or correctness cost. Ordinary wrapper code cannot recover differently from an authored error and a decoder error with the same nominal kind without private provenance; that is the potential LLM-wrapper gain. Native AI declarations and grouped state remain part of Can's identity ([decision direction](../decisions.md#design-direction)).

The [callable gate](../../../compiler/internal/check/callables.go#L13) allows functions, fetches and eligible fetch wrappers as ordinary references; a judge wrapper with grouped state and direct judge/LLM declarations do not have an ordinary callable contract. A named function wrapper works. Assess direct grouped-state references only against a real fan-out workflow. The [September 22 dispositions](../../implementation/language-design-dispositions-2026-09-22.md#native-ai-state-and-connections) retain grouped state and defer callable redesign; the [inventory](decision-inventory.md#di-17c--grouped-state-callable-composition) records this as later work.

Benchmark specification: implement one representative agent workflow using the current named wrappers and an alternative policy prototype only if the baseline causes failures. Include (1) a generated record followed by dynamic Choice, (2) native and authored failures of the same nominal kind, (3) two groups of state with one-field and multiple-field forms, (4) fan-out over several judges, and (5) a second batch handler that fails after the first writes to a controlled ledger. Verify request count, disclosed state fields, response validation before handlers, effect ordering, error bounds/provenance and no implicit replay. Record complete agent-task tokens, compile/repair cycles and semantic mistakes; source length alone is insufficient. Compare explicit transaction/outbox code before any batch semantics change. No evidence currently selects an LLM wrapper extension, bound grouped-state callable, merged native declaration or general effect system.

## Closed catalogue and SDK integration (DI-19)

Can source cannot embed JavaScript/TypeScript or import arbitrary Bun APIs. Only the maintained distribution extends the platform catalogue, and approved operations lower to native JavaScript/Bun facilities with adapters for Can contracts ([boundary and native delegation](../decisions.md#reuse-native-operations-do-not-reimplement-them)). Typed fetch, crypto and process operations exist; the [SaaS review](../saas-language-review-2026-09-24.md#7-i-would-recommend-can-if-common-saas-operations-fit-the-supported-platform-boundary) did not show a required payment/email/queue SDK that could not be integrated. The [clean-room review](../clean-room-language-review-2026-09-24.md#12-give-immutable-collections-efficient-construction-paths) likewise states an awkward integration must be reproduced before revisiting the boundary. [LD32–LD34](../../implementation/language-design-dispositions-2026-09-22.md#assertions-resources-and-platform-contracts) retain the closed catalogue/admission process and defer third-party manifests.

Benchmark specification: pick one concrete provider API needed by the invoice/webhook product slice. Build its smallest useful operation using current typed HTTP and exact codecs, including authentication, idempotency, pagination or webhook verification where relevant. Exercise deterministic raw fixtures, timeouts, malformed payloads, redacted diagnostics, immutable response values and lifetime/ownership. Measure agent success, tokens, integration code and provider-change repairs. If a named SDK feature is materially unavailable or impractical, compare a distribution catalogue addition with a narrow typed binding manifest covering codecs, errors, fixtures and native ownership. A generic permission to import npm is not the baseline candidate. The outcome is an integration contract decision, not a new payment/email/queue keyword.

## Bulk immutable collections (DI-20)

`collections::map` and `collections::set` are opaque immutable values backed by native `Map`/`Set` ([map implementation](../../../runtime/collections/map.ts#L20), [set implementation](../../../runtime/collections/set.ts#L21)); `insert`, `replace` and `remove` clone the map before publication ([map operations](../../../runtime/collections/map.ts#L47)). The gallery's [word-frequency fold](../../../examples/gallery/src/24-map-word-frequencies.can#L6) calls these per word. With *n* distinct insertions, cloning copies roughly `0 + 1 + ... + (n−1)` entries, a quadratic source-level deduction. It is not a measured throughput figure. The [C7 collection contract](../technical-spec.md#c7-collection-and-text-catalogue) requires immutable user values and native operations.

Benchmark specification: generate workloads with duplicate-heavy and mostly-unique keys at realistic sizes, and include first/last duplicate semantics, ordered callbacks, callback domain failures and one final immutable publication. Measure execution time, allocation, agent task tokens and error diagnostics against the current fold. Compare a native bulk grouping/aggregation adapter first; an internal scoped builder is a possible implementation if native bulk cannot preserve the chosen contract. Do not select general mutable aliases or a custom persistent collection merely from the complexity deduction. This trial depends on the real data volumes in Gate 3/4 flows and is therefore later, as [the program](../can-recommendation-program-2026-09-24.md#consolidated-crosswalk) records.

## Billing and calendar: library versus language (DI-21)

The catalogue already exposes `number::round_ratio_half_even` and `time::resolve_zoned_time` ([rounding contract](../../../runtime/catalogue.ts#L4961), [zoned resolution contract](../../../runtime/catalogue.ts#L10633)); exact `int` can represent minor currency units. The [SaaS review](../saas-language-review-2026-09-24.md#7-i-would-recommend-can-if-common-saas-operations-fit-the-supported-platform-boundary) asks for a maintained monthly renewal/refund example, not more core syntax. A library test should cover short months, leap years, explicit DST gap/overlap policy, currencies with different minor units, taxes, partial refunds and duplicate provider events. Keep policy choices explicit in domain code and verify exact minor-unit results. A missing arithmetic/time primitive would justify a catalogue-level finding; a tax or proration policy does not justify a language keyword. This scenario can supply the concrete provider for DI-19 and controlled transactions for the Gate 3 invoice/webhook trial.

## Authoring surface retained for agent measurement (DI-23a/b)

Calls, constructors and assertion rows currently occupy one physical line; the parser's [argument-list rule](../../../compiler/internal/syntax/expressions.go#L204) and [formatter](../../../compiler/internal/syntax/format.go#L24) reflect that surface. The SaaS review counted 154 example lines over 120 characters, maximum 336, and none in the small gallery ([§8](../saas-language-review-2026-09-24.md#8-i-would-recommend-can-more-readily-if-everyday-edits-were-less-fragile)). Those are presentation counts, not agent success or token results. `canlc parse --render` and a minimal LSP are available ([launcher README](../../../compiler/README.md#L9)); the current parser/formatter exists, while [LD44–LD46](../../implementation/language-design-dispositions-2026-09-22.md#syntax-documentation-and-authoring-feedback) call for precise diagnostics and canonical comment-preserving formatting and defer multiline forms. The checker also rejects narrowly defined immediately forwarded locals ([local checker](../../../compiler/internal/check/locals.go#L41)); this is a validity rule on otherwise meaningful naming, not an established agent failure.

Benchmark specification: after formatter and diagnostic improvements, give agents contract-heavy files containing long calls, constructors, assertions and a meaningful intermediate local. Assign both creation and controlled edit tasks. Compare present layout with a concrete continuation-inside-delimiters prototype only if parsing/repair remains costly, and compare the local rejection with advisory feedback. Record valid first-pass builds, wrong argument/order bindings, diagnostic repair turns, preserved assertion behavior and full task tokens. Visual width or shorter source alone cannot decide. No multiline grammar or local-rule replacement is selected here.

## Dependencies and evidence boundary

The AI trials rely on stable nominal/error identity and package composition (DI-02/03/05), fixture selection (DI-06), and provider raw fixtures. The product flow links DI-19/21 to routes/forms, SQL mutation results, ownership and shutdown (DI-09/10/13/14/15/18); bulk collection results depend on observed batch sizes. Agent-first evaluation must use a successful task as denominator and count all instructions, generated source, compiler output and retries. Correctness, safety and explicit contracts remain hard constraints, so a lower token count cannot excuse hidden state disclosure or lost errors. The current examples, reviews and code provide mechanisms and failure hypotheses; they do not prove production model quality, SDK blockage, throughput, or better agent outcomes. The final task list should keep each later item conditional on its stated benchmark and record an accept/retain/reject/defer disposition.
