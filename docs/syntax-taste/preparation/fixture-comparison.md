The original ambient case reproduces the [historical renamed-root observation](packages-assertions-evidence.md#attached-assertions-lexical-fixtures-and-cross-package-ownership) on current HEAD. The template case demonstrates why content reuse alone does not repair the selector link. In both cases, replacing the helper's foreign `customer` selector with `renamed` repairs the caller assertion. That repair changes **two authored files relative to the original**: `src/app/main.can` and `src/helper/main.can`. It checks and runs without a diagnostic, so the compiler does not point to the stale cross-package selector when the label changes.

The stub and injection cases solve different scopes. The stub keeps the caller's expected completion stable with a local row, but supplies the whole helper result. A control changed the helper body to return `"unexpected"`; the caller still passed with `real-can` and `supplied-completion`. Injection keeps helper-body integration, at the cost of an API parameter and an authored caller function. Changing only the supplied converter to return `"wrong"`, or only the helper's suffix to `"x"`, made the caller fail with `outcome mismatch` and `real-can` evidence. Thus both pieces participate in the passing caller path. This callable is a real Can test double, not a fixture row, raw-provider fixture, or live-provider observation.

## Technical linkage implication

Ordinary injection already provides explicit, label-independent linkage when the helper's public API can expose the desired dependency as a typed callable. It also gives the caller a helper-body integration path without new fixture syntax. The trial changed the helper API to accept that callable; it does not show that every existing helper or native effect can be made injectable at an acceptable contract cost. A whole-helper stub is the stronger current idiom when such API exposure is unavailable and caller integration of the helper body is not required. Lexical templates reduce duplicated rows but retain ambient cross-package selector coupling if the helper writes a foreign root label.

This pilot does not implement F1's proposed same-owner lexical restriction, F2 exported scenarios, or F3 exported seams. It cannot rank their API/refactor burden against injection, nor establish behavior for nested links, two helper occurrences, recursion, concurrent participants, duplicate display labels, or disappearing links. It also does not measure complete successful-agent-task tokens. Before a syntax choice, a linkage trial should compare the injectable API with a helper whose internal target is unsuitable for ordinary injection, then exercise those queue and missing-link cases under the same evidence labels. The [evaluation protocol](evaluation-protocol.md#comparison-method) requires separate agent creation, refactor, and repair trials for any claimed agent benefit.
