# External browser capability contract (source review)

Status: **proposed API and qualification conditions, not implemented behavior**. Every `test_browser::` operation below is a proposed Can-visible binding to a generic native browser driver. The driver may use Playwright internally, but it accepts typed actions and returns bounded facts; it does not contain a named test sequence, expected text/status, check count, or verdict. Ordinary Can functions choose engines, pages, actions, fault schedules, expectations, exception allowlists and report entries. This follows the selected controller/worker/resource separation in [the architecture](../../native-can-test-architecture-2026-09-30.md#L70) and the [migration ledger's browser boundary](../../native-can-tests-migration-ledger-2026-09-30.md#L55).

## Ownership and minimal operations

| Proposed native operation | Returned fact / contract |
| --- | --- |
| `test_browser::open(engine, profile) -> browser` | Engine (`chromium`, `webkit`, `firefox`), version, user agent, local-launch versus remote-connection identity, capability flags (including `JSON.rawJSON`), and owner token. Unsupported engine/profile is explicit, never a silent skip. Browser installation and remote endpoint are qualified inputs. |
| `test_browser::new_context(browser, policy) -> context` and `new_page(context) -> page` | Fresh isolated cookie/storage/cache context for each leg; context/page handles belong to the case's native resource owner. Policy contains an allowed-origin set and resource bounds. Register ownership before exposing the handle to Can. |
| `test_browser::close(page|context|browser)` | Completion/cleanup fact or named failure. Closing a context closes its pages and routes. A case must not be able to close the shared remote Firefox `launchServer`; release only its connection/context. The outer native owner closes these after worker death. |
| `test_browser::navigate(page, url, wait_stage)`, `reload(page)`, `current_url(page)` | Final URL, navigation response status/headers, redirects and load stage; a missing response is distinct from status zero. All navigations pass the pre-contact boundary. |
| `test_browser::cookie_set(context, cookie)` / `cookie_clear(context)` and `set_offline(context, bool)` | Applied state or operation failure, scoped to the context. This supports session denial and offline/replay legs without a browser-script hook. |
| `test_browser::capture(page, locator)` and `capture_all(page, locator)` | Immutable, bounded DOM records: count, ordered text, HTML/outer markup where requested, attributes (including absent versus empty), properties (`value`, `checked`, `disabled`, `selected`), selected option values, file `{name,size,type}` records, focus identity, selection start/end/direction, connected state, tag/role, and node/ID counts. A returned snapshot is an independent browser DOM read, not an application Can adapter read. Stable captured node handles may be used to test detached-node behavior. |
| `test_browser::action(page, typed_action)` | Generic locator or captured-node actions: physical click/keyboard press/type/fill/check/select/file upload/focus, and explicitly synthetic DOM mutations (`set_live_value`, `set_attribute`, `set_checked`, `set_selected`, `set_selection_range`, `reset_form`, `dispatch_input`, `dispatch_keyboard`, detach/reattach/click captured node). Return whether dispatched plus a structured native exception name, with physical versus synthetic recorded. No hidden fallback from one mode to the other. |
| `test_browser::observe(page, query)` | A typed, read-only primitive query for cases currently using `evaluate`: DOM selector projection, duplicate IDs, active element, simple global presence/type or JSON snapshot, custom-event detail, and browser feature flag. No arbitrary JavaScript source/callback or general page evaluation. Named JSON globals and event details are bounded and copied, not live objects. |
| `test_browser::load_artifact(page, owned_script)` | Load an already verified browser bundle into a blank page and return load/console/page-fault facts; this supports wire-vector bundles without accepting authored JS source. A typed global JSON read can retrieve its exported vector result. |
| `test_browser::screenshot(page, owned_output)` | Owned artifact path, byte length and digest; nonempty bytes and expected dimensions are Can assertions. No persistent screenshot directory by default. |

The primitive DOM surface must remain deliberately typed yet cover the actual native-control baseline: checkbox IDL `checked` differs from `value`; a dirty input's live `value` differs from its `value` attribute; reset, single/multi-select, file metadata, modifier/composition flags and caret accessors have engine-specific facts ([controls-native.mjs](../../../../tests/integration/browser/controls-native.mjs#L1), [controls.mjs](../../../../tests/integration/browser/controls.mjs#L20)). `capture` should preserve absent/null versus empty string and native exception names, rather than normalizing to a Can-side convenience value. For custom event observation, the binding installs only a generic listener for the named event and returns frozen/copyable details; Can checks occurrence identity, phase, reason and effect. This replaces the old `window.__occurrences` collector without moving its oracle into the driver ([invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L77)).

## Network control and independent facts

| Proposed native operation | Returned fact / contract |
| --- | --- |
| `test_browser::watch(context|page, options) -> cursor` | Register before navigation/action. Ordered request-start, response, request-failure, redirect, console-error and page-error events carry monotonic sequence, page/context ID, method, URL, status, request and response headers, raw bounded body bytes, truncation flag and transport failure. Capture bodies **as immutable bytes at the event boundary**; parsed JSON is a separate ordinary Can helper. Sensitive headers/bodies require bounded redaction in retained evidence without erasing comparison facts. |
| `test_browser::route(context, match) -> route_rule` | Match only method, exact origin/path or bounded URL pattern, resource type and occurrence count; no authored native callback. Native interception returns a pending token plus immutable request snapshot to the Can worker. Unmatched requests mechanically continue or are denied by the network policy. |
| `test_browser::resolve(pending, decision)` | One of continue, abort with named reason, fulfill with exact status/headers/body, or fetch upstream and replace specified response bytes/headers. A held token can be released later by Can; its deadline and pending-count bound are native enforced. Return upstream response facts separately from delivered response facts, preserving an after-commit corruption witness. |
| `test_browser::unroute(rule)` and `test_browser::seal(cursor, barrier)` | Remove a rule and report unresolved tokens. Seal waits for a Can-chosen causal barrier (for example, received response plus DOM state, navigation, or a bounded quiet interval), drains browser events through context close, and returns a terminal high-watermark, completeness/overflow/late-event status and all facts since the cursor. A timeout, dropped event, unresolved route or driver death is incomplete evidence, never an empty clean ledger. |

This suffices for delayed saves, mid-flight edits, fake 200/302/403/409/422/503 outcomes, control/OOB/partial headers, truncation or garbage **after an actual upstream commit**, and the missing-target-before/during-response race ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L382), [grid.mjs](../../../../tests/integration/browser/grid.mjs#L555), [invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L320), [invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L370)). The driver records both outbound request bytes and delivered response bytes; Can compares exact occurrence counts, operation IDs, headers, statuses, DOM effects and independent database rows. A route that blocks a request must expose whether upstream was contacted. The observed WebKit same-origin 302 interception limitation is a capability result and explicit coverage limit, not a synthetic passing redirect leg ([invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L414), [ledger BROWSER-017](../native-can-tests-migration-ledger-2026-09-30/browser.md#L423)).

The current scripts install a Playwright route that aborts non-loopback HTTP requests and inspect a request ledger ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L47), [controls-native.mjs](../../../../tests/integration/browser/controls-native.mjs#L40)). That is useful behavior evidence but does not alone prove **pre-contact** isolation for redirects, preconnect, service workers, WebSockets or a remote Firefox process. The proposed context policy must be enforced and qualified at a boundary that covers all browser egress, including the remote host/forwarder, **before** navigation. If that guarantee is not implemented, reports may claim only observed/intercepted request behavior, never “no external contact.” Denied attempts, including URL and reason, must be retained as facts. Can decides whether any is acceptable; the native layer enforces the allowed-origin envelope regardless of a killed Can worker. Do not call the existing isolated Bun launch environment an OS network sandbox ([architecture limits](../../native-can-test-architecture-2026-09-30.md#L302)).

## Coverage consequences beyond dirty reset

The API must support the full named obligations, not merely one control leg:

- HTMX forms/assets/accounts/dashboard: script/link inventories and integrity/CSP attributes, physical form actions, swaps, escaping, polling, response headers, browser errors and screenshot evidence ([ledger BROWSER-035/036](../native-can-tests-migration-ledger-2026-09-30/browser.md#L897), [forms.mjs](../../../../tests/integration/browser/forms.mjs#L45)).
- Three-engine controls and Can-emitted controls: independent static-page control facts, paired-script identity, all live control echoes, synthetic composition/autofill, dirty reset and engine-specific caret direction; return version/UA and limitations per engine ([ledger BROWSER-011/012](../native-can-tests-migration-ledger-2026-09-30/browser.md#L265), [controls.mjs](../../../../tests/integration/browser/controls.mjs#L240)).
- Generated browser runtime: query/equality/codec vectors, timers/disposal, cancel/focus, empty app, bundle source-map/diagnostic-table HTTP responses and `JSON.rawJSON` feature observation. A built artifact may be loaded, but its test vector values and parity policy stay Can-authored ([ledger BROWSER-010](../native-can-tests-migration-ledger-2026-09-30/browser.md#L238), [ledger BROWSER-039/040](../native-can-tests-migration-ledger-2026-09-30/browser.md#L1006), [conformance.mjs](../../../../tests/integration/browser/conformance.mjs#L85), [codec-parity.mjs](../../../../tests/integration/browser/codec-parity.mjs#L1)).
- Compare/grid/invoice/drift: real keystrokes and focus/caret, row order/node bounds, request bodies and replay IDs, hold/release and response corruption, detached/remounted nodes, navigation/reload, rollout/rollback against a restarted server, and late page faults after disposal ([ledger BROWSER-041](../native-can-tests-migration-ledger-2026-09-30/browser.md#L1060), [ledger BROWSER-046](../native-can-tests-migration-ledger-2026-09-30/browser.md#L1199), [ledger BROWSER-050/052](../native-can-tests-migration-ledger-2026-09-30/browser.md#L1309), [grid.mjs](../../../../tests/integration/browser/grid.mjs#L665), [drift.mjs](../../../../tests/integration/browser/drift.mjs#L90)).
- Staging/build/HTTP/SQL/manifest and contract-edit cases in BROWSER-001–034 and BROWSER-055–056 also require the separate generic compiler, process, filesystem, HTTP and DB capabilities. Browser DOM facts cannot substitute for their independent server/row observations or compiler rejections ([browser ledger](../native-can-tests-migration-ledger-2026-09-30/browser.md#L9)).

Driver timeouts bound each action, pending route, event stream, context and cleanup even if Can stops. Can owns readiness predicates, polling cadence within that envelope, causal barriers, assertions and engine/leg selection. Prefer `capture` plus Can polling to `waitForFunction` callback injection; waiting for a matching request should use immutable event cursors and Can predicates. A required page error can be observed; an unexpected page/console error is a Can failure only after sealing. Reports need both Can's per-leg checks and the outer cleanup/completeness receipt ([architecture evidence boundary](../../native-can-test-architecture-2026-09-30.md#L265)).

The main tradeoff is a somewhat larger typed DOM/event/action catalogue versus a compact `evaluate(JS)` escape. The typed surface is auditable and keeps scenario code in Can, but its adequacy must be demonstrated against every ledger row before retiring scripts. A second tradeoff is stricter network enforcement: it may require an OS/container or remote-browser boundary beyond Playwright routing; until proven, the design must report the narrower observed-request claim. The current scripts' report JSON and screenshots are evidence formats, not the future oracle: Can must reconstruct their named checks from raw facts and fail on missing or incomplete evidence.
