# Coverage-preservation review after preparatory checks

Scope: completion contract, migration ledger and its browser rows, authoring design, capability/lifecycle and hard-case contracts, preparatory results and canonical execution summary. This is a design review; no tests, builds or browser actions were run.

## Findings

1. **P1 — Browser host effects need an admission and retirement gate.** The [completion contract](../../native-can-tests-completion-contract-2026-09-30.md#L223) requires bounded ownership/cleanup, and the [ledger's common deletion gate](../../native-can-tests-migration-ledger-2026-09-30.md#L126) requires passing environments and resource receipts. The [authoring browser example](../../native-can-test-authoring-2026-09-30.md#L559) and [BROWSER-044 deletion condition](../native-can-tests-migration-ledger-2026-09-30/browser.md#L1160) cover contexts, processes and event seals, but do not require proof that a local browser launch cannot open a host credential dialog. [PM-B1 is canonically failed](../native-can-test-preparatory-checks-2026-09-30/execution-summary.json#L37) because an unexpected macOS Keychain prompt occurred despite complete recorded process/scratch cleanup; the direct launch omitted Playwright's test-only credential switches, with attribution plausible but not proved. **Resolution:** add a named browser-launch isolation prerequisite to the shared `BROWSER` capability and every local-browser retirement gate: explicit noninteractive test-only credential/profile configuration, no personal profile/Keychain use, an observable absence-of-host-UI qualification on the admitted host, and a failed/blocked result if that guarantee is unavailable. Retain PM-B1's failure in the evidence chain; do not treat its repaired route protocol pass as browser qualification.

2. **P2 — A fulfilled input after route abort must not imply delivered response or successful application behavior.** The [browser capability table](../../native-can-test-capabilities-2026-09-30.md#L128) distinguishes input start/settlement and route resolution, while the [authoring browser example](../../native-can-test-authoring-2026-09-30.md#L500) uses a simple sequential click. [PM-B1's initial control](../../native-can-test-preparatory-results-2026-09-30.md#L18) showed the actual click promise fulfilled after abort; its repaired control accepted either terminal click outcome and checked ordered cleanup. The ledger's intercepted invoice scenario [BROWSER-052](../native-can-tests-migration-ledger-2026-09-30/browser.md#L1372) names response injection and draft/commit effects but has only a generic retirement condition. **Resolution:** specify independent terminal facts for physical-input settlement, route resolution/delivery, page response/application effect and final callback seal. For each held-route replacement, require Can checks of the applicable facts and a negative control where abort produces a fulfilled click but no successful delivery/effect. During cleanup require `closing < route_aborted < input_settled < closed` (or a documented equivalent causal proof), with no pending route or unsealed callbacks. A click's fulfilled promise alone must never discharge a response or persistence obligation.

3. **P2 — The row-level evidence map should preserve the preparatory scope distinctions explicitly.** The [ledger introduction](../../native-can-tests-migration-ledger-2026-09-30.md#L9) promises row-specific evidence before deletion, while its [common gate](../../native-can-tests-migration-ledger-2026-09-30.md#L128) allows consolidated cases if all facets are mapped. The [summary](../native-can-test-preparatory-checks-2026-09-30/execution-summary.json#L12) supports only preparatory mechanics for PM-N1, PM-N2 and PM-F1; PM-N2 directly called a source-module `encodeJSON` export, not generated Can ingress, and PM-F1 used Python/POSIX-to-Bun rather than the product launcher. The authoring design [already says](../../native-can-test-authoring-2026-09-30.md#L643) that a separate compiled Can codec program is necessary. **Resolution:** add an evidence-scope column or linked acceptance matrix for affected `NATIVE`/`ENV`/`BROWSER` rows: distinguish transport/raw-source facts from C-compiled adapter invocation, descriptor mechanics from actual launcher behavior, and route protocol from admitted browser host isolation. Only integrated Can runs with the named candidate, independent observer and full cleanup receipt may satisfy row retirement. This is a bookkeeping design gap, not a claim that those integrated qualifications have failed.

## Correctly pending, not design failures

- The contract's [unchecked final gates](../../native-can-tests-completion-contract-2026-09-30.md#L260), ledger's [pending status](../../native-can-tests-migration-ledger-2026-09-30.md#L1), and [hard-case N2/F1/B1 acceptance criteria](../native-can-test-hard-cases-2026-09-30/experiments.md#L28) already prevent promotion of R/N, C-adapter coverage, product fd-3 launcher coverage or old-harness deletion from the preparatory checks. No separate finding is warranted merely because those features remain unimplemented.
- The preparatory [results](../../native-can-test-preparatory-results-2026-09-30.md#L28) report sampled peaks and cleanup receipts without asserting strict memory/descendant containment. That is appropriately narrower than the contract's future enforcement requirement.
