# Browser hard-case source challenge

Status: **read-only design challenge**. “Source-established” below describes current source behavior, not proof that proposed APIs work. “Design-plausible” describes a Can-authored sequence using the proposed native operations in [the capability contract](../../native-can-test-capabilities-2026-09-30.md#L110). “Unknown” is a bounded feasibility question; no experiment was run. The Can worker remains the owner of sequence, expectations and reporting; the native driver performs only typed browser effects/observations. Generated browser code is the subject, never imported into the trusted Can controller realm ([architecture](../../native-can-test-architecture-2026-09-30.md#L88)).

## 1. Hold an invoice POST, mutate the grid, then release exactly once

**Source-established.** The grid script installs a POST route, delays it, arms `waitForRequest`, clicks save, observes `saving...`, changes quantity while the request is held, then requires the new quantity and one grid after the response fold. It finally unroutes ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L378), [grid.mjs](../../../../tests/integration/browser/grid.mjs#L388)). The separate “midflight-press” leg uses a throwaway page, synthetic 200 body and a second click while the first request is pending; it requires exactly one POST and one rendered tree ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L423)). The production browser adapter uses explicit view ownership, event snapshots and async callback settlement; view disposal aborts listeners/timers ([browser.ts](../../../../runtime/platform/browser.ts#L418), [browser.ts](../../../../runtime/platform/browser.ts#L815)).

**Design-plausible trace.** Can opens a page/context, arms request/page-error watches and a method/path route, records a cursor, performs the first physical click, reads the pending token plus immutable request body, captures `#status`, applies a typed live-value + synthetic `input` operation, captures the draft, then resolves the route by continue or exact Can-chosen 200 bytes. It waits by Can predicate over fresh DOM/event facts, checks one POST, unchanged mid-flight draft, response status and one `#grid`, then unroutes and terminally seals. The synthetic body is test data chosen by Can, not embedded driver logic. A case cancellation aborts the pending route and reports whether upstream was ever contacted; a worker death leaves N with token ownership and cleanup authority ([capabilities](../../native-can-test-capabilities-2026-09-30.md#L128), [lifecycle](../../native-can-test-lifecycle-2026-09-30.md#L167)).

**Unknown / missing semantic contract.** The Can worker must receive and resolve a pending route even if `browser.input(click)` has not returned. A driver lock or Playwright click that waits for the intercepted request can deadlock a sequential RPC. Specify `input_begin`/`input_settle` or demonstrate that an input acknowledgment occurs after dispatch but before waiting for route completion, with route/event calls independently serviced. Also, `grid.mjs` dispatches **two DOM clicks synchronously in one page task** for single-flight ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L483)). Two separate Can→driver RPC calls can run a microtask/network turn between them and weaken that check. A small generic `browser.dom_batch` of fixed typed actions, executed synchronously in one page task with no callback/branch/wait, may be needed. Can chooses the list; N returns per-action dispatch facts. Neither a scenario-specific “double-save” helper nor a native verdict is acceptable.

## 2. Commit upstream, corrupt only the browser response, then replay the same operation

**Source-established.** A route calls `route.fetch()` so the real server commits, checks upstream status 200, reads the response text, then fulfills the browser with truncated or malformed JSON. The page reports “save may have committed,” enables replay, and the script checks the replay request reused the identical `operation_id` ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L555), [grid.mjs](../../../../tests/integration/browser/grid.mjs#L576)). Production action fetch uses the browser's `fetch` with same-origin credentials and the page's generation slot; its bounded body decoder distinguishes transport, timeout and codec outcomes ([action-json.ts](../../../../runtime/platform/action-json.ts#L471), [action-json.ts](../../../../runtime/platform/action-json.ts#L500)).

**Design-plausible trace.** Can arms request/response capture, installs an exact POST route, edits a field, clicks save, receives the paused request and frozen original bytes, calls `route_fetch` **once**, requires a complete upstream 200/body fact, and separately queries the owned SQLite observer for the committed revision/replay row. Can derives either first-ten-character or malformed replacement bytes and calls `route_resolve(fulfill-bytes)`; it checks DOM uncertainty/replay enablement, removes the route, clicks replay, compares the two captured raw request bodies/parsed operation IDs, checks one durable effect, and seals the browser interval. The upstream and delivered response identities must remain distinct. A failed/indeterminate fetch or body overflow cannot be turned into a synthetic passing response ([capabilities](../../native-can-test-capabilities-2026-09-30.md#L129), [capabilities](../../native-can-test-capabilities-2026-09-30.md#L139)).

**Unknown.** Whether the proposed driver can hold one Playwright route across an out-of-process Can decision, complete a `route.fetch()` exactly once, and fulfill altered bytes without an accidental second upstream request is unproved. Distinguish browser request body bytes, driver-decoded response body and true wire bytes; the script uses `request.postData()` and `response.text()`, not packet capture ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L82)). On cancellation after upstream contact, N must retain an indeterminate commit and abort delivery safely; it cannot blindly retry `route_fetch` under a new operation ID. The existing contract states this but needs a source-level feasibility result.

## 3. Remove a swap target while a response is in flight; remount a clone

**Source-established.** Two invoice legs must stay distinct. First, the script clones `#invoice_status` and removes the original **before submit**; it permits upstream HTMX to send no request, or requires a request-phase `action::missing_target` with `effect=none` if a request is sent. It preserves the page/draft and remounts the saved clone. Later, with a target initially present, a POST is held 1.5 seconds; the script removes the target **after request observation**, obtains server status 200, remounts the earlier clone and requires one response-phase occurrence with `kind=action::missing_target`, `effect=uncertain`, and an absent/detached reason. Draft and page-error checks remain ([invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L254), [invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L314)). The shipped HTMX guard emits a frozen occurrence through a bubbling CustomEvent and retains per-request target identity in a `WeakMap` ([htmx-guard.ts](../../../../runtime/platform/htmx-guard.ts#L455), [htmx-guard.ts](../../../../runtime/platform/htmx-guard.ts#L496)). Separate legs inject HX control headers, out-of-band/partial fragments and 302; the old script explicitly records a WebKit redirect interception limitation rather than claiming that leg passed ([invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L394), [invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L425)).

**Design-plausible trace.** Can arms `watch_dom_event(document, "can:action-occurrence")` and network/page-error watches, captures target subtree/node count and clone handle, installs a POST hold, fills/clicks, waits for the pending token, removes the live target, continues once, observes upstream response and occurrence, then appends the clone and checks node/ID counts, draft, response and occurrence fields. Can selects the alternate response headers/bodies for other legs. A route deadline or worker death aborts/records the token; a missing occurrence is missing evidence, not a clean empty array.

**Missing primitive / realm risk.** `browser.dom_action` lists detach/reattach, but **clone-and-append is semantically different from reattaching the original**: the current script deliberately stores a clone before removal and uses it for later legs ([invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L256), [invoice.mjs](../../../../tests/integration/browser/invoice.mjs#L290)). Add generic `clone_subtree(node) -> owned node handle` and `append(parent, child)` with document-generation/ownership checks, not a bespoke invoice repair. The `watch_dom_event` listener must be in the page's event realm and project frozen detail as data without executing a case callback or triggering getters beyond its declared representation. The phase distinction depends on installing before the request and not losing the occurrence when the target is detached. The current guard emits on `document`, which makes a page-level generic listener plausible ([htmx-guard.ts](../../../../runtime/platform/htmx-guard.ts#L468)).

## 4. Native controls, real keys, synthetic composition and synchronous cancellation

**Source-established.** The native-control script independently reads checkbox IDL versus `value`, dirty input property versus attribute, reset/select/file metadata, and installs its own listeners to record real `Shift+Enter`, synthetic Ctrl+X, simulated autofill and composing input ([controls-native.mjs](../../../../tests/integration/browser/controls-native.mjs#L60), [controls-native.mjs](../../../../tests/integration/browser/controls-native.mjs#L149)). The emitted-Can script checks the app's echoes and browser DOM independently, including engine-specific collapsed caret direction, synthetic composition and dirty reset ([controls.mjs](../../../../tests/integration/browser/controls.mjs#L30), [controls.mjs](../../../../tests/integration/browser/controls.mjs#L231)). The grid additionally installs a keydown listener **after** the app's handler and asserts `defaultPrevented=true` after a physical Enter ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L306)). Production `onCancelKey` calls `preventDefault()` synchronously before invoking its Can handler, and uses view-scoped abort signal cleanup; `setSelection` catches native throws and maps them to a Can denial ([browser.ts](../../../../runtime/platform/browser.ts#L848), [browser.ts](../../../../runtime/platform/browser.ts#L697)).

**Design-plausible trace.** Can creates a fresh context/page for each named leg, subscribes to native DOM event snapshots on a selected element **after boot when listener ordering matters**, applies physical keyboard/click or explicitly synthetic property writes and input/keyboard events, then compares browser-observed event fields, native properties/attributes and emitted Can echo text. It includes the `InvalidStateError` native baseline and the Can `rejected` projection as distinct expected facts. File upload takes bounded literal bytes from an owned fixture, not arbitrary filesystem paths. Can selects engine-specific caret expectations and preserves raw direction. Close/seal checks network/page/console facts and owns screenshots.

**Missing primitive.** The proposed `watch_dom_event` projection includes `cancelable` but omits `defaultPrevented`; the Enter check needs that field *as observed in the same listener phase/order* ([capabilities](../../native-can-test-capabilities-2026-09-30.md#L127), [grid.mjs](../../../../tests/integration/browser/grid.mjs#L310)). Add it with listener registration acknowledgment and target/document generation. The driver must not install all event watchers before app boot if doing so changes ordering, nor claim a browser event snapshot is independent if it merely reads the app's Can echo. Also verify synthetic event constructor/`isTrusted`/bubbling and DOM property-write semantics across the three engines; treating a `fill` as equivalent to `node.value = ...; dispatchEvent(input)` would silently change the obligation.

## 5. Same-generation competing write and codec vectors without an authored JS oracle

**Source-established.** The grid conflict leg reads `script[data-can-generation]`, performs a competing POST **inside the page realm** with that header, cookie-bearing same-origin `fetch`, then makes a stale grid save and checks keep/adopt behavior ([grid.mjs](../../../../tests/integration/browser/grid.mjs#L606)). Separately, `codec-parity.mjs` starts a browser on `about:blank`, checks `JSON.rawJSON`, injects a bundled TypeScript vector entry and reads `globalThis.__canWireResults` ([codec-parity.mjs](../../../../tests/integration/browser/codec-parity.mjs#L15), [codec-vectors-entry.ts](../../../../tests/integration/browser/codec-vectors-entry.ts#L1)). The vector module itself executes and judges 12 named cases in TypeScript, including bigint, `-0`, variant tags, duplicate/extra/missing fields and nested stability ([browser-wire-vectors.ts](../../../../runtime/test/browser-wire-vectors.ts#L35)). That authored host oracle cannot remain as the migrated judge; the ledger requires Can-owned vectors/comparison policy ([BROWSER-010](../native-can-tests-migration-ledger-2026-09-30/browser.md#L240)). The Can catalogue does expose generic typed `codec::encode_json`/`decode_json` and JSON-value operations ([catalogue README](../../../../std/catalogue/README.md#L371)).

**Design-plausible trace.** For the race writer, Can reads the generation attribute through `browser.capture`, constructs exact JSON request bytes/headers and directs a typed `browser.fetch(page, request)` effect in the **page's origin and credential realm**; it observes status/body and independent DB rows, then edits/saves the grid and checks conflict. For codec parity, Can builds a browser-target Can subject containing ordinary Can vector functions and writes bounded result facts into DOM or an explicitly declared data export; it compares those against fixed Can-owned expected vectors and separately runs the Bun leg. The browser driver only loads the identified artifact, reports engine/version/feature and returns DOM/data facts. It cannot retain `runBrowserWireVectors()` as an opaque TypeScript pass/fail report.

**Missing primitive / unknown.** The current capability table has `browser.route_fetch` (driver upstream from interception) and external `http`, but no generic page-realm `browser.fetch`. An external HTTP request with copied cookie/header is not the same origin/CSP/credential behavior as the old page's native Fetch. Add a typed page Fetch operation with method/path/headers/immutable body, explicit same-origin credential mode, response facts and no arbitrary JS source. It must use the candidate browser realm yet return untrusted data to the Can judge. For vectors, feasibility of expressing the exact old 12-case generic schema/codec checks as browser-target Can code and exposing their raw results without a TS oracle is unproved; `browser.load_artifact` on a blank page also needs an explicit module-entry/DOM-ready contract because the generated browser entry runs after DOM readiness ([browser entry](../../../../runtime/browser/entry.ts#L1)).

## Bounded feasibility experiments required before claiming this surface complete

These are proposed **future** experiments, each with a single scoped fixture and no broad build/benchmark. None has been run or authorized by this note. Use the qualified reference/driver inputs and the lifecycle profile only after those exist; register temporary ownership first, cap one browser context/one case and streams/disk/time, then close/reap and report cleanup on pass, failure and interruption. A failed feasibility experiment blocks the corresponding migrated leg; it does not justify an embedded script fallback.

| Question and dependency | Smallest setup and acceptance, including seeded failure |
| --- | --- |
| Can a pending route be resolved while the initiating click is outstanding, and can two DOM clicks share one browser task? Requires typed route token plus proposed `input_begin/settle` or equivalent and `dom_batch`. | One local page with a button that posts once and marks pending; arm route, begin click, read token and resolve while click is unsettled. Separately run a fixed two-click batch and require one request. Seed a driver that serializes route resolution behind click, or split the batch across event-loop turns, and require timeout/wrong-count to fail. One page, one pending token, a finite action/route deadline, cleanup after forced worker kill. |
| Can after-commit interception distinguish one upstream contact, altered browser delivery and durable effect? Requires `route_fetch`/`route_resolve` and independent DB observer. | One invoice POST with known operation ID: fetch upstream once, query one committed row, fulfill truncated body, replay same ID and require one durable effect/two captured requests. Seed a second upstream dispatch or return a truncated body falsely marked complete; the check must reject. One route, one DB namespace, body cap and explicit rollback/cleanup receipt. |
| Can a typed DOM clone/remount and event listener preserve target identity/occurrence phase? Requires `clone_subtree`, append and page-level `watch_dom_event`. | One same-origin HTMX form with a held response: clone target, submit, detach original after request, release, require response-phase `action::missing_target`, remount clone and verify no duplicate IDs. Seed a missing/dropped occurrence or reattach the original instead; Can must fail. One page/context/route, bounded event stream and terminal seal. |
| Can native event capture distinguish physical/synthetic input and synchronous cancellation across engines? Requires `watch_dom_event` with `defaultPrevented` and typed actions. | Static controls page plus one emitted Can control: record real Shift+Enter, synthetic composing input and post-app-listener `defaultPrevented`, then compare native property and Can echo. Seed listener registration at the wrong phase or substitute `fill` for synthetic dispatch; the expected event/echo must differ. One context per engine sequentially, no foreign egress, finite per-leg body/cleanup deadlines. |
| Can Can-authored browser vectors and page-realm Fetch replace the two old `evaluate` uses? Requires typed `browser.fetch` and a browser-target Can vector fixture. | One same-generation page POST with browser credentials and independent row read; then one Can-authored int64/`-0` vector rendered as data on a blank/same-origin page under Chromium/WebKit. Seed wrong generation header and wrong expected vector; both must fail. One owned server/DB/context, module artifact lease, finite byte limits, no authored JavaScript callback; close/seal and delete owned material. |

The remote Firefox path requires a separate ownership check when its required leg is admitted: current source connects to a shared `launchServer`, opens a fresh context, and intentionally does **not** close the server ([firefox-remote.mjs](../../../../tests/integration/browser/firefox-remote.mjs#L1)). A bounded two-leg probe should kill the first worker after context acquisition, have N close only its connection/context, then prove a second context still works; submit a shared-server close request with case-only authority and require rejection before effect. Never terminate the real shared server as a negative control; any destructive control needs a separately owned disposable stand-in. This remains unknown until run and does not warrant a server-termination claim from merely dropping a local handle.

Final review: the [central experiment register](experiments.md) governs exact future scope and safe controls. It separates the two missing-target phases, requires an event-realm microtask witness for same-task dispatch, same-node post-handler listener acknowledgment for cancellation, removal of the corruption route before replay, and an independently observed CSP-denied destination. No source note establishes a passing binding.
