# Database source challenge for native Can tests

Design review only, 2026-09-30. This records what the F02/F03 sources actually prove and the smallest missing test mechanics. It does not authorize a database service, build, suite, benchmark, or changed runtime. The [capability contract](../../native-can-test-capabilities-2026-09-30.md#7-additional-shared-observations-required-by-the-ledger) proposes `db.namespace/connect/begin/execute/query/commit/rollback/close`; these are logical future bindings, not present Can test APIs. A normal Can function must own fixture selection, SQL, choreography, assertions, retry decisions, and the verdict. The native service returns bounded facts and owns cleanup; it does not execute an F02/F03 script or classify success.

Final review clarification: driver promise settlement is not necessarily server-side effect quiescence after an ambiguous connection failure. Final-state inference and namespace deletion require server acknowledgment or qualified fencing/reconciliation, otherwise retain indeterminate effects and unresolved cleanup. Native SQL cancel signals are currently unsupported; lack of cancellation alone does not block the intentionally delayed-work probe. The [central experiment register](experiments.md) governs its exact scope, connection budget and acceptance.

## 2. Exact observation contract to retain

1. **Namespace and provenance.** Supervisor-owned, collision-safe disposable database/schema/table identity is reserved before any destructive SQL. Record server version, database/driver identity, subject compiler/runtime, observer driver, connection ID, transaction/attempt ID and operation ID. The old fixed `f02_*`/`f03_*` table names and `DROP TABLE IF EXISTS` are not sufficient ownership checks; old catch paths swallow cleanup errors. [F02 cleanup](../../../../tests/integration/testdata/sql/f02-live-driver.ts#L384-L405), [F03 cleanup](../../../../tests/integration/testdata/sql/f03-live-driver.ts#L534-L557). A raw observer may run setup/teardown mechanics only within that pre-owned namespace; Can chooses the fixture and checks cleanup receipts. Redact URLs/passwords before reporting, as the Go callers attempt. [F03 caller](../../../../tests/integration/sql_f03_test.go#L33-L57).
2. **Native result facts.** `db.query` must return ordered rows with column names, duplicate-name policy, tagged null/boolean/integer/decimal/float-bit/bytes/date-time values and exact int64 decimal text or bigint-safe encoding; native error class, SQLSTATE/errno/constraint are separate fields, not parsed from message text. `db.execute` returns native affected count and query identity. Preserve zero-row and two-row RETURNING results; never reduce them to a boolean. These facts let Can compare raw output with `sql::row_missing`, `row_count`, `constraint_failed`, `query_failed`, `schema_mismatch`, and exact Can values. Current codec accepts native PG boolean/bigint, SQLite 0/1 with `safeIntegers`, canonical MySQL integer text, nullable Option, and UTC-pinned MySQL `Date` projection, while rejecting unsupported shapes. [Codec](../../../../runtime/platform/sql/values.ts#L31-L62), [decode](../../../../runtime/platform/sql/values.ts#L157-L269), [PG mapping](../../../../runtime/platform/sql/postgres.ts#L9-L76), [MySQL mapping/pin](../../../../runtime/platform/sql/mysql.ts#L30-L121), [SQLite open](../../../../runtime/platform/sql/sqlite.ts#L123-L160). A TEXT JSON value is text at this boundary; JSON semantic comparison is a Can decision.
3. **Transaction/ordering facts.** `begin/commit/rollback` and Can `with_transaction` must expose distinct connection and transaction handle identities, plus begin, callback-entry, statement dispatch/settlement, decision, native settlement and cleanup facts. Transaction-bound `query/execute` must use the exact native transaction handle for the entire callback and drain; a pool handle is not a substitute. An asynchronous DB request needs separate `accepted/started`, `settled`, and `deadline` facts, with operation ID and which connection owns a still-live query. A visible deadline cannot close that query or free its transaction lease. Any `cancel` operation must report whether native cancellation is supported, whether the server acknowledged it, and whether native settlement followed; absent that qualification, cancellation is merely a stop-admission/request fact and cannot prove no mutation. A Can gate may hold an actor only at a reviewed asynchronous continuation point; release is explicit and bounded. For locks, prove A's acquisition before B's probe, B's result before A's release, and a later successful read after native transaction settlement. For `LAST_INSERT_ID`, compare generated ID and payload within each actor's same transaction and independently count final committed rows/unique IDs on a separate observer connection. F03's lookup-first outcome needs both per-attempt classification and final raw state, not only one accepted flag.
4. **Unknown effects.** `raceBoundary` does not cancel SQL: a visible `query_failed(...,"budget")` can precede a later native write, and the pool lease remains owned until settlement. A started `withTransaction` deadline yields `commit_unknown(transaction_id)` and does not retry; a prestart expiry reports `transaction_failed("budget")`. Post-decision native rejection is also `commit_unknown`; SQLite attempts rollback of failed COMMIT but retains unknown classification. [Pool boundary](../../../../runtime/platform/sql/pool.ts#L165-L190), [write boundary](../../../../runtime/platform/sql/pool.ts#L300-L348), [transaction outcomes](../../../../runtime/platform/sql/transaction.ts#L245-L294). Therefore the observer's immediate absence of a row after visible timeout is **not** proof of rollback. Keep the namespace and native lease alive, record late settlement, fence admission, then perform a fresh independent read. If quiescence/reconciliation cannot be established before finite cleanup, report indeterminate/broken and retain compact evidence; do not silently retry or drop a live fixture.

The proposed generic DB operations must expose two independently owned connections, transaction-bound operations (never silently return a pooled connection in place of the transaction), raw typed result/error facts, observable quiescence, and external ownership that survives a Can worker crash. The [capability contract](../../native-can-test-capabilities-2026-09-30.md#7-additional-shared-observations-required-by-the-ledger) sketches this interface, but no reviewed managed DB namespace/session binding or host-enforced live-query cancellation is shown there. Current Bun SQL adapters and Can SQL transactions are actor functionality, not this observer/supervisor capability. A timeout without native cancellation can only give a bounded visible wait and an eventual reconciliation/cleanup outcome, not bounded native settlement. These are admission gaps for DB migration, not claims that existing F02/F03 tests fail.
