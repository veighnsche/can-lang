# Hard native cases: source challenge and bridge gates

Status: source-based design challenge only. No implementation, test, build, live probe or measurement was run. This examines the proposed [`native.make`/`invoke`/`observe` contract](../../native-can-test-capabilities-2026-09-30.md) against current [native qualification](../../../../tests/conformance/native.ts), delegated runtime cases and compiler/runtime boundaries. “Source-established” below means the current source contains the behavior and oracle, **not** that a Can-authored replacement exists or currently passes.

These cases are distinct from a normal Can codec/collection program. Raw native facts qualify the candidate Bun APIs; a C-compiled production fixture exercises C's generated adapter; an R-built observer may inspect either only through a reviewed bridge. Agreement between two outputs produced by the same adapter is not independent evidence. The current TS tests combine setup, scenario, observation and verdict; the new native service must expose mechanics and facts while Can performs the sequence and comparison.

## Concrete constraints on the proposed bridge

The [catalogue](../../../../compiler/internal/catalogue/catalogue.go) is a closed distribution inventory; [`Resolve`](../../../../compiler/internal/catalogue/resolve.go) checks admitted operation identity, target/revision, concrete types and exact callback signatures/error bounds. Proposed `native.*` operations need actual admitted catalogue declarations and reviewed bindings; a case cannot dynamically register a JavaScript function or arbitrary runtime opcode. Can `int` lowers to `bigint`, `float` to JS `number`, and ordinary typed records/arrays do not directly represent a revoked Proxy, throwing accessor, raw JS error object or unassimilated thenable. Opaque session handles and tagged observations are therefore substantive new binding work, not simple aliases for Can values.

Ordinary named callable values lower to **native async closures returning protected `Completion` promises** ([callable contract](../../../implementation/callables.md), [emitted type](../../../../compiler/internal/emit/regions.go)). The runtime also has synchronous `value` and `invokeSync` helpers in [`completion.ts`](../../../../runtime/completion.ts), so it would be inaccurate to say every Can-related path is asynchronous. Those helpers do not by themselves prove that an arbitrary authored Can callable can implement a synchronous JS getter, Proxy trap or comparator. A trap cannot wait for controller RPC or return a Promise in place of its value. A finite immediate native descriptor is plausible for hostile traps; richer local callbacks require an explicitly checked, synchronous companion contract and source-backed admission evidence.

An R-built probe is not automatically a C-runtime probe. [`RunOutput`](../../../../compiler/internal/driver/output_runtime.go) verifies a generation's `manifest.Inputs.Runtime` against R's `PrivateArtifacts()` and validates every `runtime/*` import. Silently replacing those imports with C bytes would violate its integrity model. An **explicitly designed subject launcher** could run an identified R-built observer under C's Bun executable to establish native Bun facts, but its imported Can helpers would still be R's; current `RunOutput` does not prove or provide that bridge. Calling a C-built adapter from it requires a reviewed cross-artifact linking/protocol design and compatible completion/identity rules; no old ABI compatibility is promised. A safer initial division is: R-built Can judge in its trusted worker; disposable native observer under the identified candidate Bun for raw APIs; separately C-built subject process for production Can behavior; compare both via bounded tagged facts in R. If a delegated case requires a hostile same-realm value passed into C's adapter or a synchronous C callback, that bridge is a named implementation gap until qualified. A C-generated callback is subject code, not an independent observer or judge.

Promise assimilation is particularly easy to introduce accidentally. A JS `async` function returning a raw thenable, `Promise.resolve(raw)`, or a protocol layer that unwraps a raw value before boxing can call `then` before Can sees a handle. The current [array implementation](../../../../runtime/collections/array.ts) deliberately iterates numeric indices and boxes callback completions before `Array.fromAsync` can assimilate payloads. The proposed RPC must carry only inert handle IDs and tagged completion facts. `native.invoke` must identify which await/assimilation is **part of the named native API**; transport and `native.settle` must add none. Counters need a snapshot before and after the action and a sealed interval before a zero-call claim.

## Small future qualification experiments (not authorized now)

Each experiment is a bounded correctness probe in a fresh owned session/workspace with one candidate identity, explicit short deadline, event/byte caps, no persistent bundle, and owner cleanup receipt on success, failure and killed worker. They should be run only in a later authorized implementation/qualification round; no performance measurements are implied.

1. **Raw-value transport.** Question: can a candidate-Bun observer construct `-0`, a large JSON lexeme, a getter-backed `then` and a throwing thenable, then return handles/facts without extra access? Acceptance: Can sees exact string/bits and zero getter/then calls until explicit get/await, plus correct identity on two aliases. Negative controls deliberately unbox through a Promise, round the token and normalize `-0`; each must fail a named Can check. Close destroys handles and confirms no child remains.
2. **Synchronous hostile construction.** Question: can reviewed descriptor forms create a Proxy/getter/revoked value that the C production adapter sees in its own realm without embedding a test script? Acceptance: a C adapter's defensive action reports the expected rejection while trap count remains zero, and an explicit native get increments exactly once. Negative controls use an eager getter read and a non-revoked control. If the bridge cannot present the handle to C, mark the production leg blocked rather than crediting an R-only native probe. Bound traps/actions and tear down the subject process on every outcome.
3. **Callback and completion ABI.** Question: can an R-authored callback be admitted in a separate subject realm, and what exactly does it execute against: R helpers, C adapter, or native Bun? Acceptance requires an identified R probe artifact, a verified C subject artifact, exact callable/effect signature, explicit same-realm invocation path, no private judge channel, and raw event/occurrence facts returned to R for comparison. Negative controls swap runtime import hashes, supply a wrong callback type and return a raw thenable; all must reject or expose assimilation, not silently run. Do not assume this experiment succeeds; retain the separate-process fallback for obligations it cannot meet.
4. **Late coordination and cleanup.** Question: can a selected result return while a losing participant later fails or uses a captured resource, with the final event seal showing the late fact before release? Acceptance: Can observes selected occurrence identity, ordered late diagnostic, lease held through late use, then clean release and no event gap. Negative controls close early, drop the late event and change the occurrence handle; each must prevent a complete pass. Bound gates and settle/cancel on deadline; N cleans even if the worker dies.

The first two experiments test the fact surface. The third is a genuine compiler/runtime bridge decision, not an assumed consequence of ordinary Can functions. The fourth checks absence and lifetime claims that cannot be proved by an early successful prefix.
