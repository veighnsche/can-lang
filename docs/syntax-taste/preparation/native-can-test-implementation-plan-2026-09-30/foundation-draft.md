# Foundation tasks for native Can testing

Draft for the canonical plan at `docs/implementation/native-can-tests-plan-2026-09-30.md`; its sibling `native-can-tests-plan-2026-09-30/` should hold compact acceptance records. This draft covers the shared foundation only. The [design reconciliation](../../native-can-test-design-review-2026-09-30.md), [architecture](../../native-can-test-architecture-2026-09-30.md), [lifecycle](../../native-can-test-lifecycle-2026-09-30.md), [prerequisite inventory](../../native-can-test-prerequisites-2026-09-30.md), [capabilities](../../native-can-test-capabilities-2026-09-30.md), [authoring design](../../native-can-test-authoring-2026-09-30.md), and [migration ledger](../../native-can-tests-migration-ledger-2026-09-30.md) govern the work. R (reference compiler/runtime) and N (external Go owner) have **no accepted executable today**. Their construction and acceptance are tasks here; neither is an assumed starting gate. No new backend, build, host probe, or migration credit follows from this draft.

`D` below means a draft may be written and statically reviewed; `Q` means its qualification or live integration needs the listed accepted inputs. Keep provisional results visibly provisional. Every task records a focused diff, input and executable digests, bounded positive/negative controls, actual output, cleanup result, reviewer disposition, and the commit containing the change in a `Pxx` evidence file under the canonical plan sibling. A failing or unavailable gate records `blocked` and the exact missing guarantee, never a substituted green result. Temporary work is registered before allocation and removed on success, failure, and handled interruption; retain compact evidence only. Each slice is independently reviewable and may be committed as soon as its bounded checks pass. The task list does not authorize deferred broad builds or performance measurements.

## External generic Go owner N

`tools/native-test-owner/` is a proposed new package/executable prefix, outside candidate-generated Can. It may reuse ideas from `compiler/internal/driver/supervise.go` and `compiler/internal/driver/runtime.go`, but those assertion/entry launchers are not N. The separately identified transitional bootstrap parent T must stay outside the killable N/worker subtree and retain a finite ownership record and stop/reap authority during N's first death controls. T is bounded acceptance machinery, not a permanent scenario runner. N never chooses fixtures, expected values, retries, or a case verdict.

## File arbitration, correction and handoff gates

The plan coordinator gives one writer at a time to `compiler/main.go`, `compiler/internal/emit/program_entry.go`, `compiler/internal/driver/test_stage.go`, `compiler/internal/catalogue/catalogue.json`, and authored `runtime/` or `tools/runtime/` files. P18 owns the emitted entry; P20 owns diagnostic driver; P21 alone integrates shared CLI dispatch after both land. Future native binding lanes must queue catalogue edits behind one catalogue owner, regenerate derived files through repository tooling, and never hand-edit generated `runtime/catalogue.ts`. Runtime TypeScript edits trigger `bun run lint:fix:runtime`, `bun run format:runtime`, `bun run check:runtime` and relevant bounded tests under AGENTS.md. Independent Go/Can files can draft concurrently; shared Go interfaces and protocol schema change only through P01/P02 owner review. Migration tasks begin authoring against accepted contracts but claim live coverage only after the relevant P23 and specialized N1/N2/F1/B1/DB acceptance gates.

Critical cycles to break explicitly: (1) R cannot be accepted solely by the suite it will compile, so P05 uses separately reviewed host bootstrap/fixed observations and P23 later qualifies the suite; (2) N cannot certify its own cleanup after N death, so T remains an intact outside observer through P14; (3) strict-host qualification may fail on this Mac, leaving P13/P14 integration blocked without weakening the envelope; (4) a missing R binding must take P06's reference refresh path, not candidate self-promotion; (5) P24 cannot select fewer assertions to prove P24 itself; (6) a passing Can report needs a matching current N receipt/correction chain, never the candidate's self-report. Reserve a distinct commit for each resolved gate and its compact evidence so an unqualified downstream lane can stop at the exact prerequisite rather than forcing a broad partially trusted merge.
