# Proposed native Can migration slices

Status: **planning only**. The paths below are proposed owned prefixes; none is asserted to exist. [Machine-readable groups](migration-groups.json) contain each slice's complete row IDs, exact acceptance sentence, suggested small commit, dispositions, delegated-oracle IDs and deletion policy.

The 45 slices assign all 292 ledger rows exactly once. Each owns a distinct new `tests/native-can/migration/<slice>/` prefix. The foundation and capability lanes must supply an accepted R, qualified N, nonpublishing ordinary Can entry, typed operations, independent observers and matching receipts before these slices can claim integrated qualification. A slice can author source earlier, but unavailable required environments or unqualified dependencies remain blocked. Acceptance is per retained facet, dynamic variant, fixture and environment, with Can-owned expected values, positive/negative/missing-evidence controls, exact artifact identities and cleanup receipts.

## Retirement and cross-slice joins

- **Shared old files are integrator-owned.** No migration slice deletes or edits a shared old Go/Bun/JS/TS harness. The integrator checks the file map's direct and related rows, delegated oracles, required profiles, current callers and correction-aware Can/N receipts before removing an old file. Static fixtures and historical records may remain. Conditional `historical_candidate`/`preserve_record`/`retain_fixture` rows get an individual current-contract relevance decision; their inclusion in a group is not a requirement to preserve obsolete ABI, old pass counts or dated advice.
- **HISTORY-143 and EDGE-001 are linked views of native qualification.** M37 owns Can policy for native qualification; M43 owns the Python/Linux caller transition. They are one protected qualification dependency, not two coverage wins.
- **Delegated runtime suites cross parent groups.** All 30 delegated suites are indexed in the JSON. `DELEGATE-009` and `DELEGATE-016` join CORE cases with LIFE-009; `DELEGATE-026` and `DELEGATE-028` join CORE-044 with LIFE-009. Keep those declarations and dynamic variants mapped until both parent claims are accepted. Calling Bun tests from Can does not migrate their oracle.
- **Existing source files span slices.** The file map assigns multiple rows to `tests/integration/gate3_matrix_test.go`, `invoice_contract_test.go`, `invoice_test.go`, `harness_cache_test.go`, `tests/baseline/*`, native qualification and prototype test files. A completed slice cannot retire such a file while another direct row remains. M29 deliberately joins HISTORY-034–041 with LIFE-016–024 because both protect cache ownership/reuse; all individual row controls remain mandatory.
- **Browser and SQL joins remain gated.** M18/M21 require B1/B2 and D1–D4 evidence where their invoice race/settlement facets apply. M12/M20 need exact required engine profiles and host-effect isolation, including remote Firefox ownership where used. M25's new SQL sentinel and settlement checks are stronger qualification evidence, not retroactive claims about F02/F03.
- **External consumers are work, not proof.** M43–M45 rewire `distribution/qualify.py`, Linux scripts, CI, `host/conformance` and operator docs only after their referenced Can rows are qualified. Independent compiler/runtime unit suites invoked by the old broad meta-runner remain separate gates unless individually placed in the ledger. Preserve ordinary provisioning behavior while removing old test policy.
- **No automatic historical deletion.** M13's grid bundler/SHA shim, M30's baseline/T27 records, M31–M34's prototype rows and M36's authoring-policy records have conditional dispositions. Resolve active source-presence checks and callers first; preserve useful records without crediting them as execution.

## Validation performed

Static ledger reconciliation found 45 unique owned prefixes, 292 unique row IDs out of 292 source rows, and all 30 delegated-oracle IDs attached to at least one parent slice. No build, test, browser, service or performance measurement ran. The implementation planner should turn each slice into smaller per-row or per-fixture commits where needed; the JSON commit text is a starting scope label, not permission for a large batch commit.
