# Final coverage and report review

Status: design review only; no main-document edit, test, build or measurement. Reviewed [the lifecycle contract](../../native-can-test-lifecycle-2026-09-30.md) against the [completion requirements](../../native-can-tests-completion-contract-2026-09-30.md), [authoring report policy](../../native-can-test-authoring-2026-09-30.md) and [execution architecture](../../native-can-test-architecture-2026-09-30.md).

The requested distinctions are mostly explicit. A valid named mismatch may end the case with later checks marked `not_reached_after_failure`, preserving exit 1 when every selected case has valid terminal/accounting and clean receipts. Those unperformed tails get no exercised-coverage credit. Selected cases left unstarted by fail-fast are counted but make the run exit 2. An earlier failed retry remains visible and a later pass cannot make that same run clean. Expected crash/timeout of a subject, including a subordinate runner deliberately tested by an intact outer case, is observable data; an actual top-level judge/controller/N failure cannot be self-certified as a passing case.

Two useful clarifications remain before freezing the exact report schema:

1. **Separate selected units from attempts.** Section 1 says the complete selected plan is expanded before admission and calls `case + variant + attempt` the planned execution unit. Retry attempts are selected later by Can, so their count cannot generally be in that initial complete plan. Freeze the selected **case/variant matrix** and required checks before admission; append each retry as a new identified attempt under an existing selected cell, with its Can-chosen reason and immutable history. This preserves the stated no-shrinking rule and avoids making a later legitimate retry look like an unplanned variant or allowing it to change profile coverage.
2. **Close the cross-job evidence set.** Section 7 correctly permits different platform artifacts, requires matching per-job receipts and forbids unioning partial attempts or picking the best unexplained flaky outcome. To make that checkable, bind a qualification campaign/evidence-set ID and its candidate/suite/coverage identities to an append-only index of submitted jobs and attempts. The Can reducer should account for duplicate observations of the same required matrix cell, including failed or blocked ones, and require an explicit reason/corrective-run relationship before superseding them. A manifest assembled only from passing job files cannot establish that no failing same-identity job was silently omitted. This is a report/provenance rule; N need only transport and identify jobs, not choose which results count.

No additional status axis is needed. Keep the existing 0/1/2 mapping and the paired Can report plus N receipt: exit 1 describes an honestly completed behavioral failure, while missing selected work, report integrity loss and cleanup uncertainty take exit 2 even when a mismatch also occurred. The implementation gates for host enforcement remain future work, as the document states.
