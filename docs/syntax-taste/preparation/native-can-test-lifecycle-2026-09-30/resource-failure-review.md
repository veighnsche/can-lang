# Failure and resource lifecycle review

Status: **design recommendation from source review only**. No suite, build, host enforcement or recovery probe was run. This refines the [execution architecture](../../native-can-test-architecture-2026-09-30.md#evidence-transport-failure-and-resource-boundary) and [capability contract](../../native-can-test-capabilities-2026-09-30.md#2-shared-authority-outcomes-and-evidence). Can owns case expectations, stop policy and report reduction while it is alive; N owns admission safety, monotonic deadlines, process containment, cleanup and the outer receipt even if Can dies.

## States and finality

**Run:** `recover-prior → preflight → active → quiescing → cleaning → finalized | unresolved`. N first reconciles earlier owned records and establishes a durable run scope, then checks reference/candidate identities and profile guarantees before launching a Can controller. `quiescing` closes new case and native-operation admission and fixes the set of selected, started and not-started attempts. `finalized` means resource accounting is complete and N has issued its receipt: a clean success additionally requires a valid matching Can report. On controller crash, N may finalize a nonzero generic incomplete envelope after confirmed cleanup, but cannot synthesize a Can report. `unresolved` retains owned records and cannot be a clean result. No path from `quiescing` returns to `active` within the same run.

**Case/attempt:** `planned → admitted → running → evidence-closed → cleaning → terminal`, with `not-started`, `blocked` or `cancelled` exits from the appropriate earlier state. `evidence-closed` means no new worker evidence is accepted; it is not a passing verdict. N records a terminal operation state and cleanup receipt before the Can controller reduces behavior, execution and cleanup to `passed`, `failed` or `error`. A previously emitted Can `passed` is provisional until N confirms cleanup. If the controller is gone, N retains the trace and marks the attempt incomplete instead of assigning a case verdict. Every selected variant/attempt remains accounted for after fail-fast or interruption.

Use separate identities and deadlines for **subject operations**, **Can worker/judge**, **Can controller**, **run**, and **cleanup**. A Can-selected subject `proc.wait_exit` deadline, expected subject crash or expected compiler rejection is raw observation; a judge timeout/crash, controller death, malformed or absent private terminal record, and N cleanup timeout are execution errors. A late worker report cannot override a fired external judge deadline. Current assertion supervision already applies an outside monotonic timeout and discards a result observed at/after the budget; unconfirmed direct-worker reap stops its suite ([source](../../../../compiler/internal/driver/supervise.go#L240)). The live contract must add descendants and resources, not reuse only `root=N` reporting.

## Cancellation and cleanup order

For a hard case deadline, worker crash, protocol overflow or explicit interrupt, N should:

1. Latch the initiating cause and close that scope's admission first. Reject later commands and evidence as late, retaining their identities and bounded diagnostics. Preserve any earlier Can mismatch; cleanup errors append rather than replace it.
2. Signal cooperative cancellation to a live worker/controller when time remains. Do not rely on their `finally` or callback drain; after a bounded grace, stop/reap the worker externally. A second interrupt may shorten the grace, but cannot make an unfinished cleanup look complete.
3. Quiesce accepted external operations and stop their producers. Mark a lost acknowledgment or ambiguous write/commit `indeterminate`, never replay it automatically. Terminate owned children/sessions within a separate bounded cleanup budget, confirm descendant/stream/descriptor state, and only then remove dependent workspaces, DB namespaces or object prefixes. Deleting storage before late accepted writes finish can recreate state after cleanup.
4. Record both the original execution/behavior facts and each forced action, remaining resource, cleanup error and ownership identity. Emit a final N receipt only after all claimed closures are confirmed; otherwise retain a recoverable `unresolved` record. If the controller died, emit a generic nonzero incomplete envelope, not per-case fabricated failures or passes.

The ordering is a dependency order, not permission for an unlimited drain: every wait, stream and cleanup step has a finite outer deadline. A failed `proc.close` or `work.dispose` must retain ownership/quota for remaining children, paths or leases, rather than release capacity on a partial receipt ([resource review](../native-can-test-capabilities-2026-09-30/review-resources.md)). Current `process::run` termination is in the worker's runtime scope, uses process groups and can suppress cleanup errors ([spawn](../../../../runtime/platform/process/spawn.ts#L143), [group termination](../../../../runtime/platform/process/wait.ts#L1)); it is not sufficient after worker `SIGKILL`. Current Go assertion supervision kills/reaps its direct Bun worker but does not establish descendants or external fixture cleanup ([source](../../../../compiler/internal/driver/supervise.go#L240)).

## Continue, quarantine or stop

| Observed condition | Required disposition |
| --- | --- |
| Can comparison failure with complete evidence and cleanup | Record `failed`; the living Can controller may continue other selected cases under its declared stop policy. No success for the failing case. |
| Expected subject nonzero exit, crash or bounded timeout | Can may pass its own expected-behavior check **only** after raw status/timeout and cleanup are complete. N does not decide whether the negative outcome was expected. |
| Isolated worker crash, judge timeout or missing terminal record, with all case resources contained and cleaned | Record `error`/incomplete evidence. The living Can controller may continue disjoint cases; it cannot retry the attempt invisibly or turn it into success. Every attempt stays in the report. |
| Lost case output/evidence events but confirmed containment and cleanup | Record case `error` with gap/truncation facts. Other disjoint cases may continue by Can policy; missing evidence cannot be reconstructed from a digest. |
| Ambiguous external write/commit/HTTP effect | Mark the case indeterminate and quarantine the affected namespace. Do not replay on the same state until Can-directed independent reconciliation establishes the effect. Only demonstrably disjoint cases with separately enforced capacity may continue; default initial profile stops further live admission. |
| Cleanup failure, unknown descendant/liveness, corrupted owner journal, exhausted or unenforceable run budget, or failure of N's run-level control channel | N stops new live admission for the run and returns unresolved/incomplete status. A Can controller cannot override this safety stop. Preserve resources for safe recovery, not destructive guessing. |
| Controller death, run hard deadline or user interrupt | N stops all new work, contains active cases and reports selected outstanding cases as not-started/cancelled where known. No valid Can aggregate exists after controller death; interruption is never a full pass. |
| N death | No final receipt or success. Surviving external resource service/watchdog may act if implemented; otherwise the next entry must recover. Do not describe later recovery as immediate containment. |

This separates **case-level evidence failure** from **run-level safety failure**. The existing assertion `runRootsOrdered` cancels remaining roots after its first genuine supervisor error ([source](../../../../compiler/internal/driver/supervise.go#L142)); the live suite can continue after an isolated cleaned case failure because Can owns stop policy, but must stop when N cannot prove isolation, ownership or capacity. Initial one-live-case scheduling makes that boundary easier to audit.

## Interrupted and abandoned resources

On a handled SIGINT/SIGTERM, N latches `interrupted`, closes admission, asks Can to cancel, then performs bounded external cleanup as above. A compact partial Can report is useful if available, but it cannot change interruption into success. An unhandled N crash leaves no receipt; the next invocation performs `recover-prior` **before** live admission, using durable owner/run IDs, path inode or equivalent identity, process start identity, leases and an inactivity proof. Age or name alone never authorizes deletion. Active or foreign paths/processes remain untouched; uncertain liveness is unresolved. Do not retry a candidate mutation merely because the old worker is gone.

Admission after recovery is allowed only when prior owned resources are confirmed closed or their unresolved scopes are proven disjoint from the new namespace **and** hard capacity accounting still holds. The conservative initial policy is to refuse new live runs while any prior owned resource remains unresolved. Read-only inspection/reporting may proceed. Recovery may finish an interrupted disposal but must retain its earlier failure and its own actions in the new receipt. Unknown files or identity changes should cause refusal, as the existing output-store recovery/prune does for its own bounded generation tree ([recovery](../../../../compiler/internal/driver/output.go#L676), [prune preflight](../../../../compiler/internal/driver/output.go#L830)); that code is not a general process/DB/browser recovery service. Current launcher cleanup calls `os.RemoveAll` without reporting its error ([source](../../../../compiler/internal/driver/runtime.go#L291)); the live owner must report it.

The main draft is consistent about separate Can/N receipts and nonpassing unknown cleanup. One wording risk is its generic `closed`/`completed` state: neither should mean "cleanup attempted" or "leader exited". The resource tables should require confirmed closure for quota/lease release and retain an `unresolved` state with a recovery record on partial close. No host mechanism for detached-descendant containment, strict disk quotas or crash-safe pre-exec registration is established by these documents; capabilities requiring them remain unavailable until qualified ([capability contract](../../native-can-test-capabilities-2026-09-30.md#2-shared-authority-outcomes-and-evidence)).
