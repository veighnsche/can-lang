# Reference toolchain prerequisite audit

Date: 2026-09-30. This is a source and evidence audit only. No compiler, build, test, service, benchmark, download, or feasibility probe was run for it. The installed-artifact inventory is a separate prerequisite; this note does not nominate a pathname or promote an artifact.

## Role and acceptance boundary

The [native-test architecture](../../native-can-test-architecture-2026-09-30.md#reference-suite-and-candidate-identities) gives **R** the compiler, emitter, language runtime/catalogue, Bun executable, and trusted platform bindings that compile and execute the Can controller and judges. **C** supplies compiler/runtime inputs and generated subjects under test. **N** is the generic external supervisor and resource/driver owner; its content identity and capabilities must be recorded separately. R must build the suite. Invoking `candidate canlc run` would compile the judge with C, because the current [`Run`](../../../../compiler/internal/driver/run.go) builds with the invoked compiler. C compiling or rebuilding a runner is a subject observation, never reference promotion. The [completion contract](../../native-can-tests-completion-contract-2026-09-30.md#4-coverage-preservation-and-material-classification) likewise says the first actual qualified reference artifact still requires evidence.

An R acceptance record must bind one exact, immutable distribution and its source/build provenance; compiler, runtime/catalogue, Bun, supervisor and binding digests; supported host/capabilities; independent qualification evidence; and known limits. It must distinguish R trust from the reviewed suite source/coverage/expected-vector snapshot and its negative controls. The [architecture's bootstrap protocol](../../native-can-test-architecture-2026-09-30.md#bootstrap-and-deliberate-reference-refresh) says no exact distribution or commit was qualified by that design work. Checksums and a valid bundle are necessary identity checks, not a semantic qualification receipt. An unestablished seed blocks R-dependent feasibility tests; C's own successful tests cannot close that gap.

The repository evidence can therefore **identify plausible seed lineages and checks to reuse**, but cannot itself promote any concrete installed artifact. An installed candidate found by the parallel inventory needs exact bundle/manifest/launcher/Bun hashes, source/build provenance and a scoped acceptance record matched to those bytes. A mere `canlc` on `PATH`, an install-root `current` symlink, `git describe` version, or self-reported version cannot serve as the authority.

For any future build, source revision alone is incomplete provenance: [`Build`](../../../../distribution/build.go) walks every regular file under `runtime/`, `tools/runtime/`, `distribution/assets/` and `distribution/notices/`, including ignored local files. The actual staged inputs and resulting manifest must be recorded and checked before a build can be proposed as R.

## Bounded noncircular path for a later authorized qualification

1. Inventory existing distributions without executing them. Resolve immutable version roots, record full path plus manifest/launcher/asset digests and Bun target pin, and map each to a source revision/build recipe and any pre-existing receipt. If no artifact has credible provenance, leave R unestablished; do not silently use C.
2. Pick a seed by explicit evidence review. Run only bounded, independent checks needed to close that seed's remaining gap when probes are authorized: bundle integrity plus compiler/runtime behavior against fixed expected vectors and native observations that do not obtain their answers from C. Record host/target and exact scope. Historical I45 evidence can contribute only where its tested bytes and obligations actually match.
3. Before accepting the first native runner, verify Can selection/reduction and independent seeded failures: wrong observation, early `ok`, missing check, malformed report, controller/worker death, timeout, and cleanup failure must not yield a complete green receipt. N owns temporary work before effects, enforces bounded resources, and emits its own completion/cleanup facts. These are runner controls, not C self-tests.
4. Save a compact reviewed acceptance manifest for R, N and binding capabilities, with input and output identities, evidence links, assumptions and limits. Bind the separately reviewed suite/coverage snapshot and negative controls when it exists. Do not retain full execution workspaces by default. A future R1 refresh remains a separate promotion using predecessor-compatible comparisons, independent observations and controls; if a feature is beyond R, record the trusted bridge or keep that obligation blocked.

This path is intentionally preparatory. No feasibility probe, performance run or broad build is authorized by this audit. It preserves the established architecture: R builds judges, C is only a subject, and N remains the external owner of resource limits and cleanup.
