# Platform semantics for Can preparation

24 September 2026 · P3.2 primary-source research · evidence only, no design or syntax selection

This note supplies external platform facts for [DI-09–11, DI-14–15, DI-19–20](decision-inventory.md), the [server](server-evidence.md), [browser](browser-evidence.md) and [lifetime/deployment](lifetime-deployment-evidence.md) packets, and the [evaluation protocol](evaluation-protocol.md). Sources below are official specifications or maintainers' API documentation, checked on 24 September 2026. The URLs for `current` PostgreSQL and Bun documentation are moving targets; at this check, PostgreSQL `current` identified version 18. Can's pinned Bun distribution is `1.4.2`, so current Bun documentation is evidence of platform possibilities, not proof that every API or behavior is present in the pinned binary. No source here establishes a Can compiler guarantee.

## Native lowering and server routing

| Upstream fact | Relevance and limit |
| --- | --- |
| [Bun's HTTP server](https://bun.sh/docs/runtime/http/server) accepts a `Request` and returns a `Response` or promise; its native `routes` can include static paths, `:param` segments and wildcards. [Bun routing](https://bun.sh/docs/runtime/http/routing) exposes decoded parameter strings on `BunRequest.params`. | DI-09a can evaluate a narrow native lowering or an adapter. Native routing availability does not create a Can endpoint type, URL builder, authorization check or compile-time route-reference guarantee. Can currently has an exact-path router. Verify route precedence, decoding and the pinned Bun version in an executable probe before choosing an implementation. |
| [Bun server lifecycle](https://bun.sh/docs/runtime/http/server) says `server.stop()` stops accepting new connections and waits for in-flight requests; `server.stop(true)` terminates active connections. Its idle timeout can reset a quiet connection, including an in-flight request without output. | DI-15a and DI-16 need an installed-target shutdown test. Connection closure is not evidence that arbitrary handler work, SQL or external effects stopped. The documented timeout and stop policy require a host grace/kill policy and owner-drain observations. |
| [Bun SQL](https://bun.sh/docs/runtime/sql#basic-transactions) documents `sql.begin(async tx => ...)`: queries inside run in one transaction, with commit on successful callback completion and rollback on error. Its [reserved-connection wait](https://bun.sh/docs/runtime/sql#reserved-connections) accepts an `AbortSignal` while waiting for a free connection; abort after acquisition has no effect on that reservation. | This supports DI-14 and DI-15's distinction between native transaction/wait operations and Can ownership adapters. A signal for pool acquisition must not be generalized to cancellation of a running query or committed transaction. Check the pinned Bun implementation and actual Can adapter. |
| [JavaScript `Map`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map) maintains first-insertion key order, uses `SameValueZero` key comparison and replaces a key's value on later `set`. | DI-20 can consider one native bulk build followed by immutable publication. It must specify Can's duplicate, equality, callback-order and aliasing contracts before lowering to mutable `Map`; native construction does not itself make an exposed map immutable. |

## URL, forms and HTML response behavior

| Upstream fact | Relevance and limit |
| --- | --- |
| The [HTML form submission algorithm](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#constructing-the-entry-list) builds an ordered list of name/value entries from successful controls. Repeated names remain distinct entries; the [URL Standard `URLSearchParams.getAll`](https://url.spec.whatwg.org/#dom-urlsearchparams-getall) returns all matching values in list order. | DI-09b's repeated `str[]` fields fit the native wire model. Neither standard pairs separate repeated columns into invoice line-item records or rejects unexpected/duplicate scalar fields; those are Can decoder and application contracts. Preserve strict UTF-8, unknown-field and scalar-duplicate behavior when using native parsing. |
| The [URL Standard](https://url.spec.whatwg.org/#urlsearchparams) defines `URLSearchParams` as `application/x-www-form-urlencoded` name/value parsing and serialization; space is serialized as `+` and percent encoding follows that format. | DI-09a/b needs separate tests for path captures, query and form bodies. A successfully parsed URL or form string does not imply a mounted Can route, an allowed HTTP method, a field schema or a live DOM target. |
| [HTMX response handling](https://htmx.org/docs/#response-handling) matches response status rules in order and permits configuration of `swap` and `error`. Its documented example swaps `422` but marks other `4xx/5xx` as non-swapping errors. The [response-targets extension](https://htmx.org/extensions/response-targets/) can choose targets by status. | DI-09d's 503/409/403 feedback is a policy question. Under the Can asset policy recorded in the server packet, returning a 503 fragment alone will not display it. The extension shows an upstream option but is not presently admitted by Can; test the exact vendored asset and rendered DOM before claiming visible feedback. |
| The [HTML entry-list algorithm](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#constructing-the-entry-list) derives form names from controls, while [DOM `getElementById`](https://developer.mozilla.org/en-US/docs/Web/API/Document/getElementById) returns `null` when no matching element is in the document. | DI-09d/10 should distinguish static authoring checks from runtime DOM presence. A route, field or target spelling change can drift across independent strings; native HTML/DOM APIs do not provide Can's proposed cross-file link. |

## Browser execution, scope and cancellation

| Upstream fact | Relevance and limit |
| --- | --- |
| [Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers) run in a global context distinct from `window`; they cannot directly manipulate the parent document and communicate through messages. [`Worker.terminate()`](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate) stops a worker immediately without giving it time to finish. | DI-11b/c must choose a main-thread DOM capability separately from worker computation and specify message codecs, ownership and termination if workers enter scope. A generic “browser” target cannot imply DOM availability in every browser execution context. |
| [`addEventListener` with `signal`](https://developer.mozilla.org/en-US/docs/Web/API/EventTarget/addEventListener) removes the listener when its controller aborts; [`removeEventListener`](https://developer.mozilla.org/en-US/docs/Web/API/EventTarget/removeEventListener) requires matching event type, listener and capture value. | DI-11c can use native listener disposal. Detaching a view or aborting a listener does not cancel already-running event callbacks or pending saves; the grid trial must observe late completions and avoid updating a disposed view. |
| [Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch#canceling_a_request) accepts `AbortSignal`; abort rejects an unsettled fetch and can abort reading a response body. HTTP error status such as 404 still fulfills with a `Response`, requiring explicit status inspection. | DI-11c/15a needs distinct transport, HTTP-status and domain-error cases. Aborting a client request cannot be treated as server rollback or proof that the remote system did not act. A late success after view disposal still needs a state policy. |
| [`Promise.race`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/race) with an empty iterable remains pending, whereas [`Promise.any`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/any) rejects an empty iterable with `AggregateError`. Neither API cancels losing operations as part of its selection contract. | DI-15b/c can retain native selection while guarding an application-required nonempty candidate set and observing losers through Can ownership. This platform fact does not decide whether Can should add a static nonempty type or fault-reporting mode. |

## PostgreSQL mutation and schema guarantees

| Upstream fact | Relevance and limit |
| --- | --- |
| PostgreSQL [`UPDATE`](https://www.postgresql.org/docs/current/sql-update.html) supports `RETURNING` values from rows actually updated; its command count can be zero without an SQL error, and counts matched rows even when values did not change. [`INSERT`](https://www.postgresql.org/docs/current/sql-insert.html) supports `RETURNING` from inserted or conflict-updated rows. | DI-14a has a native row-returning mutation path for invoice/outbox examples. A Can descriptor must still specify cardinality, row codec, dialect and zero-row meaning; `RETURNING` alone does not distinguish forbidden, missing and stale-revision cases. |
| PostgreSQL's [default Read Committed isolation](https://www.postgresql.org/docs/current/transaction-iso.html#XACT-READ-COMMITTED) takes a new snapshot per statement. Two `SELECT`s in one transaction can see different committed data; an `UPDATE` facing a concurrent updater waits and re-evaluates its `WHERE` condition against the new row version. | DI-09c/14 should test authorization and revision predicates at the protected write, or use a stated locking/isolation strategy. “Inside one transaction” alone does not make a prior authorization/read snapshot stable. More restrictive isolation introduces retry behavior to qualify. |
| PostgreSQL's [`UPDATE` reference](https://www.postgresql.org/docs/current/sql-update.html) specifies table/column semantics and output values at database execution time. Bun's [SQL documentation](https://bun.sh/docs/runtime/sql) describes runtime query execution, not a Can source descriptor checked against a versioned schema. | DI-14b must keep parser/descriptor validation, runtime row validation, and compile-time agreement with a schema snapshot as separate claims. Any snapshot proposal needs migration provenance and deployed-database drift checks; upstream SQL syntax cannot certify a Can declaration. |

## Remaining unknowns for bounded probes

1. Confirm native route parameter decoding, precedence, error handling and `server.stop` behavior in the pinned Bun `1.4.2` target; current upstream docs may have changed.
2. Test exact browser HTMX asset behavior for 422, 409, 403 and 503, including focus and retained values. An upstream configuration example is not evidence that Can's vendored policy has it.
3. Determine which pinned Bun SQL operations, if any, can cancel a running query, and what a client disconnect does to Can-owned transaction work. Pool-wait abort is the only SQL abort fact established here.
4. Specify a versioned PostgreSQL schema source before claiming compile-time projection agreement; observe a wrong projection against a real database.
5. Test a browser main-thread grid and, if proposed, a worker slice on named browser versions. Check DOM access, event cleanup, stale responses, fetch abort aftermath and observable rollback. No browser bundle or worker contract is established by these docs.
6. Benchmark native bulk collection construction only after duplicate/equality/immutability contracts are stated. The JavaScript `Map` API establishes semantics, not a Can performance result.
