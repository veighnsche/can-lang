# DI-06 current-Can fixture comparison: preregistered pilot

24 September 2026. Source revision: `02a549d28fd5fc5c3996160e65a97de332390d30`. This is a hand-authored executable mechanism probe, not an agent trial or syntax selection. Execute the same assertion before and after renaming only the caller assertion `customer` to `renamed`. Keep the expected result `"fixture"` and the helper source fixed across that rename. Capture compile/check outcome, assertion outcome, changed authored files, diagnostics, and whether the caller path executes the helper body.

Cases:

1. **Ambient lexical row:** reproduce the historical helper `text::from_int(7)` with local `unit` and foreign `customer` rows. Expected: `customer` passes; `renamed` falls through to real conversion and fails the caller assertion.
2. **Lexical template:** move repeated completion content into a `fixture ... for text::from_int` template, expanded by the helper's lexical `when`. Retain `unit` and `customer` selectors. Expected: same rename sensitivity because use-site selectors remain lexical.
3. **Whole-helper stub:** caller puts a `when` row around `helper::read()`, while helper has only its local `unit` fixture. Expected: caller assertion passes across its label rename with the caller's row renamed; the helper body is bypassed on that path. Helper unit assertion still passes separately.
4. **Ordinary injected callable:** helper accepts a typed callable converter and calls it inside its body. Caller passes an authored conversion function returning `"fixture"`; the helper also performs a second internal operation after that call. Expected: caller assertion passes across label rename with only its assertion row changed; helper body and the supplied callable both execute. This is a real Can function path, not a fixture supplied completion or provider adapter.

The comparison does not claim F1's proposed lexical ownership restriction is implemented. Current runtime selector behavior is measured as is. It does not test F2/F3 exported scenarios/seams, recursion, concurrency, nested linked scenarios, duplicate labels, or agent token cost. Any claim that helper-body execution happened must be supported by a distinct post-converter operation in the helper's returned value; an outer assertion pass alone would not establish it.

Follow-up controls registered before execution: in each failing renamed lexical case, change the helper's `customer` selector to `renamed` and expect a pass, recording that both packages' source files now changed since the original state. In the passing injected-callable case, change only `supplied_convert` to return `"wrong"`, then change only the helper's suffix from `"e"` to `"x"` in a separate copy; expect caller failures with `real-can` evidence. These controls test that the caller path depends on both the supplied function and helper's post-call body. A further stub control changes the helper's returned value to `"unexpected"` and expects the caller still to pass with `supplied-completion`, confirming that the stubbed caller path bypasses the helper body.
