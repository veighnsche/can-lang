# Implementation-planning readiness audit

24 September 2026. This is a separate consistency pass over the completed design packets and the [implementation graph](../can-implementation-task-list-2026-09-24.md), not production qualification. It checks the decision inventory rather than endorsing every mechanism. The user directed us to ask no more design questions and consult Jev for difficult technical choices. Earlier user choices of `bind name` and dependency-qualified imports remain unchanged.

| Audit axis | Result and evidence |
| --- | --- |
| Identity and scope | Every accepted mechanism addresses agent contract reliability, independent composition or the observable invoice/webhook/Can-browser target. Human readability is not an acceptance gate. Complete-task tokens are secondary and measured under the [evaluation protocol](evaluation-protocol.md); no token gain has been asserted from prose or Jev probabilities. |
| Inventory coverage | [DI-01–DI-23 ledger](design-disposition-ledger.md) gives every crosswalk row accept, retain or defer, including subtopics. Deferred mechanisms have reopening conditions and are excluded from the implementation graph. |
| Cross-feature contracts | The [integrated action contract](integrated-action-contract.md) resolves the HTML-form/JSON-browser wire conflict and the typed initial-load/reconciliation gap. Its three source actions expose HTML save, JSON save and authorized JSON load. The two writes share one protected operation; form-only and JSON-admissible inputs, result variants, decoders and renderers remain distinct. Owner records cross wire boundaries via transparent records/factories; package identity underlies owner, action, fixture and error identities. Variant and generic rules are compatible with symbolic public checks. |
| Server security and failure | Typed path IDs never authorize. Guarded Bun callbacks reenter the service lifecycle. Actor, membership, tenant, resource and revision are checked at the protected write. Foreign/nonexistent resources share a denial. Grid operation IDs prevent duplicate effects after uncertain acknowledgement; HTML uncertainty requires authorized reread. Real status, retained draft, strict form/JSON decoding and webhook replay must be externally observed in T14–T17. |
| Browser and platform | Browser capability closure rejects server modules; exact codec parity, safe DOM, view disposal, app-owned identified save and in-view offline draft are in T21–T25. Debian 13/Bun 1.4.2 installation, abort/shutdown and both server flows are in T19–T20. No reload persistence or arbitrary worker/import promise is made. |
| Dependency graph | T01–T27 dependencies point only to earlier IDs; package identity precedes owner/errors/actions, action metadata precedes route/form/JSON adapters, shared domain operation precedes both UIs, browser profile precedes DOM/Fetch/grid, and actual Linux/browser observations precede claims. The parallel-ready sets are advisory and respect hard dependencies. |
| Syntax and advice | Selected source forms are `bind`, qualified `uses`, `owner record`, unnumbered `error`, `scenario`, and bounded `action`/`captures`/`form rows`/`json`. Each difficult choice has saved three-request Jev advice and an engineering rationale. Jev disagreement over pattern uniformity, owner codec reachability and route dispatch was reconciled against executed probes; agreement was never treated as proof. |
| Evidence limits | Native Bun, FormData, compiler and HTMX probes are bounded and disposable. No live production invoice, SQL, browser grid or Linux qualification has passed yet. Agent-task comparisons and exact case registrations occur before trials in T01/T26; they may trigger a design revision, but cannot be represented as completed evidence now. |

A fresh document-link and task-DAG check found no missing relative links or forward dependencies after the final pass. The JSON result leaf-name collision and missing typed initial-read path identified during this audit were corrected with distinct `grid_*` leaves and a bounded GET snapshot action. The earlier action comparison packet remains a history of alternatives; the integrated contract explicitly supersedes its exact-route/query and malformed-form examples. No material public syntax or architecture choice remains delegated to implementation workers. Exact implementation-level method signatures, diagnostic wording and fixture data are constrained by the design packets and are ordinary coding decisions; if a production test contradicts the selected contract, return to design rather than silently changing it.
