# DI-07 current Can variant matrix

24 September 2026. This is an executed baseline for the alternatives in [DI-07](core-alternatives.md#di-07--variant-specialization-and-leaf-compatibility), not a semantic or syntax selection. The compiler was built from current HEAD `02a549d28fd5fc5c3996160e65a97de332390d30` with the repository's pinned Bun archive. Each case is an isolated project generated by [run.py](probes/variant-matrix/run.py); it uses current Can source and the bundled current runtime. No compiler or runtime files were changed.

| Case | Current observation |
| --- | --- |
| `tagged<int>` → `tagged<str>` directly; both have only `unit` | Checker rejects `ok value` with `expression type does not fit expected type`. |
| `tagged<int>` → non-generic `bridge` → `tagged<str>`; all have only `unit` | Builds; the conversion and `main` assertions pass (2/2, `real-can`). |
| `tagged<int>` → common `unit` leaf via `match` → `tagged<str>` | Builds; 2/2 assertions pass. The arm narrows `value` to `unit`. |
| `option::value<int>` → `option::value<str>` directly, with a `none` assertion | Checker rejects the whole variant assignment. A `none` fixture does not make the function's static input type leaf-only. |
| `option::value<int>` → `option::value<str>` after a `none` arm | Builds; 2/2 assertions pass. The `some<int>` arm explicitly returns a fresh `none`. A direct `option::none` leaf → `option::value<str>` also builds and passes. |
| `option::some<int>` → `option::value<str>` | Checker rejects it; `some<int>` is not an admitted leaf. |
| `option::some<str>` → `option::value<str>` | Builds; 2/2 assertions pass. |
| `box<int>` → `box<str>` where `record box<item>` contains `item value` | Checker rejects it. `box<int>` → `box<int>` builds and passes, so this is a specialization identity distinction, not a malformed fixture. |
| JSON `tagged<int>` encode/decode and `tagged<int>` encode → `tagged<str>` decode | Both build; 2/2 assertions pass per case. The wire codec can recover the common `unit` leaf under either schema. This does not make direct source assignment legal. |
| JSON option roundtrips: `none` in `option<int>`, `some<str>` in `option<str>` | Both build; 2/2 assertions pass per case. |
| JSON `option<int>` `none` → `option<str>` decode | Builds; 2/2 assertions pass. |
| JSON `some<int>` tag → `option<str>` decode | Builds; assertion passes by observing `codec::invalid_data("/case", "variant_tag")`, a runtime decoder rejection rather than a checker rejection. |

The four checker-rejected cases have no runtime assertion result: compilation stops before validation. Every admitted case above reports `validation: verified`, `failed: 0`, and `evidence: ["real-can"]`. No assertion unexpectedly failed. The current [`Assignable`](../../../compiler/internal/types/compatibility.go) rule explains the direct/bridge contrast: it rejects different specializations of one declaration before testing complete nominal leaf-set inclusion for distinct variants and leaf-to-variant assignment. The runtime [variant codec](../../../runtime/codec/json.ts) and [decoder](../../../runtime/codec/project.ts) select nominal leaves from the requested schema; the passing cross-schema `unit`/`none` probes show no retained variant provenance on those paths.

```sh

python3 docs/syntax-taste/preparation/probes/variant-matrix/run.py /private/tmp/can-variant-matrix-bundle/can-variant-matrix-probe-bun-1.4.2-darwin-arm64-v1/bin/canlc
```

The script prints one JSON result per case and exits nonzero if an expected rejection becomes an admission, a diagnostic changes away from the checked type mismatch, or an admitted build/assertion fails. Generated projects and compiler output stay under `/private/tmp/can-variant-matrix-cases`. The matrix is 16 isolated cases: 4 checker rejections and 12 verified builds with 24/24 real Can assertion roots passing.

The candidate implications remain distinct. **Extensional leaf sets** would admit the direct equal-leaf `tagged` assignment, because its source and target leaf sets are equal; it would still reject whole `option<int>` → `option<str>` and `some<int>` → `option<str>` because `some<int>` and `some<str>` are different nominal leaves. It must preserve generic record identity. **Retained path-sensitive admission** would intentionally keep the observed direct rejection alongside the admitted bridge and leaf paths; it cannot claim transitive subtype admission or durable phantom branding. **Nominal variant wrappers** would require explicit injection/conversion and wrapper identity through matching and codecs; the current flattened bridge and cross-schema decode observations would no longer be sufficient behavior tests. No wrapper implementation was run.

Nested variants, leaf-addition edits, an explicit wrapper representation, allocation cost, and comparative agent repair cost remain untested here. Codec probes cover these specific leaf schemas and tags, not every nested or malformed wire shape. This evidence does not choose among the three contracts.
