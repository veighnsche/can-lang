## Timeout/cancel remediation record

The browser action path has no cancel operand: the catalogue maps
transport, abort, codec and unexpected-status outcomes into the
declared failure bound (`action::request`/`action::post` emit
`http::transport_failed` et al; abort folds into `transport_failed`).
The recorded remediation — uniform across both apps through the
shared library — is therefore the remedy branch, never a phantom
cancel:

- in-flight work whose view disposes: the local fold is abandoned
  (`disposed`/`stale_version` arms return `none`, N2–N5);
- the flown request stays server-owned until settlement (consistent
  with the R04 cancel-absent branch; no local primitive pretends
  otherwise);
- transport/status/codec failures project to the honest unknown-write
  vocabulary (`save_failure_notice` + `save_failure_uncertain`), load
  failures to plain retryable notices (`load_failure_notice`).

A "cancel-positive" outcome (a verified cancel operand on the browser
action path) cannot verify against the current catalogue: no such
operand exists, and this experiment proposes none.

## C-D error-shape alignment (handoff to E09)

GET invoice error shapes now project through one vocabulary,
byte-identical in both apps (grid `*_applied` legs + compare
`outcome_notice` legs + library asserts):

| Wire/outcome shape | Notice | Leaf |
| --- | --- | --- |
| `grid_loaded` | `loaded revision <rev>` | clean |
| `grid_load_forbidden` (any message) | `access denied; draft kept` | denied |
| `grid_load_unavailable` | `server busy; retry reread` | failed |
| load transport/status/codec/request | `connection lost|unexpected response|unreadable response|request invalid; retry reread` | failed |
| `grid_saved` | `saved revision <rev>` | clean |
| `grid_invalid` | first problem or `rejected by server; edit and retry` | failed |
| `grid_conflict` | `<message>; reread to compare` | failed |
| `grid_forbidden` | `access denied; draft kept` | denied |
| `grid_unavailable` | `save may have committed; replay or reread` | uncertain |
| save transport/status/codec | `connection lost|unexpected response|unreadable response; save may have committed` | uncertain |
| save limit/request | `save too large; remove lines and retry` / `request invalid; reread and retry` | failed |

Nondisclosure holds on both sides: the server answers denied loads
with the fixed `request denied` case (E-owned mapping, untouched),
and both clients project any forbidden case to the fixed
`access denied; draft kept` notice. Flight chrome strings
(`saving...`, `loading...`, `unsaved changes`, `no changes to
save`) stay app-owned: they describe grid flight workflow, not
shared error shapes. E09 owns any HTTP-mapping change; none is
requested — this table is the alignment evidence only.

## C05 gate verdict: INACTIVE

No nested cross-view shape proved inexpressible. Every nested
ownership demand in scope expresses with the existing root-only
rule plus view-scoped cells and the disposed/stale arms:

- two control instances in one view dispose independently
  (drop-left → right-only render, sibling cell untouched);
- late callbacks never mutate disposed views (N2, N4);
- view disposal aborts listeners/timers and poisons handles
  idempotently per the catalogue (`dispose_view` contract);
- cross-instance folds are ordinary cell-handle values with
  disposed/stale arms on both ends (N4).

C05 trip conditions (a future precise shape that would activate the
gate): a library-owned listener that must survive its creating
view's disposal AND mutate a sibling view, or a parent disposal
that must run child cleanup code — neither demonstrated here.

## Native additions (F-R02-01/02): none proposed

The minimal-sufficient set is empty for every leg runnable without
a browser: all extraction, consumption, disposal, reorder, focus
(row intents), caret (in-place status/totals updates without
re-render), normalization (canonical grammars), conflict and
version (CAS) legs pass on the current catalogue. Files,
multiselect, autofill/reset and IME composition have no catalogue
API and need live-browser evidence (workflow + bounded projection
+ Chromium/WebKit/Firefox tests per the contract), which C01
blocks; they stay open for C06 qualification, not C04 proposals.

## R02 case-list coverage

Immutable drafts, versions (CAS), conflicts (adopt/hold),
disposal (independent instances), normalization (grammars),
reorder (step/cut/splice), focus (shared row-intent matcher),
caret (in-place updates): covered by assert legs in both apps.
Files, multiselect, IME, autofill: no catalogue API; live-only;
deferred to C06 with no addition proposed.
