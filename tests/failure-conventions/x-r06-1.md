## Question

Can result-data (nominal outcome records plus boundary adapters) carry
reusable retry/trace infrastructure concisely across two unrelated
callback error sets and a wrapper-around-wrapper, with attempt/sequence
correctness proven by an independent oracle — or do adapters stay so
extensive that finite error-set syntax (Q5) is warranted?

## Method

Built the convention in two committed versions, then a fixed-bound
mirror for the P04 head-to-head:

- v1 (`5f6e6545`): lossy single-domain helper with the FIFO oracle
  (14 roots). Proved the oracle mechanism before any other claim.
- v2 (`ec4bd92d`): faithful error-set variants (authored plus
  catalogue), capture/re-raise adapters, two trace shells with
  root-cause recovery, standard-fault transparency (35 roots).
- `retry-fixed/`: per-domain fixed-bound retries over the same two
  loaders plus one layered bound-repetition consumer (15 roots).
- `retry-negative/`: frozen no-retry mutant; the over-attempt leg is a
  one-line surgery asserting the other direction.

## Simplification ledger (before measurement)

Each candidate simplification was attempted as code and kept or
rejected on measured lines plus coupling. The shipped form is the
winner of every row.

| Attempt | Result | Verdict |
|---|---|---|
| Fixture-template oracle rows (`fixture` + `use`) | Green, +5 lines per converted sequence at one site | Rejected; literal rows retained. Templates pay off only for identical sequences reused across sites. |
| Near-capture helper arity (3 type params to 2) | Green, saves 2 lines once | Rejected; implicit name capture per domain costs more than it saves, and Q3 `with` will favor explicit args anyway. |
| Merge `always_ok`/`always_bad` into `canned(mode)` | Saves 9 lines | Kept. |
| Per-leaf injection helpers vs do-block capture arms | Helpers cost ~9 lines/leaf (fn plus mandatory row); do-blocks cost 3 | Kept do-blocks (`as failure => do / <set> leaf = ... / ok rejected(leaf)`). |
| Witness-param generic `trace` vs leaf `tag` + inline layer | Witnesses poison every call site with dummy error values | Kept `tag` (8 lines, once) with 5-line inline layers. |
| Per-layer/per-domain wrap helpers vs inline matches | Helpers need one concrete type per layer nesting (22 vs 10 lines at two layers) | Kept inline layers. |
| Nested-literal annotation vs projection assertions | Full explicit type arguments on every level check and run | Kept literals (verbose but exact); see R8. |

Findings the ledger depends on (each probed green): variants admit
authored and catalogue error members; catalogue errors construct and
substitute in rows; `ok` of a narrowed member value injects in return
position; member values never infer their variant through generic
constructors (hence R4); field paths do not narrow (hence R5
do-local); do-blocks accept match terminals; `relay call f(1 / 0)`
checks (used by B02, not here).

## Oracle evidence

- `flaky` (fail then success), `down` (exhausted, exact queue),
  `first_try` (single row: any spurious retry fails missing-fixture).
- No-retry mutant: exactly the 11 two-attempt roots fail, all
  `unused fixture`; the other 24 pass
  (`TestRetryNoRetryMutantFails`).
- Over-attempt (bound 2→3, queues unchanged): exhausted roots fail
  `missing fixture` (`TestRetryOverAttemptFails`).
- The oracle is the harness FIFO queue, independent of helper and
  adapter implementations; no-rows-for-selector falls back to real
  execution, which is why every oracle root pins its queue size.

## Conversion and provenance rules (recorded)

- Capture preserves identity: the bound error value is rebuilt
  constructor-for-constructor into the faithful set; payloads intact.
- Re-raise reproduces the identical error value, including catalogue
  errors (`read_quote` refused leg) and values through two trace
  shells (`read_traced` roundtrip_denied leg).
- Standard failures are never converted to data inside adapters and
  never caught by the helper; `blast_kind` proves kind propagation.
  Occurrence/provenance for standards rides the runtime propagation
  the helper preserves.
- Redaction boundary (R9): adapters keep full values server-side;
  client-visible projections go through the `entry.ts` policy at the
  E06-owned hook.

## Limitations

- Generic-constructor inference never injects member values into
  variants; the annotated-local arm (R4) and full literal annotation
  (R8) are workarounds, not elegance. A future inference rule for
  member-to-variant coercion would remove ~2 lines per capture arm.
- Single-error domains skip the variant (failure is the error
  directly); only multi-error sets pay R4.
- The loader stubs are pure and total; live-adapter conversion (SQL,
  HTTP) uses the same arm shapes but is qualified by lanes E/F, not
  here.

## W3-helper verdict

Passes: one helper serves two unrelated sets (authored-only and
heterogeneous); oracle verifies counts plus failure-then-success both
directions; add-error touches only the owning domain plus registry
with unrelated consumers byte-identical; conversion/provenance legs
round-trip exactly, including through wrapper-around-wrapper and for
a catalogue error.

## Q5 assessment (for gated B03): inactive

Result-data adapters are not extensive: per-layer authoring and repair
sit at parity with fixed-bound arms (17 non-row lines each, both
styles), the helper is written once instead of per domain, and wrapper
nesting is expressible only in this style. The measured conversion
premium is +12 code lines per domain (set declaration plus consumer
wrapper). Finite error-set syntax would not remove it — explicit
`emits` still requires per-error arms at every boundary under either
syntax; it would only de-duplicate fixed-style helpers (~11 lines per
domain) at the price of a new generic kind plus checker surface. The Jev C2 `error_rows` counter-case
is answered by the parity measurement: there is no adapter-extent
finding for syntax to relieve.

Trip conditions (reopen only on new evidence): a third domain shows
super-linear adapter growth; a boundary appears where faithful capture
is inexpressible; or agent-repair trials (B05) measure conversion
repair above fixed-style repair on held-out tasks. No numeric cutoff
is invented: the judgment is the parity table plus the shared helper
above.
