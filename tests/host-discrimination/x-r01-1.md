pinned Bun 1.4.2, go1.27.1 darwin/arm64, isolated worktree at `b283d2ab`

Prerequisites built on: C04 (X-R02-1 library proof: ordinary-Can
controls consumed unmodified by the invoice grid and invoice-compare;
root-only ownership composes; disposal arms `disposed`/`stale_version`
return `none`), C05 INACTIVE (root-only append rule retained; no
nested-ownership primitive), F01 (C-G identity vocabulary,

consumed, never patched).

## Question

For each of three widget/operation classes, which tier — generic
catalogue addition, reviewed adapter package, or companion service —
is the correct integration path? The standing hypothesis (small native
ops → adapters, large SDKs → companion; catalogue growth kept live via
the Jev C3 near-tie) is confirmed or refuted per class by measurement,
not by vote.

## Classes

- **Op A — persistent client key-value storage** (`storage::local_get`,
  `local_set`, `local_remove`): small, synchronous, stable native shape
  (WHATWG Storage: `localStorage.getItem/setItem/removeItem`), quota
  failure. Representative of the small-sync-op class.
- **Op B — clipboard text exchange** (`clipboard::read_text`,
  `write_text`): async, permission-gated, richer failure/reentrancy
  surface (W3C Clipboard API: `navigator.clipboard.readText/writeText`,
  Permissions-Policy/engagement gating). Representative of the
  permissioned-async-op class.
- **Widget C — invoice chart widget**: third-party chart-SDK shape
  (init with spec+data, update, select callback, dispose) required by
  the invoice-analytics workflow (totals-over-time chart over the C04
  apps' records). Representative of the third-party-widget class. No
  vendor is pinned: the class is the SDK shape, so vendor choice
  cannot prejudge W2.

## Tiers

- **T1 generic catalogue addition**: design sketch per class (operations,
  types, checker admission, failure mapping) plus merge/ownership cost.
  E owns the merge; D implements nothing in the catalogue. The tier
  stays live through D02: every class carries explicit T1 selection
  conditions.
- **T2 reviewed adapter package**: isolated prototype per class under
  `adapters/` implementing the adapter audit contract (declared I/O
  types, immutable copying, failure mapping, target availability,
  callback/reentrancy rules, ownership/disposal, reproducible
  packaging, conformance suite). Ships only through distribution
  review; this experiment grants none.
- **T3 companion boundary**: isolated prototype per class under
  `companions/` with a typed data boundary consuming F01's C-G policy
  (destination rules, identity/correlation) plus a serving/auth/release
  recipe. F05 owns the real pair; these prototypes prove or disprove
  fit only.

## Rubric (fixed before measurement)

Each class × tier is scored on the same dimensions:

1. compare targets: the same workflow runs through each tier
2. immutable copies: values crossing the copy boundary per call
3. failures: distinct mapped leaves and their honesty
4. callback/reentrancy: rules the tier needs
5. disposal: lifecycle states and disposal arms
6. reproducibility: packaging determinism (double-build byte equality)
7. companion auth/release parity (T3 only; N/A with reason elsewhere)
8. no self-admission: review gate preserved in every tier

## Assignment rule (fixed before measurement)

A tier is excluded for a class when any rubric dimension is
unsatisfiable in it. Of the remaining tiers, the assignment is the
lowest total burden (surface + packaging + per-call overhead). T1 wins
ties only when the surface is generic (cross-app, vendor-neutral,
stable). T3 requires demonstrated auth/release parity. A class with no
fully-evidenced tier returns to preparation with named gaps — it is
never assigned an assumed tier.

## Measurements

### Op A — storage

Compare target: the same `theme` set/get/remove workflow through T2
(`adapters/storage.ts`, 184 lines) and T3 (`companions/storage.ts`,
334 lines). Legs: `adapters/storage.test.ts` 7/7,
`companions/storage.test.ts` 10/10.

| Dimension | T2 adapter | T3 companion |
|---|---|---|
| ops | 3, sync | 3, async (network boundary) |
| failure leaves | 3 (`invalid_key`, `quota_exceeded`, `unavailable`) | 8 (3 storage + `destination_denied`, `unauthorized`, `version_mismatch`, `transport_failed`, `protocol_error`) |
| immutable copies | 0 crossings (string primitives; past results immune to overwrite) | 2 crossings/call (JSON encode + decode; 117-byte get request, 132-byte set request, 72-byte response, pinned) |
| callbacks/reentrancy | 0 callbacks; sync, no interleaving | 0 app callbacks; async settlement order |
| disposal | stateless; no handles | stateless per call; no handles |
| target availability | `available=false` fails closed with zero host calls | destination denied fails closed with zero sends; offline → honest `transport_failed` |
| native-text leakage | none (quota/security names mapped, never propagated) | none (transport natives mapped; secret absent from all reports) |
| auth/release parity | N/A (in-process; no credential) | demonstrated: same policy version both sides, env-name credential, version handshake both directions |
| compare targets | origin-local persistence | server-side persistence: workflow satisfied with recorded property deltas (offline behavior, latency, cross-device scope) |

Discrimination signal: T3 carries the full boundary tax (async, 117+
wire bytes, 5 extra failure leaves, per-call policy+auth) for a
synchronous 3-op surface with no secret and no cross-device need,
while T2 satisfies every contract dimension in 184 lines with zero
callbacks and zero copies. T1 sketch: 3 catalogue ops with identical
signatures; selection condition recorded in the T1 section.

### Op B — clipboard

Compare target: the same device-clipboard write/read workflow through
T2 (`adapters/clipboard.ts`, 156 lines) and T3
(`companions/clipboard.ts`, 301 lines). Legs:
`adapters/clipboard.test.ts` 8/8, `companions/clipboard.test.ts` 7/7.

| Dimension | T2 adapter | T3 companion |
|---|---|---|
| ops | 2, async | 2, async |
| failure leaves | 4 (`invalid_text`, `denied`, `empty`, `unavailable`) | 9 (4 clipboard + 5 companion boundary) |
| immutable copies | 0 crossings (string primitives) | 2 crossings/call (106-byte read request, 127-byte write request, 79-byte response, pinned) |
| callbacks/reentrancy | 0 app callbacks; explicit no-ordering rule for concurrent calls (pinned on the fake) | 0 app callbacks; async settlement order |
| disposal | stateless; no handles | stateless per call; no handles |
| target availability | `available=false` and denied permission fail closed before clipboard contact | destination denied fails closed with zero sends; offline → honest `transport_failed` |
| native-text leakage | none | none (secret absent from all reports) |
| auth/release parity | N/A (in-process; no credential) | demonstrated: same policy version both sides, env-name credential, version handshake both directions |
| compare targets | device clipboard reached | **unsatisfiable**: server holds a pastebin cell disjoint from the device cell (pinned by the semantic-gap leg) |

Discrimination signal: T3 satisfies every boundary dimension yet
fails rubric dimension 1 — a companion server cannot observe the
device clipboard, so the pastebin it serves is a different workflow,
not the compare target. T3 is therefore **excluded for Op B** under
the assignment rule. The only satisfiable T3 shape (a served isolated
frame plus postMessage boundary) is unbuilt: it would inherit
adapter-like review burden plus serving/origin costs, so it cannot
beat the T1/T2 choice on burden. That domination claim is analysis,
not evidence — it binds only if D02 ever reconsiders T3 for this
class, in which case the frame variant must be prototyped and
measured. Native-behavior uncertainties (empty-read shape,
engagement gating) are shared by all tiers and non-discriminating;
D02 verifies them live.

### Widget C — chart

Compare target: render the invoice-totals bar chart, select the Feb
bar, then dispose/release — through T2 (`adapters/chart-widget.ts`,
279 lines) and T3 (`companions/chart-widget.ts`, 360 lines). Legs:
`adapters/chart-widget.test.ts` 12/12,
`companions/chart-widget.test.ts` 8/8.

| Dimension | T2 adapter | T3 companion |
|---|---|---|
| ops | 3, sync (create/update/dispose) | 3, async (render/select/release) |
| failure leaves | 3 (`invalid_spec`, `disposed`, `unavailable`) | 7 (`invalid_spec`, `expired` + 5 companion boundary) |
| immutable copies | deep copy at every crossing (create, update, each callback point; frozen) | 2 crossings/call (209-byte render request, 164-byte response, pinned; table frozen) |
| callbacks/reentrancy | 1 callback + 4 dispatch rules (single dispatch, sealed reporting, immediate reentrant update, dispose-during-callback) | 0 callbacks; select is request/response |
| disposal | opaque tokens; idempotent dispose; late events dropped; dispose-during-callback completes then drops | idempotent release; select-after-release → `expired` |
| target availability | `available=false` fails closed with zero host calls; SDK throw → `unavailable`, no native text | destination denied fails closed with zero sends; offline → honest `transport_failed` |
| auth/release parity | N/A (in-process; no credential) | demonstrated: same policy version both sides, env-name credential, version handshake both directions |
| compare targets | satisfied in-process | satisfied across the boundary (selection = roundtrip) |

Discrimination signal: both tiers satisfy every rubric dimension —
this is the genuine two-way contest. T2 pays callback/dispatch
complexity (4 rules, sealed reporter, opaque tokens) and ships SDK
bytes in-process under review per SDK version; T3 pays async,
209-byte render requests, per-call policy+auth, and offline failure,
but needs zero callbacks and keeps every SDK byte out of the Can
build. The assignment turns on the T1 sketch, packaging measurements
(slice 5), and the Jev read (slice 6).

## Assignment

Standing hypothesis (small native ops → adapters, large SDKs →
companion; catalogue kept live) is **confirmed for all three
classes**, with a refinement: stable-standard ops assign to T2 even
when generic, and T1 graduation requires demonstrated multi-app
demand — not assumed reuse.

| Class | Assigned tier | Basis | Live alternatives |
|---|---|---|---|
| Op A storage | **T2 reviewed adapter** | Lowest total burden: 184 lines / 4559 bytes, 3 leaves, 0 callbacks, 0 copies; stable Storage standard makes review ~one-time. T3 satisfies the workflow but carries async + 117-byte requests + per-call policy/auth for zero workflow gain. | T1 on second-app need; T3 for server-side/cross-device persistence needs (measured costs attached) |
| Op B clipboard | **T2 reviewed adapter** | Only satisfiable low-burden tier: 156 lines / 2987 bytes, permission pre-gate, explicit reentrancy rule. T3 **excluded by measurement** (server cell disjoint from device cell — compare-target failure, Jev companion 0.00 in all wordings). | T1 after D02 live permission/empty-read matrix + second-app need |
| Widget C chart | **T3 companion**, scoped to the invoice-analytics workflow | Total burden including structural terms: T2's measured shim (279 lines / 6051 bytes) excludes real SDK bytes and per-version re-review under vendor churn, both positive by the tier/class definitions; T3's structural online cost is ~zero marginal for this workflow (C04 apps load/save through server actions already — online by construction), with zero callbacks and SDK bytes out of the audited browser asset. Measured T3: 360 lines, 209-byte render requests, 7 leaves, auth/release parity demonstrated. | T2 for latency/offline-critical widget shapes (trip conditions below); T1b if charts become platform surface; Jev's weak T2 lean (0.56/0.58/0.88) preserved as the counter-case |

Scope and trip conditions for the Widget C assignment: it covers
occasional-selection analytics widgets over server-loaded data. Any
of the following reactivates the tier choice (T2 first, via the
measured T2 legs — no new experiment needed unless the shape
differs): sub-roundtrip interaction budget (brushing, hover-linked
selection), offline render of cached drafts required by H/user, or a
D02-measured select roundtrip above the packaging latency budget.
SDK representative sizing stays an unmeasured gap whose direction is
known (positive bytes, T3-favoring) and whose magnitude cannot flip
the ordinal while T3's marginal structural terms stay ~zero; if H
disputes that premise, the gap returns to preparation with this
paragraph as the issue statement.

Evidence gaps returned to preparation (not assumed tiers): none
block the three assignments above. Live-browser verification of
every native call (C01 blocked) is owned by D02 conformance as a
verification step, not a tier input — the discriminating evidence
(surface shape, lifecycle, semantic reach, structural burden) does
not depend on it. New widget shapes outside the stated scope return
individually per the trip conditions.
